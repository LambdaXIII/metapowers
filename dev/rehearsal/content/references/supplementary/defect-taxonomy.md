# 内容缺陷分类法
> 按需参考 — 被引用时加载。

从大规模 rehearsal（推演）实践中归纳出的**常见**缺陷类型（非完备清单，以文档/知识库类载体为主归纳）。可用于验证时快速归类发现。

分类按通用论述的四向复现组织（劣化 / 偏差 / 过度 / 重复——定义见通用论述首章，此处只归类）。方向标注为各缺陷对复现质量的主要影响。每类带严重程度参考标记（🔴 常见且影响大 / 🟡 中等 / 🟢 较少见——仅为实践参考，不代表 P5S3 的严重程度格式判定）。

---

## 劣化（复现比编写时浅）

> 归类理由：以下类型的共性（除文件无归属声明外）是**关键信息缺失或未展开**——读者获得了路径但缺收束、获得了范围但缺覆盖、获得了原则但缺量化，理解停留在比编写时更浅的层次。文件无归属声明归劣化而非偏差：读者缺的是"我在知识库中的位置"这一信息，不是被误导（不涉及方向错误）。

### 🔴 路径末端无收束

**描述：** 读者走完文档路径后（读完参考文件、填完模板），不知道"已完成"和"下一步该做什么"。文档提供了入口（主文件的决策树），但每个子文件缺少回到主路径的收束指引。

**典型信号：**
- 读完最后一个 section 后，文件直接以参考链接结束
- 没有回到主入口的回链
- 没有"如果你完成了 X，下一步应该是 Y"的引导

**修复模式：** 在每个子文件末尾添加"下一步"区块，包含 2-4 条明确的后续行动建议 + 回到主入口的链接。

### 🔴 覆盖不完整

**描述：** 新增的特定路径（如"环境 A → 环境 B 迁移"）只覆盖了部分必要维度，遗漏了工具适配、安全审查、回归测试等步骤。

**典型信号：**
- 迁移分支只有 3-4 步，但实际工作需要 6-7 个维度
- 缺少"完成验证清单"

**修复模式：** 每次新增路径时对照已有路径的覆盖范围，确保关键维度（结构、内容、工具、安全、测试）都有人口。

### 🟡 修复后无返回信号

**描述：** 「路径末端无收束」在诊断-修复场景的子类型：读者在诊断文件中定位到某个问题，阅读修复方案后直接离开——不知道应该回到诊断工作流继续排查其他问题。

**典型信号：**
- 问题详解以"深入阅读 → xxx.md"结束，没有"修复后请回到诊断工作流"
- 自查清单存在但问题修复段落未引用

**修复模式：** 在每个问题的修复方案末尾添加标准返回信号：`🔄 修复后请回到 [§X 诊断工作流] 继续排查剩余问题，或用 [§Y 自查清单] 全面验证。`

### 🟢 文件无归属声明

**描述：** 当读者从搜索/链接直接打开某个子文件（不经过主入口），完全不知道这个文件是一个更大知识库的组成部分。文件中没有任何归属声明。

**典型信号：**
- 文件头部只有标题 + 来源说明，没有指向主入口
- 模板文件的反向引用藏在注释中（读者看不到）
- 从文件内部跳转到另一个文件时，读者不知道自己在"知识库体系"中

**修复模式：** 在每个子文件头部添加标准声明行：`> 📍 本文件是 [知识库名称](../入口文件) 的组成部分。主入口和决策树请见 [入口文件]。`

### 🟢 缺少量化判断框架

**描述：** 文档深入解释了 WHY（理论原理），但缺少 HOW MUCH（量化判断标准）。读者带着具体数值问题（如"500 条记录算不算多"）来，找不到答案。

**典型信号：**
- 只有"越少越好""合理分配"等定性建议
- 无从判断自己的实际数值处于什么水平

**修复模式：** 在理论章节后添加"快速参考"表，提供分档的量化判断标准（如 <500 精简 / 500-2000 正常 / >5000 危险）。

## 偏差（复现与编写时不同向）

> 归类理由：以下类型的共性是读者**理解错方向**——歧义、误导、无法解析的参照。其中 Context Leak（悬空参照）虽表现为"解析受阻"，但受阻的结果是读者被迫猜测，猜错即偏离编写时的方向，故归偏差而非劣化（劣化指理解了但变浅）。

### 🔴 信息不一致

**描述：** 同一概念在不同文件中使用了不同的表述单位或范围，导致读者困惑。例如"超过 5 个分支"在诊断表中指全局总量，在健康度标准中指每分类上限。

**典型信号：**
- 诊断表和详解表的同一指标使用了不同单位
- 一个文件说"策略 A 适用于场景 X"，另一个文件暗示"策略 A 仅适用于非 X"
- 量化阈值在不同文件中有不同表述（">5" vs "≥6"）

**修复模式：** 统一量化标准的单位和措辞；在敏感边界处增加说明脚注（如"此阈值指每分类上限，非全局总量"）。

### 🟡 Context Leak（悬空参照）

**描述：** 作者在写作时依赖了对话/设计讨论中建立的共享上下文，导致文字在独立阅读时出现悬空参照——读者缺少必要的锚点来解析含义。常见于从设计讨论、计划文档、施工笔记中直接搬运文字到正文而未做适配。

**典型信号：**
- **时序泄漏**：在术语被定义之前就使用了它（如"在身份转换之前"，但"身份转换"在后文才被定义）
- **速记泄漏**：开发者内部代号（如 L0/L1/L2、项目缩写、层级编号）出现在面向外部读者的文档中
- **自毁式举例**：解释"不要用速记"时，举例本身用了速记——例子的读者恰好不理解例子里使用的概念

**修复模式：**
- 以目标读者的身份逐句重读——每句话自问"如果不参与这个项目/这场对话，我能理解这句话吗？"
- 删除超前引用——用编号、自然顺序、或"详见下一步"替代
- 用自然语言替换所有速记
- 检查每个例子：例子的读者能否理解例子中使用的每一个概念？

### 🟡 概念关系未显式说明

**描述：** 两个相关但不同的概念（如"规则"和"原则"、"分支逻辑"和"优先级栈"）被读者误解为互斥替代方案，而实际上它们是互补的。

**典型信号：**
- 文档中两个概念各自有独立章节，但没有一段说明它们的关系
- "替代方案"的措辞暗示互斥，但实际意图是补充

**修复模式：** 在"替代方案"标题后立即加入澄清声明（如"不是完全替代，而是补充"）；在两个概念首次同时出现的地方添加关系说明。

### 🟡 交叉引用缺锚点或单向

**描述：** 文件 A 引用了文件 B，但链接无 `#` 锚点（指向文件头部而非具体章节）；或者 A→B 有引用但 B→A 没有（单向）。

**典型信号：**
- `[content-writing.md](content-writing.md)` — 无 `#` 锚点
- 某文件提到"工具是预算大头"但无链接到对应的详细章节
- 点击交叉引用后落在文件头部，需要手动滚动到目标章节

**修复模式：**
- 所有交叉引用使用 `#` 锚点指向具体章节
- 相互引用的文件建立双向链接（A→B + B→A）
- 引用文本描述目标章节的内容，让读者知道"跳过去会看到什么"

## 过度（复现超出编写时）

> 归类理由：以下类型的共性是读者收到**编写时未意图的内容**——身份边界错位（施工痕迹等作者侧内容混入）与过度承诺/强度放大（措辞超出实际支撑）都让复现图景超出编写时的本意。

### 🔴 身份边界错位

**描述：** 材料中混入了作者身份的内容——读者能解析这些内容，但收到的是不该收的内容（与悬空参照不同：悬空参照是读者无法解析）。典型来源：施工痕迹、开发侧知识、编写行为约束、作者的声音。

**典型信号：**
- **脚手架残留**：施工阶段的 TODO 注释、创建说明、同步提醒未被剥离（如"创建本文件后需同步更新路由表"）
- **编写行为约束入文**：写作时的纪律（如"本文不出现 XXX"）被写成文档的一行
- **开发侧知识入文**：只有参与开发过程的人才知道的内部约定出现在面向读者的正文

**修复模式：** 以"读者身份"审视每段内容——读者能看懂一段话，不等于这段话应该出现在材料里。施工注释、操作日志属于开发侧记录，不属于正文。

### 🟢 过度承诺/强度放大

**描述：** 材料承诺或强调了编写时未意图的内容——把建议写成保证、把定位词写进正文、警告强度超过实际后果。

**典型信号：**
- 绝对化措辞超出约束的实际范围（"永远""一定""零成本"）
- 营销性表述（"彻底解决""最优方案"）
- 轻微问题使用严重警告——读者收到强度被放大的图景

**修复模式：** 措辞与意图对齐——承诺的范围与材料实际能支撑的范围一致；警告强度与后果的实际严重程度一致。

## 重复（同一内容多份拷贝）

### 🟢 重复呈现/冗余定义

**描述：** 属于"重复"方向（定义见通用论述首章）。本类补充该方向在实践中的常见形态：同一概念在多个位置被重新定义而非引用前文、同一说明在不同文件中重复出现且无分工（内容重叠无分工）。

**典型信号：**
- 同一概念在多个位置被重新定义，而非引用前文定义
- 同一说明在不同文件中重复出现且无分工（内容重叠无分工）
- 后文完整展开前文已定义的内容，篇幅与原文相当

**修复模式：** 概念定义唯一化——首次出现处定义，后文使用处引用；重叠内容明确分工或合并（两个文件讲同一主题时，确定哪个是权威、另一个引用它）。

---

## 使用方式

在 rehearsal 推演完成后（P5S2 发现归类），将发现的缺陷按此分类法归类。同一类别出现 2 次以上 = 结构性缺陷，需要从载体架构层面修复（如全局添加归属声明），而非逐处修补。分类法按四向组织，但不替代 P5S1 的四向复现对照——对照是检查方向，归类是缺陷类型，两者配合使用。

**无法归类时**：分类法不是完备清单——遇到无对应类型的发现，按最接近的方向标注并保留原始信号，不要硬套。
