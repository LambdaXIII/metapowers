# 技能修改（skill-modify）

> 本文档是 skill-master 技能的修改工作论述：处理已有技能成品上的一切
> 变更——修问题、增删内容、重构、修剪。读者默认已读 SKILL.md 的前提
> 部分（《什么是一个好的技能》，它给出判断一段正文好坏的坐标系）；
> 本册只写修改这一件事该怎么想、怎么做。从零设计一个技能归设计工作
> 论述，只读评判归审查工作论述——修改站在两者下游，拿到审查的定位
> 与设计的定案再动手。

## 定位与范围纪律

修改工作服务的是已经存在的成品：技能装了什么内容、以什么结构组织、在什么情况下被加载，都已定案，本次变更只是让其中一部分变成另一副样子。判断一件事是否属于修改，看变更对象与幅度：对象已存在、改动可以在既有结构内完成，是修改；对象还不存在、或既有结构本身要动，属于设计。这个归属判断先于一切动作，因为它决定后面调用哪套做法。

范围纪律的第一条是只改要求的部分。技能是多文件互指的呈现，一次改动实际影响的面积总比视线里大；一旦顺手把相邻段落也「优化」了，这次变更就失去边界——执行后检验（旧词残留、耦合回归）都以范围为地图，地图模糊了，检验也无从做起。场景：修一处术语定义时顺手重排了相邻小节，收工时无法回答「这次到底改了什么」，并行维护同一册子的同事也无法判断会不会撞车。

动手前先写下目标效果：改完是什么样，用一句可以检查的话说清。目标效果是修改的收敛方向——没有它，修改会在探索中不断滚大范围，改到一半还会冒出「顺便也改改这里」的念头；有了它，范围外的每处诱惑都能被一句「不在目标里」挡回去。例如改术语一致性，目标效果写成「目标概念在全部正文中定义唯一、引用与定义一致、旧词零残留」，后面每一步都在为这句话的可检查性服务。

## 理解现状

修改的起点不是改，而是先让技能自己说出它现在长什么样。技能的读者是零上下文 agent，正文沿一条呈现路径展开：
description 把它带到 SKILL.md，SKILL.md
路由到具体论述，论述里再展开判断依据。目标概念沿这条路径有多个出现点，每处承担的语义角色不同——理解现状就是把这条路径完整走一遍。

做法是呈现路径追踪：先全文检索目标概念的所有出现点，范围覆盖全部正文、示例、description
与元信息字段；再给出现点排序，定出首次出现的位置——那通常是定义锚点，决定概念的含义——其余是引用点，依赖定义成立；最后核对定义本身是否准确、各引用与定义是否一致。检索先于判断的理由很直接：没有完整出现清单就动手，改到一半才会在某册子深处发现还有一处引用，而那时的改动语境已经变了。检索结果只证明文字出现在那里，不证明它现行有效——命中可能落在已废弃的内容上——但清单本身必须先建全。

不靠记忆改术语。对话上下文与长期记忆不是权威，文件才是——「我记得 description
里没提」常常只是上一版改动没有落盘。判据只有一条：检索结果里没有，才算没有。场景：凭印象断定某词只在
SKILL.md 出现，改完后在另一册子里又搜出三处，旧词残留直接让执行后检验失败。

## 修改执行

修改的节奏是涟漪式的：找到一处出现点 → 判断它属于哪一类 → 动手改 →
再找下一处。为什么不能先扫完再统一改：每一次修改都会改变后续出现点的判断语境——定义改了，后面那句引用是否还成立就要重新看；用修改前的语境判断修改后的问题，等于刻舟求剑。归属判断分四类：定义区，决定概念含义，改动影响最大；引用区，依赖定义，多数只需跟随；历史残留，描述旧行为的句子，往往该删而不是替换；无关命中，同名异指或纯属巧合，不该动。

每个命中是候选，不是目标。检索命中只说明这个词出现在这里，不说明这里必须改；把命中直接当目标，就会把历史残留改成新词——句子描述的是「当时如此」，跟随后反而失真，也把无关命中卷进改动。归属判断逐处做，没有捷径。

批量替换因此是最该抵制的默认动作。机制在于：同一字符串在不同出现点的语义角色不同——定义点决定含义，引用点依赖定义，示例与常见问题里的出现绑定当时语境，还有同名不同物的巧合；文本级整体替换把这些差异全部抹平，把旧词整体换成新词时，「描述旧行为」的句子也被替换，等于把记录改写成了谎言。逐处修改比批量慢，但慢得值：不同位置本来就需要不同处理——改、删、或明确不动。批量的另一层隐患是默认「这条和那条差不多」，而每次「差不多」都可能是微妙差异。

## 耦合链回溯

改动的影响沿三层传播。核心定义是第一层；直接引用者——提到该概念的文件与段落——是第二层，定义一变它们就要跟随；条件依赖者是第三层：字面上不出现目标词、却依赖定义成立的内容，包括标准门槛、示例与常见问题。分层的意义在于区分涟漪的显隐：对直接引用者，检索能命中；对条件依赖者，检索根本找不到，它们只在你主动追问时暴露。判据：动一个概念时，除了检索出现点，还要问「哪些内容依赖这个概念成立」——示例示范的还是不是新行为，常见问题回答的还是不是新定义，标准门槛的措辞是否仍然准确。场景：把某技能的支持范围定义收窄后，一个示例示范的用法恰好越界，而旧词检索命中不了它。

远端残留是最容易漏的一层：技能的配套设计文档不参与执行，却是一致性锚点。设计文档描述这个技能提供什么、不管什么，是日后审查判定「缺陷还是设计如此」的坐标系；正文改动后坐标系不动，文档与正文描述的可能已经不是同一个技能。判据：凡改动触及定位、命名、范围边界的，回头核对配套设计文档里描述该技能能力与边界的句子，需要时一并更新。场景：技能更名后正文、路由、
description全部跟进，设计文档却仍用旧名旧能力描述它——下一次审查拿它当锚点，会把新正文误判成偏离设计。

## 内容手术

新增内容要与既有结构对齐，不造第二套并列惯例。机制很直接：读者按已建立的结构预期阅读，第二套惯例意味着读者要学两套组织、维护者要维护两套、审查要多审一套，每一项都是净成本。判据：把新内容放进目标文件时，问它和同层其他小节是不是同一种形态——一个以要点论述组织的册子里混入大段编号步骤，就是第二套惯例正在诞生。

大幅度重写走备份做法：整文件重写前先复制一份原文件作备份，写完后对照备份逐段检查有没有丢内容，确认无丢失再清理备份。为什么对照不可省：提纲与记忆都不可靠，原文件里总有「提纲没列、当时觉得理所当然」的实质内容，对照是唯一能让丢失显形的动作。搬动内容时同样遵循先立新位、再删旧位——新位置写好、引用更新之后，旧位置才退出，中间任何时刻技能都保持完整可读。

修剪的执行要点是先诊断、再动手，判定标准在 documents/writing-craft.md
的修剪判据一组，这里讲怎么执行。先诊断目标内容是沉积还是臃肿：沉积是过时、冗余、被取代的内容，删；臃肿是每行都还活着、但整体太长，不删，披露分层——按主题拆成多册，或把深层内容移入更细的册子，让每一册的篇幅与它的主题相称。诊断顺序不能反：把臃肿当沉积删，会丢掉活内容；把沉积当臃肿分层，则是给垃圾盖楼。修剪时整句删、不裁半句——半句残留保留了原句的引导作用却丢了原句的内容，比整句更误导。常见的沉积对象是化石内容：某一次实务的交付形态（报告模板、评估矩阵、个案规律）冒充通用方法论，它的判别属于审查工作的化石维度，而删的动作在这里执行——删掉格式外壳与个案规律，留下其中提炼出的判断洞察。

## 升级判断

变更接近重写、或开始动摇设计意图时，停下来，转设计工作。机制在于坐标系的区分：修改的坐标系是既有设计意图——定位三问的答案、术语的权威含义、范围边界；在坐标系内改动是修改，坐标系本身要动就是设计问题，此时继续修补，只会得到一次没有锚定的重写。两条判据：改动面覆盖文件的大半、几乎逐句在变；或一次变更牵动「这个技能提供什么、不管什么」的回答。场景：修一个路由问题时发现三工作划分本身已不合理——在正文里打补丁只会把论述改得自相矛盾，正确动作是停下，把「划分怎么改」作为设计问题重锚定。

## 执行后检验

修改收尾时做三件事，让「改完了」成为可检查的陈述。第一，旧术语全文零残留：再检索一遍旧词，覆盖正文、示例、元信息与配套文档，与改前清单逐项对齐——每个出现点都必须有去处：改了、删了、或判定过不动。检索词要覆盖两种写法：正文用词与引用格式，漏一种格式就可能有残留潜伏。

第二，逐文件核对同层结构一致：同一级小节的组织形态在各文件间保持一致——新增小节后，路由与索引是否覆盖到它，各册子同级标题的形态是否仍然齐整。结构不一致会让读者在每个文件里重新学习导航。

第三，耦合项回归：先列所有引用点，再改定义点；定义改完后回到清单逐点确认引用仍然成立。清单是改前的快照，回归是让「应该改的」与「改了的」对齐——漏改引用是修改最常见的残留形态，而清单让漏改变得可见。场景：定义改完就收工，两周后示例里还在示范旧行为，而改前清单上那一项从没被勾掉。

## Gotchas

修改的失败很少发生在单一动作上，而是发生在动作的顺序与归属判断上。下面是最常复发的几种，每条配对「该怎么做」。

凭记忆替代检索：动手前不建出现清单，凭印象判断哪些地方提过这个词——清单缺失时，漏改不可见。该做的是让理解现状先于修改，检索结果就是地图。

把命中当目标：检索命中就直接改，跳过归属判断，历史残留与无关命中跟着遭殃。该做的是逐处判断定义区、引用区、历史残留、无关命中，再决定改、删还是不动。

整体批量替换：文本级替换抹平语义角色差异，把描述旧行为的句子也替换成新词。该做的是涟漪节奏逐处改，允许不同出现点有不同处理。

改定义忘引用：定义处改了，引用点、示例与常见问题留在旧行为上，日积月累连自己都看不出不一致。该做的是改前先列引用清单，改后逐项回归。

顺手扩大范围：改 A 时看 B
不顺眼一并改掉，这次变更失去边界，检验无从做起。该做的是动手前写下一句可检查的目标效果，范围外的念头记下来留给下一次变更。

重写丢内容：大幅重写不走备份对照，原稿里提纲之外的实质内容静默消失。该做的是整文件重写先备份，写完对照补漏，再清理备份。

该升级不升级：变更已动摇设计意图，仍在正文里打补丁，把论述改得自相矛盾。该做的是接近重写或牵动定位三问就停下，转设计工作。
