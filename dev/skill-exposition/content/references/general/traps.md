# 陷阱专项展开

> 通用论述第 3 节给出四类陷阱的框架——每类的本质、典型表现与自查句。本文按同一框架逐类深化：补充更多典型表现（含跨类组合）、具体正反例与可用自查句。**框架以通用论述为准，本文不重复定义，只在需要时引用**。交付前对照陷阱清单自查时，可用文末的快速定位表。

## 1. 内容失真

本质：说明文与源内容不一致——省略、歪曲、劣化、添加源里没有的内容（通用论述 3.1）。

### 更多典型表现

- 规则缺了例外：源里有"除非……"，说明文里只剩主规则
- 阈值被近似或取整："文件超过 500 行"写成"文件较大时"；"3 次重试"写成"几次重试"
- 条件被简化："A 且 B 才触发"写成"A 触发"；条件分支的兜底丢失
- 流程顺序被打乱：步骤之间的依赖关系（必须先 A 后 B）在重组时丢失
- 示例被"典型化"时丢掉关键参数：示例的输入、输出、边界条件被删减
- 多来源合并时张冠李戴：把 A 文件的限定条件写进 B 文件的表述（同一技能内的来源混淆；跨技能版本见 multi-skill.md 的归属纪律）
- 夹带评价：源只描述行为，说明文加了"这一设计很巧妙"——评价技能好坏超出本技能行为边界，也属于添加源里没有的内容
- **反模板（结构层失真）**：说明文组织成"任何技能都适用的通用模板"，该技能的独特特征被结构性省略——结构上没有位置承载独特内容，内容就装不进去（通用论述 §4 组织原则：不同技能用同一个结构模板 = 说明文没有忠实反映该技能）

### 正反例

反例（丢例外）：

> 源："当文件超过 500 行时标记大文件警告；生成代码文件除外。"
> 说明文："技能会标记大文件。"——阈值、例外全丢。

正例：

> "当文件超过 500 行时，技能标记大文件警告；生成代码文件不在此列。"——阈值与例外原样保留。

反例（反模板）：一个安全检查技能与一个知识整理技能的说明文章节骨架完全相同，只替换了名词——读者无法从结构上看出两者有什么不同。

正例：安全检查按"检查项 → 检测方法 → 误报处理"组织，知识整理按"分类体系 → 入库流程 → 查询方式"组织——结构本身反映各自的内容。

### 跨类组合

- 内容失真 × 视角漂移：补主题背景时顺手加了源里没有的"规则"（主题知识被当成技能能力写进去）
- 内容失真 × 推断未标注：为补"为什么"而编的理由没有标注，读起来像源中明文
- 内容失真 × 语体残留：复述指令时把设计理由整段丢掉——"为什么"也是源内容，丢了就是省略

### 自查句

- 源里的每条规则、每个阈值、每个例外都出现了吗？原样吗？
- 有没有哪句话是我"补"的、或从别处"借"来的？
- 去掉技能名称后，这篇说明文还能用在另一个技能上吗？——能，说明独特内容被模板化了
- 每个示例的输入、输出、边界条件与源一致吗？

## 2. 视角漂移

本质：阐述的是技能**处理的主题**，而不是技能**本身**（通用论述 3.2）。

### 更多典型表现

- 大段介绍主题领域的背景知识：阐述安全扫描技能时写成安全科普，阐述翻译技能时写成语言学导论
- 用"这个技能可以帮你……"引出主题价值后，整段转为主题教程
- 示例场景被展开成主题讲解：示例里出现一份"扫描报告"，开始解释什么是扫描报告
- 主题知识喧宾夺主：主题内容自成一体、删掉也能成立，而技能机制反而模糊

边界提示：主题知识不是禁用——按推断纪律可以标注补充（如 `[推断: 行业常识]`）；判断标准是**谁为谁服务**：主题知识帮助理解"技能为什么这样工作"是界内；主题知识替代技能机制成为正文主体就是漂移。

### 正反例

反例（攻壳机动队）：阐述一个处理动画作品元数据的技能时，开篇写"攻壳机动队是一部 1995 年的日本动画电影……"——读者学到的是电影知识，不是技能机制。

正例：

> "技能接收动画作品名称，从知识库匹配元数据并输出。以《攻壳机动队》为例：输入片名后，技能返回年份、导演与类型字段。"——讲的是技能机制，作品只是示例数据。

### 跨类组合

- 视角漂移 × 内容失真：主题知识里夹带源里没有的"技能能力"（把主题领域的通用做法说成该技能的行为）
- 视角漂移 × 推断未标注：用主题常识充当技能的设计理由，且未标注 `[推断]`
- 视角漂移 × 语体残留：步骤转述中插入主题背景段，读起来像"命令 + 科普"的拼贴

### 自查句

- 每一段都在讲"这个技能如何工作"，而不是"这个主题是什么"吗？
- 删掉技能名称后，剩下的文字是在描述一种机制，还是一篇主题科普？
- 主题知识出现时，它是为理解技能机制服务，还是自成一体？

## 3. 推断未标注

本质：补充"为什么"时把推断当成原文呈现（通用论述 3.3）。推断纪律（可推断三类 / 不可推断三类 / 无法确定兜底）以通用论述 3.3 为准，本文只展开违反纪律的典型表现。

### 更多典型表现

- 理由未标注：源里只有"限制为 5000 行"，说明文写"5000 行的上限防止上下文溢出"——无 `[推断]` 标注，读者以为是源中明文
- 标注不合格：`[推断]` 不带依据（通用论述要求 `[推断: 依据]` 格式，如 `[推断: 基于约束反推]`）；或依据含糊（"大概是因为"）
- 越界推断：把设计者主观取舍写成理由——"选四个维度是为了平衡全面性与成本"，源未说明，属不可推断
- 静默跳过：该标注 `[未推断]` 的地方不标注，读者以为"这里没有理由"，实际是"无法确定"
- 推断与源冲突：推断出的理由与源中显式约束矛盾——宁可 `[未推断: 无法确定]`，不写矛盾的理由

### 正反例

反例：

> 源只有"限制为 5000 行"。说明文："5000 行的上限防止上下文溢出。"——无标注。

正例：

> "上限设为 5000 行，防止上下文溢出 [推断: 基于约束反推]。"；若无法判断，则"上限设为 5000 行的具体原因未在源中说明 [未推断: 无法确定]"。

反例（越界）：

> "选择四个检查维度，是为了在覆盖度与速度之间取得平衡。"——源未说明取舍，属设计者主观取舍，不可推断。

正例：

> "技能设置四个检查维度；取舍原因源中未说明 [未推断: 需设计者主观取舍]"。

### 跨类组合

- 推断未标注 × 内容失真：未标注的推断本身就是"添加源里没有的内容"，是内容失真的一种具体形态
- 推断未标注 × 视角漂移：用主题常识充当技能理由，未标注且对象漂移

### 自查句

- 每个"为什么"都有出处吗？源里有 → 直接呈现；源里没有 → 要么 `[推断: 依据]`、要么 `[未推断: 原因]`，二选一，没有第三个选项
- 有没有哪句话读起来像理由，但既无源依据也无标注？
- 推断出的理由与源中的显式约束冲突吗？

## 4. 语体残留（认知面）

本质：把说明文写成了指令复述（通用论述 3.4）。注意：这里只指**认知错误**——把"教人理解"做成了"转述指令"；句法层的调整（祈使句怎么改、步骤怎么展开）是行文问题，见 [readability.md](readability.md) 的启发。

### 更多典型表现

- 全文转述"你应该……""第一步：……""禁止……"，读起来像在向读者下达命令
- 只写"做什么"不写"是什么 / 为什么"：流程步骤齐全，但没有任何解释，读者能照做却学不到设计意图
- 约束被复述为禁令：只有"不可读取 eval_metadata.json"，没有"为什么不可"与边界
- 说明文与源指令逐句对应：句子顺序、措辞都跟着源走，只是换了标点

### 正反例

反例：

> "你必须先读取 SKILL.md。第一步：确定范围。第二步：定位分布。禁止修改源文件。"——纯转述，无解释。

正例：

> "阐述从梳理开始：技能先读取 SKILL.md 以确定输入范围，再在源文件中定位范围内内容的位置。源文件全程只读，不修改。"——陈述机制与理由。

### 跨类组合

- 语体残留 × 推断未标注：复述指令时，指令背后的"为什么"被一并丢掉——既像指令，又缺了该补的理由
- 语体残留 × 内容失真：转述"做什么"时省略"为什么"，若理由在源中有明文，就是省略
- 语体残留 × 视角漂移：步骤转述中插入主题背景，读起来像"命令 + 科普"的拼贴

### 自查句

- 读起来是在陈述"是什么 / 为什么"，还是在复述"你必须做什么"？
- 每一处约束都有理由和边界吗，还是只有"禁止"？
- 读者合上书，能说出"这个技能为什么这样设计"吗？——说不出，语体残留嫌疑

## 快速定位表

交付前自查时，从现象反查类别：

| 现象 | 主要类别 |
|------|----------|
| 出现源里没有的规则 / 丢例外 / 阈值变了 | 内容失真 |
| 大段主题背景，技能机制模糊 | 视角漂移 |
| 理由无出处、无标注 | 推断未标注 |
| 通篇祈使句复述，无解释 | 语体残留 |
| 结构套模板，独特内容装不下 | 内容失真（反模板） |
| 多个技能的内容互相串了 | 见 [multi-skill.md](multi-skill.md) 归属纪律 |
