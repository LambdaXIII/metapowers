# rehearsal 规格

本域是推演（rehearsal）技能：切除作者知识，模拟接收方的首次接触 → 理解 → 决策，以卡住之处定位材料的缺陷。约束对象是推演过程与推演产出的评估，不是被推演的材料本身。

## 边界

- **指导止于推演结论**：本技能应当覆盖从推演准备到评估产出，但不能延伸到报告解读、意见取舍与材料修改，也不得给出「通过 / 不通过」类判定。
- **偏离如实记录**：材料与其设计意图不符时应当记录偏离与修复方向，但不能反向修改设计意图使之与材料一致；推演不得当作严谨校对使用或宣称与严谨校对等价。

## 硬性约束

- **硬性约束只在骨架上**：强制措辞应当只落在准备 → 模拟 → 评估的流程骨架上，不能写场景特化规则，也不能设「必须记录」类机制。
- **评估整理**：评估只做归类、排序与判断，不能二次发现缺陷，也不能采用固定评分机制；严重程度格式由载体类型决定，1-5 星仅用于跨版本量化追踪。
- **委派下发边界**：向子代理只能下发身份设定、材料与输出格式，不能下发推演方法、评估维度、验证点与预期路径；对读中第 n 段的反馈必须先于第 n+1 段送达，上游文本须前置并入并标注为背景或声明推不到，不能静默假设已知。反例：「默认它读过前文」。
- **缺陷分类**：缺陷统一以「元语境渗漏」表述，判定只走读者身份检验，不能以信号清单替代；修复方向只有删除、归位、转化三类，不能新增第四类；从材料未提及处推出的结论须对照作者意图，有意省略不算缺陷。

## 内容形态

- **用词与表述**：被模拟对象统一称 reader，不能以 user 专指；「快速」「零成本」类定位词只留在 description 匹配面，不能进正文。

## 触发

- **两条进入线**：应当同时命中用户请求与交付前自问（没上下文的人读得懂吗），但不能收纯错别字、标点与格式调整；纯代码逻辑验证仍触发。
