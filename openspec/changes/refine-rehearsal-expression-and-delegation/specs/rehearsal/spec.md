# Spec Delta

## REMOVED Requirements

### Requirement: 行为边界——推演止于评估
**Reason**: 「推演止于评估」可被误读为对推演行为的流程约束（「做到评估即停手」），而其真实含义是技能指导范围的声明；且「评估」在技能内是 P5 的专有步骤名，同一词承担两个角色造成双重歧义。
**Migration**: 全部行为契约由新 Requirement「行为边界——指导范围止于推演结论」承接：表述从流程约束式改为范围声明式；原场景「修改决策不越界」「偏离如实记录」语义保留；「推演是轻量模拟手段、不作为严谨校对使用」的定位声明原文保留。

## MODIFIED Requirements

### Requirement: 元语境渗漏术语群
缺陷分类法以「元语境渗漏」（英文对照 Context Leak）为统一术语，指作者身份的语境（设计意图、讨论背景、写作时的自我定位）泄漏进材料。术语约束：(1) 不引入「元语境 / 文字语境」「写过程 / 读过程」等独立语境模型术语——语境概念一律通过「作者身份 / 读者身份」表述；(2) 判定标准只有读者身份检验一条（这段内容是读者身份需要的，还是只有作者身份才懂、才在乎），任何信号清单扩展都不成为替代判定；(3) 观察形态保留两名：悬空参照（无法解析，归偏差方向）与身份边界错位（能解析但读者身份不需要，归过度方向）；(4) 修复方向三分——删除 / 归位 / 转化——已穷尽，不新增第四类，转化保持约束强度同档；(5) 「不正确的暗示」是偏差方向的独立缺陷类型，不与元语境渗漏合并。暗示的来源包括材料写了什么（结构、顺序、标题、措辞），也包括材料没写什么——材料未提及某项，读者会推断该项不需要、不存在、不被支持或不危险——以及详略与措辞强度的对比：对一处详加说明或使用强制措辞，而对同地位的事项从简或不用，读者会推断后者不重要或不受约束。缺席不都是暗示：有意省略与依赖外部约定的省略不构成缺陷，核对标准不变——读者做出的推断是否为作者意图；(6) 不显式区分「内容完整 / 表述准确」两个操作层面——推演一次性完成两层检查，显式分层制造「分别对待」的错误暗示。

#### Scenario: 判定只走读者身份检验
- GIVEN 一段疑似元语境渗漏的文字，其措辞无任何作者现身信号
- WHEN 判定是否渗漏
- THEN 用读者身份检验判定（读者身份是否需要），不依赖措辞信号清单

#### Scenario: 修复三分不得扩类
- GIVEN 一处元语境渗漏的修复方向归类
- WHEN 检查分类集合
- THEN 归入删除、归位、转化之一，不存在第四类

#### Scenario: 缺席推断对照意图核对
- GIVEN 材料未提及某能力或选项，模拟读者由此推断其不存在或不被支持
- WHEN 处理该信号
- THEN 对照作者意图核对读者从缺席做出的推断：推断非作者意图且由材料触发的，按偏差或过度方向记录；刻意留白或依赖外部契约的缺席不构成发现

## ADDED Requirements

### Requirement: 行为边界——指导范围止于推演结论
本技能指导推演本身：从推演准备到推演结论（评估依据）的产出。推演结论产出之后的工作——推演报告如何解读、其中意见如何取舍、材料是否修改与如何修改——属于使用者当前任务的一部分，不由本技能定义；本技能指导任务中的推演步骤，不替代使用者的任务。评估结论本身不含对错判定，不设「通过 / 不通过」类出口。推演是轻量模拟手段（不依赖外部资源、可反复执行），不作为严谨校对使用，也不宣称与严谨校对等价。

#### Scenario: 修改决策不越界
- GIVEN 推演发现材料存在偏差
- WHEN 产出评估
- THEN 交付归类、排序后的发现与修复方向建议，不直接修改材料、不给出通过与否的判定

#### Scenario: 偏离如实记录
- GIVEN 推演发现材料偏离其设计意图
- WHEN 处理该发现
- THEN 如实记录偏离，不修改设计意图使其与材料一致

#### Scenario: 范围声明不写作流程约束
- GIVEN 技能正文表述指导范围的边界
- WHEN 检查该表述
- THEN 它声明技能指导范围与使用者任务的分界，不使用可读作「推演到某一步骤停手」的流程约束措辞

### Requirement: 委派推演形态
委派推演的形态在通用论述的执行策略处集中并列记述，共三形态：单推演者委派（材料整体交接给一个子代理）、批量委派（按场景交接给多个子代理）、代理对读（分段流水交接）。三形态共用同一机制——将模拟阅读委派给独立的子代理，以隔离推演者的隐含假设——形态的区别在委派的结构；各形态记述其委派结构、由此导出的适用条件与代价。通用方法（推演者自我模拟）为基座，始终完整可用，不因委派能力存在而被替代。各形态的选用条件表述为能力前提下的裁量——具备委派与通信能力时可考虑选用——不由能力存在而自动触发。

#### Scenario: 三形态入口集中
- GIVEN agent 阅读通用论述执行策略的委派推演论述
- WHEN 检查形态记述
- THEN 三种形态并列记述、入口集中，各形态写明委派什么、怎么委派、适用什么、代价是什么

#### Scenario: 通用方法不依赖委派
- GIVEN 推演者不具备委派能力或选择不委派
- WHEN 执行推演
- THEN 通用论述的推演步骤（准备、模拟、评估）完整可用，不需要委派能力即可完成推演

#### Scenario: 选用条件为裁量表述
- GIVEN 技能正文表述委派形态的选用条件
- WHEN 检查其表述
- THEN 条件以「有能力委派时可考虑选用」的裁量口径表述，不表述为「能用则选」的能力触发

### Requirement: 代理对读
代理对读是委派推演的形态之一：主侧承担推演准备、按材料自然结构切分片段、逐段传递与评估整理；子代理只以设定的读者身份阅读当前片段，对每段产出理解状态反馈（复述、期待、困惑）。反馈时序约束：子代理对第 n 段的反馈先于收到第 n+1 段。下发内容限于身份设定、当前片段与反馈任务，不含材料其余部分、推演方法与评估维度。适用条件：具备委派与多轮通信能力时可考虑选用，适用于篇幅长、前后依赖强的材料——读者形成的预期要到后文才核对得上，预知后文会使核对失效。方法文档如实交代方法边界：切分依材料自身的结构单元进行，不为推演效果另设边界；片段依赖的上游文本前置并入并标注为背景，或声明该路径推演不到；适用面为线性消费的材料，分支消费形态按路径多轮对读或如实声明不适配。

#### Scenario: 反馈先于下一段
- GIVEN 代理对读正在进行
- WHEN 检查传递顺序
- THEN 子代理对当前片段的反馈发生在下一段传递之前，对后续内容的预期先于该内容被记录

#### Scenario: 下发不含材料全貌
- GIVEN 主侧向子代理传递片段
- WHEN 检查下发内容
- THEN 只含身份设定、当前片段与反馈任务，不含材料其余部分、推演方法与评估维度

#### Scenario: 上游依赖显式处理
- GIVEN 某片段的理解依赖上游前文
- WHEN 主侧准备该片段
- THEN 上游文本前置并入并标注为背景（不作推演对象），或声明该路径推演不到，不静默假设子代理已知

#### Scenario: 分支消费如实声明
- GIVEN 材料为决策树分支消费形态（如多路径知识库）
- WHEN 判断代理对读的适用
- THEN 按路径做多轮对读或如实声明不适配，不做万能宣称

### Requirement: 表述朴素性
技能正文（SKILL.md 与 references/ 全部内容）的表述遵守朴素性约束：自创术语在首次出现处给出定义或朴素解释，后续使用与定义一致；不使用未经铺垫的隐喻与比喻承载判断——比喻旁有直白表述，判断依据不依赖比喻；方法论框架以要素展开的方式介绍，不以要素名压缩成的连字串替代解释。

#### Scenario: 自创术语先定义
- GIVEN 技能正文引入一个自创术语
- WHEN 检查其首次出现
- THEN 术语在首次出现处有定义或朴素解释，读者不参与编写过程也能凭该处文字理解术语含义

#### Scenario: 判断依据不依赖比喻
- GIVEN 正文使用比喻或隐喻
- WHEN 检查该处表述
- THEN 比喻不作为唯一解释载体，其所指的判断以直白表述在同处可获取

#### Scenario: 框架要素展开介绍
- GIVEN 一个多要素方法论框架进入正文
- WHEN 检查其介绍方式
- THEN 各要素被逐一介绍或指向其定义处，不以「A-B-C」式连字串替代解释
