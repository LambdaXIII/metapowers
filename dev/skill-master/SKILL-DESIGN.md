# skill-master — 设计锚定文档

> 本文档锚定 skill-master 技能的设计方向、设计目标和关键决策（含理由）。
> 目标读者：未来参与该技能开发/维护的人（可能是未来的自己），未参与设计对话。
> 文档自包含，不引用会话；术语见下方「术语」节。

## 背景

metapowers 仓库是技能开发工坊，其自身的技能开发知识此前沉淀在 journal
的 Skill Dev 域（方法论 4 篇 + 实战 5 篇 + 调研若干）。门户文件中已约定：
这些知识终将融入一个名为 skill-master 的技能，届时 Skill Dev 域整体退役。

skill-master 就是这个承载者：把「如何设计/编写/修改一个技能、如何找出一个
已有技能的问题」的全链知识产品化为运行时能力，让任何零上下文的 agent 加载
后能独立完成这些工作。

## 设计意图

skill-master 是全功能的元技能：让零上下文 agent 独立走完「实践 → 技能」的
全程——判断值不值得做、把内容写成另一个 agent 一次读懂的文档、组织成符合
开放标准的结构、交付前验证真的能用。技能是实践的沉淀物（先有被走通的做法，
技能把它搬运给任何 agent），这一世界观是讨论底座，不写进技能正文。

性格：**指导支持，而非规范限制**。以要点提示为主、辅以简单的推荐流程、
给足发挥空间——agent 读完获得判断依据后自主发挥，而非照章执行。

## 设计目标

- 两类工作（设计/修改）各有一册独立站住的论述，找出问题另有一册——它是
  一种注意模式，不是第三类工作（决策 1）；SKILL.md 承载前提《什么是一个
  好的技能》与工作路由，加载即得
- 内容质量四标准——有用、全面、准确、清晰——是每一段正文的编写要求；
  框架只服务检索与维护，让 agent「做好」的是内容本身
- description 与触发面已按 general/ 披露论述重写，并经盲测定稿（5 版本 × 6 场景
  / 24 次子代理委派，记录见 test-space/trigger-check/findings.md）：业务措辞骨架
  + 一条中文自问信号，333 字符。两条关键实证决定这个形态——
  （1）中文触发词在纯英文诉求下仍被子代理直接引用为命中依据，跨语言语义匹配是通的，
  所以中英双面不是通用性负担，该删的是触发词穷举与 `Triggers:` 这类结构化标签
  （24 次决策无一引用过穷举动词，它们只贡献常驻成本与重叠面）；
  （2）压到 262 字符会让「判断质量」路径在决策里的位次被 rehearsal 抢走，
  故不追求最短，追求精准

## 现状：已成文，未验证

十二册支撑文档已按骨架成文：每节的判断依据来自 journal Skill Dev 域的
实质洞察、开放标准原文、仓库活技能样本三者之一，无来源的句子不落笔。
各册标题表述读者的工作，不宣布文件身份。

分册由两条轴组成：论述轴（设计 / 修改 / 找出问题）+ 内容轴（`documents/`
`scripts/` `general/`）。内容轴的分组是**内容性质**，不是打包位置——
含入口文件这一册（决策 13）。披露的机制与 `description` 的定稿分在两篇
（决策 14），合起来的读者时机不同。

未完成的义务：还没走设计论述要求的验证环节（委派无上下文子代理凭文档
完成目标任务）。机械合规已过（断链零、frontmatter 合法、`name` 与目录名
一致），自足性未验。版本号因此停在 0.3.0，不进 1.0.0。

## 关键架构决策

1. **两工作加一种模式，调试不独立**。设计、修改各一册论述；找出问题是
   一种**注意模式**，不是第三种工作，与症状排查同册。理由：审查与修改是
   两种注意模式而非两个工序——边看边改会让剩下的面没人扫；生命周期上不
   存在「设计→编写→验证→审查→修改」这样一条链，它可以在任何时点切入。
   「行为与预期不符」的静态排查与它同根，是本册的第二个进入方式，排查后
   的修复本属修改。不设调试分册：journal 无调试方法论素材，行为不对是写
   得不对的表现。
2. **不设技能类型框架，结构层分册删除**。知识型/操作型/模板型的类型分流
   不采用：文件组织已有开放标准约束，类型标签不增加真实的组织约束；此前
   按类型框架写的 structure-* 四册删除。理由：类型框架是 journal 承载结构
   的残留，用其知识不用其设计；「去掉技能后最缺什么」只作为锚定阶段的一条
   判断依据，不是组织骨架。
3. **「素材提炼」概念消解**。不设材料提炼章/册：所谓提炼知识实际是各内容
   形态的编写方法（先加后减、弯路转 Gotchas 归论述型编写；范例拆解、试填
   验证归模板编写）；材料齐备度/可行性归锚定的价值判据。理由：「提炼」是
   journal 六阶段框架的残留阶段，拆开后没有任何知识真正属于独立环节。
4. **references 按内容性质分三个次级目录**：documents/（文本类家族：各
   文档形态的编写方法 + writing-craft）、scripts/（脚本设计论述 +
   scripting-craft）、general/（跨类通用：规范册、披露设计论述）。理由：
   扩展在目录内进行，顶层三册论述稳定；内容性质（文本/脚本/跨类）是
   编写方法的真实分组轴。
5. **打包/编写分离**。目标技能的打包目录（SKILL.md / references /
   templates / scripts / assets）是开放标准的放置规范，由 general/ 规范册
   转述；编写论述的分组（决策 4）与之正交——工作流文档打包成 asset 不改变
   其编写论述归属 documents/。理由：混淆两轴会导致「按打包位置找编写方法」
   的错误路由，模板编写论述因此放 documents/ 而非按打包目录另设顶层。
6. **四形态收敛**。知识=静态客观资料（打包归 assets，是查的不是读的）；
   references 只区分工作流（照着走）与论述（读了懂自己发挥）两形态；提示
   是论述的笔法，不是独立形态。理由：四形态并列会造成「知识型 reference」
   这类错误归类，收敛后形态边界清晰。
7. **前提进 SKILL.md**。所有工作共享的前提背景置于 SKILL.md 加载即得，
   SKILL.md 因此是「前提 + 路由」而非纯路由。
   共享背景枚举（枚举各工作论述假设读者已知什么、取交集）已完成，交集
   是三项：技能靠三层加载生效、读者是零上下文 agent、内容四判据（有用、
   全面、准确、清晰）。三者分别是三册论述的地基——设计据此定组织与
   成本，修改据此定改动边界，审查据此定判定锚点。前提节内容见 SKILL.md；
   v0 的前提内容（四特征检查清单）为无来源编造，已清除。
8. **编写手艺两层分离，craft 随对象**。各形态论述讲「这类内容怎么组织怎么
   写」；craft 讲跨形态通用的编写要点（正向陈述、量化模糊词、完成判据、
   指针三要素、no-op 检验）。writing-craft 归 documents/（服务文本类），
   脚本因非散文单设 scripting-craft 归 scripts/。理由：通用要点与形态特化
   是两个层次；craft 跟服务对象走比跟「通用性」走更符合检索路径。
9. **取材原则：用知识不用设计**。journal 的六阶段流程、类型架构、模式/规范
   编号清单是其知识库的承载货架，不搬入本技能；只取货架上的实质洞察（如
   「禁止词让被禁行为更可及」「不收集就消失是焦虑幻觉」「推演验证查的是
   写全了没有不是写错了没有」），按本技能自己的结构安置。
10. **分册命名**：工作论述带 skill- 前缀（skill-design / skill-modify /
    skill-review），craft 以 *-craft 命名，论述/规范册用职能名。理由：命名
    模式区分文档身份，内容增长后文件名自解释。
11. **推荐流程轻量**。工作论述以要点并列组织；整体路径只轻轻带过（「大致
    这么走，卡住随时回头」），不设阶段门禁。理由：设计是发现过程，强制
    顺序会把论述误导成步骤；仅内容本身是程序时才用流程形态。
12. **骨架先于成文**。v0 判废后以大纲骨架重建：每节先完成设计（读者在
    这个阅读位置需要什么、依据哪些真实素材），再展开成文；未完成设计的
    节保持要点态。理由：v0 的病不在句子质量，在生成快于理解——先有设计
    动作与真实素材，成文才不是拼接。
13. **入口文件单设一册**（`documents/skill-md-writing.md`）。理由：它是
    唯一必存在、且每次命中全额支付的文件，形态问题（前提节怎么产生、路
    由按什么轴组织、索引与路由怎么合一、不触发条件放哪、`description`
    怎么定稿）此前零覆盖——`writing-craft` 明示「对 SKILL.md 一视同仁」
    却只到句子层。它不属于 documents/ 三册按「读者缺什么」的分野（动作
    序列 / 输出框架 / 判断依据）：入口读者缺的是「从这里能去哪」。归
    documents/ 的依据是决策 4 的文本类轴，且与 essay/template/workflow
    命名同族。
14. **披露拆两篇**。`general/disclosure.md` 收机制与判据（加载器三条、
    可见性决策、正匹配信号与遮蔽源、两条触发路径、反向条件、不误指向、
    命名）；`documents/skill-md-writing.md` 收 `description` 的定稿流程
    与回归（先扩后删、子串模拟、双向用例组织）。理由：前者回答「什么算
    好、凭什么」，后者回答「按什么顺序做」；合并时读者在判据段落里找不
    到回归做法、在回归段落里又缺判据，且两件事的查阅时机不同。
15. **组织册定位为「取舍」而非「转述」，约束按来源分开标注**。
    `general/standards.md` 从「标准规定了什么」改为「组织一个技能的结
    构」——除标准条目外，还承载分层取舍（加载成本、下沉代价、拆册判据）
    与 references 层级模型。约束分「标准」与「环境」两列标注，理由是一
    条实证：`assets/` 是开放标准推荐的静态资源目录，而本环境 `content/`
    白名单是闭集且不含它，照标准写就违反环境硬性约束；`metadata` 同理
    （标准可选、本环境必填四子字段）。判据：判断一条约束值不值得为它改
    结构，先问它属于哪侧——地板侧无讨论空间，环境侧换环境要重判。
16. **入口的索引与路由合一**。删掉 `SKILL.md` 独立的目录节：情形路由已
    把每个支撑文件指过一遍，第二遍是重复披露（净损失），且两处会各自漂
    移。分组的路由本身即全貌；确有未进路由的文件，作为路由的一节补在末
    尾，不另起清单。
17. **审查册的方法主线改为三源交叉比对，七维降为病灶分类**。旧版以七维
    清单扫描为主，实测（n=3，见 `test-space/review-ab/`）暴露两件事：
    （1）清单扫描查的是**存在性**（这条写了没有），交叉比对查的是**一致
    性**（说的和做的是不是一回事），后者才是大头——旧版跑出来的最硬一条
    是机械项缺字段，新版跑出来的是「设计文档划的边界被正文越过、而另一
    册恪守着它」，前者后者都没抓到对方的强项；
    （2）七维里有五维的判据权威不在本册，本册只是转发，按 writing-craft
    的重复披露标准是净损失。改后：七类只留判别问句与指回权威册的指针，
    用途从「扫描检查项」变成「不一致之后的根因分类」。
18. **自违判据自足，合规判据依赖环境**。三次实测里，执行者都在最硬的那
    条上犹豫，落点决定成败：判据是自违的（技能自己声明的 vs 自己做的），
    回到设计文档原文就站得住；判据是合规的，环境规则读不到就无处落脚，
    执行者会自行降级把真缺陷放掉。因此机械项单独成节并规定动作——逐字段
    对表（不是凭印象扫过），环境不明时标「待核实」进清单，既不降级也不
    硬判。
19. **锚点不自动豁免**。实测抓到设计文档「设计意图」一句与它自己的详细
    设计及正文整章打架。三源互为基准，没有哪一源天然正确；锚点自洽优先
    ——它内部不一致时先报出来，再拿它当基准，否则后面每条判定都建在歪坐
    标系上。
20. **审查的执行固化为委派，并要求过程记录**。作者审自己参与过的产出时，
    自己的指纹从内部看就是事情本来的样子，唯一出路是委派。委派契约要求
    执行者写明「明知该查而没查的是哪几类」：**没查的那部分比查出来的更
    有价值**，它标的是方法本身的失效点，是委托方改方法的输入——三次实测
    的方法改进全部来自这一段，没有一条来自问题清单。

## 术语

本技能设计讨论中定案的术语在此单列权威。仓库契约（`docs/agents/domain.md`）
约定仓库根不设 CONTEXT.md，领域知识（术语与决策理由）在技能层——本节即其
落点。正文用词不得漂移到 Avoid 词。

### 工作与论述

- **工作 (Work)**：技能生命周期上被论述覆盖的两类工作领域：设计、修改。
  找出问题不是第三类工作，是一种可随时切入的模式。Avoid：任务、阶段、
  流程（暗示时序步骤，与论述形态冲突）
- **论述 (Discourse)**：对一种工作或一类内容编写方法的完整知识呈现；要点
  提示形态，读者获得判断依据后自主发挥。Avoid：教程、手册、指南
- **前提 (Premise)**：所有工作共享的背景判断《什么是一个好的技能》，置于
  SKILL.md 加载即得。Avoid：理念、原则
- **症状排查**：找出问题的第二个进入方式——从「行为与预期不符」沿触发链
  倒推根因，输出定位并转修改；比全量比对快，但只覆盖链上。Avoid：调试
  （已取消该独立工作）
- **病灶 (Defect class)**：给根因定性的七个高发类别——转发、自违、占位、
  空转、悬空、断链、化石。用途是**分类**不是**检查项**：比对发现不一致
  之后再归类才是对的，拿着它逐项扫会退化成走过场。Avoid：维度（旧版七
  维是扫描检查项，已被替换）

### 成品与形态

- **成品 (Artifact)**：技能装载的内容产物：SKILL.md、description、参考
  文档、模板、脚本、静态资源。Avoid：材料、素材（「提炼」叙事已消解）
- **知识（成品形态）**：静态、客观、供查阅的资料；打包时进静态资源目录
  （以目标环境白名单为准，本环境为 `templates/` 或 `examples/`）。
  Avoid：参考资料（与打包目录 references 混淆）
- **工作流（文档形态）**：分步骤、照着执行的文档形态
- **论述（文档形态）**：供阅读获得判断依据的文档形态；笔法侧重提示、
  支持、启发
- **提示（笔法）**：论述的书写方式，非独立文档形态
- **编写手艺 (craft)**：跨内容通用的编写要点；文本类 writing-craft、
  脚本类 scripting-craft。Avoid：笔法（专指论述的提示式写法）
- **入口文件 (Entry file)**：技能中唯一必须存在的文件 `SKILL.md`——
  加载器靠它的 frontmatter 认出技能，读者靠它的正文决定去哪。Avoid：
  主文件、包规范文件（暗示它是内容主体，与「极简」冲突）
- **分层 (Layering)**：两件事——内容按加载成本在三层之间分配（留/下沉
  的取舍），以及资源层内部主文档与分组的层级结构。Avoid：渐进式披露
  （专指标准定义的三层加载机制，是分层的依据不是分层本身）

### 设计词汇

- **锚定 (Anchoring)**：设计起点——确定技能提供什么、指导什么、不管什么，
  并判定价值与可行性。Avoid：定位、需求分析
- **披露 (Disclosure)**：技能向加载器与用户呈现自身的方式：description、
  触发面、命名
- **触发面**：description 与触发词共同决定的「被语义匹配命中」的词汇面
- **打包/编写分离**：放置（按开放标准打包到哪些目录）与编写方法（按内容
  性质分组论述）是正交关注点

## 措辞风格约定

- 要点提示笔法：每要点讲清「是什么、为什么、给个具体场景」；不写成
  「必须/禁止」式规范条目，不堆编号清单
- 确定性陈述：只写确定的内容，无「待定/开放问题/将来可考虑」；本锚定文档
  与正文同规
- 术语以「术语」节为单一权威；正文首次出现时按需就地定义
- 开发讨论的速记/代号不进正文；正文读者是运行时 agent
- 判断依据给足理由（机制或判据），断言不悬空——这是对 skill-master 自己
  应用它所教的「有用、准确」标准
- 无来源不落笔：每句正文答得出「这凭什么成立」，来源只能是真实机制或
  被走通的实践；「对话里出现过」不是来源。输入先分类（决策/方向/启发
  素材/事实观察），启发素材的产物是设计不是文本
- 标题表述读者的工作（如「设计一个技能」），不宣布文件身份；宣布式开头
  （本文档是/读者默认已读）是成块 no-op，文档靠执行表明自己
- 写前算读者的信息状态：按加载序列推导此位置读者已知什么，已披露不重
  述、未披露不依赖

- journal 的 Skill Dev 门户（`~/.agents/journal/portal/skill-dev.md`）是
  素材来源清单，按需读取对应条目；技能完成后门户内容退役

  顶层目录——目录跟内容重量走，混合形态多到值得独立论述时再升册
- 新的文档形态出现时：先有内容，再定分组；不预先造框架
- 动 description 之前先过 general/ 披露论述的逐词判据：正匹配信号（核心
  名中英双面、贴用户说法的触发动词、自然措辞的 when-to-use）删之伤匹配；
  遮蔽源（宽泛适用面、方法论名词、触发词穷举）删之是安全收益。判据只在
  披露册维护一份，本处不复制
