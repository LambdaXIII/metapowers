# 交互流程推演
> 场景文档 — 配合推演通用论述（`../rehearsal-guide.md`）参考使用，补充交互流程载体的特化内容。

将推演方法应用于任何**交互流程**的验证。适用于：
- UI 界面：Web/移动端/桌面应用的界面和交互
- CLI 程序：命令、参数、输出、管道组合
- 表单流程：多步骤填写、校验、提交
- 操作序列：任何需要按特定顺序执行的动作关联

不适用：纯文档阅读（→ `doc-guide-rehearsal.md`）、API 调用（→ `api-design-rehearsal.md`）、代码执行逻辑（→ `logic-chain-rehearsal.md`）。

## 本载体的核心差异：交互媒介分模式

交互流程按媒介分为 UI 和 CLI 两种模式（P1 准备时确认媒介）。两种模式共享推演流程，在信号类型和边界侧重上不同。载体与模式的归属：网页/移动/桌面界面、表单流程 → UI 模式；命令行程序、终端操作 → CLI 模式；操作序列按其主要媒介归属。

**通用信号和边界始终适用**，另选对应模式的特定项（信号和边界见下两节，完整清单在下节信号表）。

| | UI 模式 | CLI 模式 |
|---|---|---|
| 信号侧重 | 视觉可发现性、困惑点、放弃点（完整清单见下节信号表） | 命令可记忆性、参数合理性、输出清晰度（完整清单见下节信号表） |
| 失败表现 | 不知道这里能点击、看不懂图标 | 不知道命令名称、参数错误无指引 |
| 恢复方式 | 返回按钮、关闭、尝试别处 | 读 man/help、猜参数名 |
| 放弃诱因 | 太多选项、不知道下一步 | 命令名称不可记、错误信息不可操作 |

## 操作者定位（P2 身份设定的要点）

操作者——第一次接触这个交互的读者。没有作者/设计者的知识，不知道任何功能在哪里，不知道正确的操作流程，不知道错误发生时的下一步。

初始状态：
- 知道目标（"我要完成 X"）但不知道怎么做
- 首次看到界面/收到第一个命令提示
- 没有预先知道功能位置或命令名称

P2 身份转换时特别需要划掉的设计者知识：哪个按钮最重要、这个功能的快捷键、菜单的层级结构。

## 模拟阅读的特有信号（P3 补充）

按操作顺序逐步走（操作序列即交互载体的"阅读顺序"），记录信号：

**通用信号（所有交互）：**

| 信号 | 含义 |
|------|------|
| "这里停住了" | 不知道为什么不能前进 |
| "这里不知道该做什么" | 缺少明确的下一步引导 |
| "这里想放弃" | 挫折感累积达到放弃阈值 |
| "这里走错了" | 被误导或误解了上一步的结果 |

**UI 特定信号：**

| 信号 | 含义 |
|------|------|
| "没看到这个按钮/入口" | 视觉层次问题——关键元素不够突出 |
| "这个图标不知道是什么意思" | 缺少文字标签或 tooltip |
| "这个流程比预期长" | 放弃率上升点——需要进度提示 |

**CLI 特定信号：**

| 信号 | 含义 |
|------|------|
| "这个命令记不住" | 命名不直观——无法自然推断 |
| "参数格式不确定" | 缺少清晰的示例或 --help 不够详细 |
| "错误信息不知道什么意思" | 需要外部查询——错误信息不可操作 |

## 边界与异常场景（P4 补充）

**通用边界：**

| 场景 | 检查目标 |
|------|---------|
| 跳过某步直接到下一步 | 引导是否依赖线性顺序？跳步者是否迷路？ |
| 从中间进入 | 非预期入口的上下文是否充足？ |
| 操作错误后尝试恢复 | 错误状态是否清晰？恢复路径是否存在？ |
| 第 N 步放弃后重新回来 | 状态是否保留？是否需要重新开始？ |
| 空输入/超长输入 | 表单校验与错误提示是否清晰（表单流程高频边界） |

**UI 特定边界：**

| 场景 | 检查目标 |
|------|---------|
| 不同屏幕尺寸/设备 | 响应式布局下功能和信息是否保持可发现 |
| 失焦/切屏后回来 | 状态保留和重新定位体验 |
| 网络中断/超时 | 错误信息和重试流程 |

**CLI 特定边界：**

| 场景 | 检查目标 |
|------|---------|
| 不同 shell/OS 上执行 | 跨环境兼容性和错误信息差异化 |
| 输出被管道到另一个程序 | 输出格式是否可预测和解析 |
| 标志组合爆炸 | 大量标志组合的交互复杂度 |

## 评估整理（P5 的要点）

**严重程度格式：** 阻塞/缺陷/建议。三级定义：

- **阻塞**：操作者无法完成目标（如首次可执行性失败）
- **缺陷**：操作者能完成但体验受影响（如困惑点密度高）
- **建议**：交互细节改进

**评估维度提示（额外提示，非硬性指标）：** 覆盖检查仍按通用论述 P5S4 进行——以通用论述评估维度表为基准，本表为可选的额外提示。

所有交互通用：

| 评估维度 | 含义 |
|------|------|
| 首次可执行性 | 首次接触时无需外部帮助就能完成目标 |
| 困惑点密度 | 操作过程中疑问、停顿的频率 |
| 放弃率预估 | 最可能放弃的步骤和原因 |
| 错误恢复路径 | 操作错误后能否自行回到正确路径 |

UI 扩展维度：

| 评估维度 | 含义 |
|------|------|
| 视觉可发现性 | 关键功能和状态是否可被注意到 |
| 操作反馈及时性 | 每次操作后是否有明确的系统反应 |

CLI 扩展维度：

| 评估维度 | 含义 |
|------|------|
| 命令可记忆性 | 命令名称和参数格式是否易于记忆 |
| 参数合理性 | 参数命名、格式、默认值是否合理——"参数格式不确定"信号的对应维度 |
| 错误信息可操作性 | 错误信息是否告诉操作者怎么修——"错误信息不知道什么意思"信号的对应维度 |
| 输出可解析性 | 输出是否清晰、可预测、可被程序解析 |

**复现对照注意（P5S1）：** 回到 P1S3 整理的作者意图（编写时的理解），按四向对照复现理解。偏差不一定说明交互有问题——可能是操作者发现了一条更高效的路径。

**错误模式搜索候选（P5S5）：**

- **错误恢复路径缺失** — 操作错误后没有明确的回到正确路径的方式
- **状态保留问题** — 离开再回来时状态丢失，需要重新开始
- **视觉层次与操作重要性不匹配** — 关键功能不够突出，次要功能过于醒目

## 常见陷阱

- **把设计者知识当作操作者知识**：你知道每个功能在哪里，操作者不知道
- **只测正常路径**：高频缺陷在边界路径上——操作错误、网络中断、好奇心点击
- **混淆 UI 和 CLI 信号**：同一问题在不同模式中表现不同——不要用 UI 框架推演 CLI
