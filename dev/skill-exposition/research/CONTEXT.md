# CONTEXT — skill-exposition 重设计域模型

> 本文件是 skill-exposition 设计会话的域模型（ubiquitous language）——记录**已确认的术语定义**与**已定案的设计决策**（会话账本），不收纳实现细节。决策正式载体为 SKILL-DESIGN.md。设计来源：2026-08-08 设计讨论。

---

## 名称与定位

- **名称**：skill-exposition（中文：技能阐述）
- **中文定义**：将一个技能（或其中指定的某些方面、或多个技能）转化为人类可读的说明文形式，让人类可以通过阅读材料学会这项技能。
- **定位**：本技能产出"教会人类使用某个 agent 技能"的教学材料。人类通过阅读材料学会该技能后，可自行应用、设计更好的技能——这是学习的结果，不属于本技能范畴。
- **输入**：技能内容的一个子集，**范围由用户指定，不假定"一个完整技能"**——可以是完整技能包、技能的部分方面、或多个技能（含跨技能方面，如"这几个技能的委派机制"）。"技能"判定 = 含 SKILL.md 的技能包目录。一个方面可能跨多个源文件分布，梳理时需先在源中定位范围内内容的全部位置。
- **输出**：以人类为读者、以"学会使用"为目标的说明文（教学材料）。形态：单技能/单方面=单篇（逻辑整体，超长可拆章节文件）；多技能批量=每技能一篇；跨技能方面整合=单篇整合。语言与学习者一致，术语首次出现附源语言原文；源混排语言时：术语保留原文并附翻译，行文风格统一为学习者语言。
- **行为边界**：只读源文件、不修改；不执行、不测试被阐述的技能；不评价技能好坏。

## 术语

- **说明文**：本技能的交付物形态。以人类为读者、完整呈现技能的说明性文体（exposition 在修辞学中即"说明文/说明性文体"义）。
- **教学材料**：说明文的实质身份。阅读后可理解并运用该技能。
- **忠实性**：教学材料的硬性要求——完整、准确，不歪曲、不省略、不劣化源技能内容。理由：材料不忠实，学习者学到的是错误的技能。此要求从"学会"目的直接推出，是设计正文第一条硬约束。
- **可读性**：教学材料的硬性要求——流畅、有条理，适合人类阅读。理由：材料是教材，不是给 agent 执行的指令。
- **自包含性**：教学材料的硬性要求——产物包含理解所需的全部前提与知识（含技能之外但叙述所需的内容，如环境前提、外部概念），读者仅以产物为唯一依据，产物绝不反向链接到技能内部文件。理由：学习者拿到的是说明文而非技能源文件，材料必须独立站住——反向链接使产物退化为"索引"而非"教材"。
- **学习者**：教学材料的读者。区别于"读者"：学习者的目的是学会技能并应用，而非仅仅了解。
- **转化**：本技能的核心动作——在保持内容完整的前提下，将技能从"执行指令形态"重组为"说明文形态"。重组是形式操作，内容一个不丢。

## 边界（元语境：指导层级）

本技能指导 agent 的**阐述认知**，不展开指导**文档工程**。此边界由用户 2026-08-08 定案，是重设计的第一原则。

**边界模型 = "展开指导 / 效果提及"**：不着重 ≠ 去掉。界内内容展开指导（给方法）；界外内容以**效果级提及**存在——只声明要达到的效果，不展开 HOW，把方法留给 agent 的通用能力。推论：技能正文很短，由"三块展开 + 几个效果句"构成。

**展开指导（界内）**：
- **梳理**：完整提取技能内容、理清结构，含源一致性矛盾裁决
- **阐述陷阱**：内容失真（省略/歪曲/劣化/添油加醋）、视角漂移（阐述主题而非技能）、推断未标注、语体残留的认知面（把说明文写成指令复述——只指认知错误，句式机制不展开）
- **组织知识**：教学逻辑——知识如何排序、分组利于学习（是什么→怎么用→边界规则→为什么），知识层组织，不指导文档层结构

**效果提及（界外）**：
- 质量检查：提示"编写后应进行质量检查，确保内容完整、忠实、不含源中没有的断言"等效果，不展开检查步骤/维度/停止规则
- 行文：提示"以人类可读的说明文形式呈现"等效果，不展开句式/语态/风格
- 工程执行：提示输出契约（"产出说明文、内容完整"），不展开文件结构/管道
- 收尾自查：交付前对照陷阱清单自查，一句提及，不设计质检流程

**推论**：流程工程阶段（理解/解构/编排）在界内，表达/质检在界外；流程与行文类文档几乎全部出界，仅知识分类、少量组织原则、边界情况表与单文件章节顺序有继承价值。

## 结构（2026-08-08 定案）

仿 rehearsal 技能：**通用论述 + 按需加载的启发库**。此结构是 metapowers 仓库既定规范（SKILL.md 入口化，已固化于 AGENTS.md §4.8），非本技能特例——SKILL.md 极简（命中/触发/路由），方法主内容在 references/ 主文档。

- **SKILL.md**：入口（薄）——这是什么、触发条件、路由表
- **references/通用论述**：完整方法（展开指导三块：梳理、陷阱、组织；+ 效果提及句），独立站住、自包含

**所有参考文档定位**：按需加载、自行判断、提供启发，非必读（通用论述为必读主入口）。

**参考文档分类（2026-08-08 定案）**——按**环节**分三类目录，非按内容性质：
- `extraction/`（内容提取，输入环节）：**按技能内部的内容类型**给提取提醒——内容类型是片段级的，一个技能可同时含多种类型（工作流程型/知识库型/规则决策型/案例型/设计思想型），遇到哪类内容就加载哪类提醒。**不是**按技能整体特征特化（技能级分类已否决，如旧"纯指令型/混合型"）
- `structure/`（结构规划，输出环节）：交付物结构设计模式，**每模式一个文件，纯资料性质**（参考手册，agent 选中哪种翻哪本）。定案 8 个模式文件：learning-path（默认，在通用论述）、golden-circle、knowledge-types、progressive-disclosure、iceberg、scenario-driven、5w1h、functional-decomposition——组织轴各异，均保留独立；金字塔原理为横切行文原则，并入 general/readability.md
- `general/`（通用，全程）：横切提示——陷阱专项、边界情况调整、可读性强化、**multi-skill**（多技能场景专项：范围界定/跨技能一致性/归属纪律/组合组织/批量纪律——只在该场景加载，不干扰通用论述）

触发机制分离符合 AGENTS.md §4.7：extraction/ 与 structure/ 按内容类型/情境匹配加载，general/ 按需要加载。分工：通用论述自包含（提取基础/陷阱框架/默认结构方案/源一致性裁决纪律），参考文档只做类型提醒、模式手册、深化。

**素材去向**：五框架（golden-circle/5W1H/iceberg/functional-decomposition/pyramid）作为"理解技能框架"使用价值有限（易被复述成冗余），但作为**结构设计模式**是合法素材——核心概念表继承，按模式手册框架重写；不作废。真正出局：流程工程（已否决）、四目录输出（已否决）、三 C 行文原则（内容并入 readability）。

## 补充定案（2026-08-08 多技能差异粗验证后）

- **混合语言源**：源混排语言时，先识别性质——专业术语（指称内容）保留原文附学习者语言翻译；行文风格（叙述载体）统一为学习者语言。产物整体语言必须一致。
- **制式性内容**：templates/、examples/ 等制式性内容按"价值在格式 → 原样保留；价值在含义 → 转述"判断呈现形态。
- **自包含**：产物是读者唯一依据——包含理解所需的全部前提与知识（含技能之外但叙述所需的内容），绝不反向链接技能内部文件。

## 已否决/落选术语

- **人性化 / humanizer**：曾候选。语义是"语气软化、像人写的"，与本技能"完整呈现"不符；且与已存在的 humanizer-zh 技能撞语义（运行时加载器会混淆触发词）。
- **解构 / deconstruction**：曾候选，落选。词义是"拆解分析"（描述手段而非交付物），且中文语境带批判/消解色彩，与忠实性要求冲突。保留为流程内部的方法论词汇（分析阶段名），不作技能身份词。
- **guide / tutorial / handbook / blueprint / methodology / essence / doc / explainer**：命名讨论中的其他候选，均落选。guide 等为"向导/教程"视角（读者出发），阐述/exposition 为"完整呈现"视角（内容出发），后者承载忠实性要求。
