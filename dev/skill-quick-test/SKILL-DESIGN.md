# skill-quick-test 设计文档

> 本文档记录 skill-quick-test 的设计意图和核心决策，作为维护参考。

---

## 设计初衷

技能开发中存在一个验证缺口：

- **skill-creator 测试**验证功能正确性（能加载、能执行）
- **缺少**验证可用性的手段——Agent 能否理解指令、走通流程、完成任务

本技能填补这个缺口：通过子代理并行推演，在不实际执行的情况下模拟 Agent 使用技能的完整链路。

---

## 核心设计决策

### 1. 推演而非执行

测试子代理不实际执行被测技能的功能（不画图、不写代码、不调 API），而是推演"如果我按这个技能的指引走，会怎样"。

**原因**：
- 隔离——测试不应污染被测技能的目标环境
- 速度——推演比执行快一个数量级
- 可重复——不依赖外部服务或特定项目状态

### 2. 能力模拟（Capability Simulation）

被测技能中涉及的外部能力（子代理委派、工具调用、脚本执行），测试子代理不实际调用，而是模拟执行并记录假设。

统一标注：`[能力模拟] [类型] → 动作 → 推演结果`

**原因**：测试目标是技能文档的清晰度，不是运行时行为。如果技能文档写得清楚，子代理应该能正确推演出预期结果。

### 3. 隔离铁律

子代理不能知道：预期效果、其他测试单元的存在、这是 baseline 还是实验组、任何对比信息。

**原因**：知道预期效果会引导子代理"朝着正确答案走"，失去测试意义。baseline 的价值在于"不知道技能时 Agent 会怎么做"。

### 4. Light / Full 双模式

- **Light**：复杂场景 < 2 且总数 < 5。全部在对话中完成，不写文件。适合快速验证。
- **Full**：复杂场景 ≥ 2 或总数 ≥ 5。前置写测试计划，子代理写报告文件。适合全面测试。

**原因**：简单测试场景不需要文件 I/O 的开销；复杂场景需要结构化的报告管理。

### 5. 计划闸门（Full 模式）

委派子代理前必须写入 test-plan.md。未完成前禁止委派子代理。

**原因**：测试计划中的预期效果是汇总阶段的对比基准。跳过计划会导致汇总时无法评估"技能是否引导了正确行为"。

### 6. 报告格式硬约束

报告格式从推演指引中独立出来，作为硬约束。禁止 JSON/纯文本，每个章节必须出现。

**原因**：早期版本中子代理返回格式不统一（JSON、自由文本、混合），导致汇总阶段解析困难。提升为硬约束后格式一致性显著改善。

### 7. 触发测试维度（独立 reference）

**方向**：新增 references/trigger-check.md，作为现有测试框架的补充说明，定义一种「触发测试单元」测技能 description 在真实触发场景下能否被选中——盲测：技能池（含大量其它技能）+ 真实业务诉求场景，子代理自由决定加载哪个，测试者不预设答案。

**原因**：

- 正文六步测试的起点在「已触发」之后，不覆盖加载器选择环节——触发失败是技能不可用的第一道关卡
- 触发是加载器面对技能池 + 真实用户诉求的选择行为——场景必须是触发源（真实业务诉求）而非触发词；测试者构造「对口触发词」的测试是自我印证，无效
- 依据 omp 全量注入 + 纯语义匹配机制实证（正匹配信号 vs 遮蔽源判断框架）：触发效果由「词的性质」决定，与长度无关——测试针对匹配面，不针对字数
- 触发测试单元框架本身不独立于主测试框架——它复用主框架的场景设计、委派与汇总，只补充一种单元类型与评估视角，不新增执行路径，避免技能复杂化
- 红绿预期（正场景预期加载 / 反场景预期不加载）只作测试者评估对照，不进入子代理 context，保持盲测

**不变量**：

- 场景是触发源不是触发词；子代理只见技能池 + 诉求原文，不见被测技能强调、红绿预期、测试意图（漏题红线）
- 可准备多份技能池，同场景组跨池对比某次 description 改动对命中率的影响
- 触发测试单元复用主框架的场景设计、委派与汇总，不新增执行路径；是可选补充，不替换、不强制
- 触及被测技能 description 设计意图的改动，先更新该技能的 SKILL-DESIGN 记录决策，再动 description

## 维护注意事项

### 错误模式清单（error-patterns.md）

- 只增不减——某个模式长期未触发 ≠ 没用
- 模式不绑定具体技能——每行必须泛化
- 每次测试后回顾发现的缺陷，可泛化的补入清单

## 措辞风格约定

- **SKILL.md 用英文编写**（2026-08-23 定）：技能入口全量英文化；description 保留中英双触发词（推演/测试/验一下/快速验证/走通 + rehearsal/test）
- **跨文件协议字面量不翻译**：`[能力模拟] [委派/工具/脚本] → 动作描述 → 推演结果`、「推演中止」等与 references 模板共享的字面量保持中文原样——SKILL.md 英文化时不得单方面英化，否则主代理与子代理报告检索失配；待 references 同步英文化后统一
- 被测技能统一称「被测技能」（英文 the tested skill），术语不混用
