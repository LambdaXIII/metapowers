# 触发效果检查（Trigger Check）

> 📍 本文件是 skill-quick-test skill 的参考文件。主入口和决策树请见 SKILL.md。

---

## 定位

本文件是现有测试框架的**补充说明**——在框架内定义一种**触发测试单元**，测技能 description 在真实触发场景下能否被选中。

它**不是独立的执行路径**：触发测试单元复用主框架的场景设计、子代理委派与汇总评估，只改变「测什么」（description 触发而非正文可执行性）与「怎么评估触发结果」。正文测试单元答「技能被加载后能否理解走通」，触发测试单元答「该不该被加载」——两者互补，共用同一套委派与汇总机制。

---

## 盲测原理

触发测试要能测出东西，前提是**测试者不知道答案**。两个不变量：

- **场景是触发源，不是触发词**。真实用户不喊技能名，而是表达业务问题（「我们需要更好地解决 XX 问题」→ 可能触发 web-deep-research，而非「我要深度研究」）。测试场景必须是这种真实业务诉求。
- **不预设命中**。技能池含大量技能，子代理自由选择。被测技能被选中与否不可预知——这才反映 description 的真实触发力。

任何「告诉子代理该选谁」「场景为命中而造」的测试都是自我印证，无效。

---

## 触发测试单元的设计

### 技能池

一份只含 **name + description** 的清单，包含：

- 被测技能（description 用原文）
- 大量其它技能：从真实技能列表取材，也可编造；至少 8–10 个，保证选择有区分度
- 刻意混入与被测技能相邻 / 主题相近的技能，测区分度（遮蔽）

技能池由主代理准备，写入一个临时文件（`skills-pool.md`），子代理用文件读取能力加载——池大时避免撑爆 context。

**多份技能池（对比效果时）**：要量化某次 description 改动对触发的影响，准备多份池，其余技能相同、仅被测技能的 description 不同（改版前 / 改版后）。同一组场景跑多份，跨池对比命中率。

### 场景清单

每个场景是一句**真实业务诉求**，覆盖：

- **正场景（绿）**：本应触发被测技能的业务问题（不点名技能），预期加载
- **边缘场景**：可能沾边、需要判断到底用不用被测技能，预期不确定
- **反场景（红）**：与被测技能无关，预期不加载

> 场景绝不含触发词本身。例如测 web-deep-research，写「用户要求：我们需要更好地解决 XX 问题才行」，不写「做深度研究」。

红绿预期是**测试者的评估对照基准**，只标在测试者侧，**绝不进入子代理 context**。

### 子代理 context（委派时严禁漏题）

触发测试单元按主框架委派子代理，context 用以下模板：

```
你是技能加载器。给定一个技能池和一段用户诉求，决定加载哪些技能。

技能池（文件）: [skills-pool.md 路径]
用户诉求: [场景原文]

任务：
- 阅读技能池中所有技能的 description
- 判断：基于这段用户诉求，你会加载哪个（或哪几个）技能？为什么？
- 只返回思考过程 + 加载决策，不执行任何技能。

输出格式（硬约束）:
- 加载决策: [技能名列表，可空]
- 思考过程: [逐个比较候选技能时，你看了 description 里的哪些词、为什么排除/选中]
```

**漏题红线**（以下信息绝不能出现在 context）：

- 被测技能是哪个、它的名字被强调
- 「这段诉求应该触发某技能」的任何暗示（含红绿预期标注）
- 这是针对某技能的测试、场景与技能的对应关系

子代理只看到：技能池文件路径 + 用户诉求原文。

> 技能池**含**被测技能是允许的——盲测是「不预设该选谁」，不是「隐藏被测技能」。红线只禁强调、暗示、预设，不禁技能池列出被测技能。

## 评估触发结果

触发测试单元的结果随主流程汇总。汇总时对照红绿预期与实际加载决策：

| 场景 | 预期 | 观察 | 判定 |
|------|------|------|------|
| 正场景（绿） | 加载被测技能 | 是否选中 | 未选中 → 正匹配信号不足（description 缺真实业务措辞） |
| 正场景（绿） | 加载 | 选中理由基于哪些词 | 凭猜 / 凭位置而非 description 正匹配词 → 信号弱 |
| 边缘场景 | 不确定 | 能否有依据地判断 | 无法判断或摇摆 → 措辞模糊 |
| 反场景（红） | 不加载被测技能 | 是否误选 | 误选 → 触发面过宽 / 反向条件缺失 |
| 任一 | — | 是否被相邻技能抢走 | 被相邻抢走 → 区分度不足（遮蔽） |

修复方向映射到 description：补真实业务措辞 / 补另一条触发路径 / 收敛宽泛适用面 / 去相邻重叠。

**多份技能池对比**：同一组场景跑多份池后，跨池对比命中率（正场景选中被测技能的比例）与红绿预期偏差随版本的变化，量化某次 description 改动是提升还是降低触发。

> 触及被测技能 description 设计意图的改动，先更新该技能的 SKILL-DESIGN 记录决策，再动 description。
