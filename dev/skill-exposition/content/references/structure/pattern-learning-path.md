# 学习路径模式（learning-path）

> 按**学习顺序**组织内容：从"知道是什么"到"知道怎么用"到"知道边界与规则"到"知道为什么这样设计"。本模式是默认结构方案（概要见 exposition-guide.md 第 4 节），本文件为其完整手册。

## 模式定位

组织轴是**学习顺序**。章节按照一个新手学习者理解技能的先后次序排列：先建立"这是什么"的认知，再学会"怎么用"，然后了解"边界与规则"，最后理解"为什么这样设计"。每一章是后一章的前提——读者按顺序读完全文，即完成一次完整学习。

## 适用情况

- 读者以**零基础新手**为主，需要从头学会技能，而非查阅某类信息
- 技能内容存在一条自然的理解链：不知道"是什么"就看不懂"怎么用"，不理解"怎么用"就难懂"边界"为何存在
- 技能规模适中，读者预期会**通读全文**（而非跳读）
- 无法确定读者诉求时，本模式是最稳妥的默认选择

## 结构示意

章节顺序（依据技能内容增删合并，骨架不变）：

1. **这是什么**：一句话定义 + 解决什么问题 + 适用对象（术语在此定义）
2. **怎么用**：能力与流程，配合典型示例逐步说明
3. **边界与规则**：何时不该用、阈值、条件、例外、约束
4. **为什么这样设计**：设计理由与决策依据（源中没有的理由按推断纪律标注，见 exposition-guide.md 第 3.3 节）

要点：

- 示例不单独成章，而是嵌在"怎么用"中随步骤出现——读者在学用法时看到例子
- 概念与术语在"这是什么"中定义，术语较多时可在"怎么用"前单列一个小节，遵循"先定义后使用"
- 源中没有可提取的设计理由时，"为什么这样设计"一章可合并进"边界与规则"或省略，不要为凑章节而推断
- 流程类技能在"怎么用"内按步骤展开时，该章内部就是一条完整的步骤链

## 权衡与注意

- **何时不选**：读者以有经验的查阅者为主、诉求是快速定位某条规则时，顺序通读的代价过高——可考虑按知识类型分组（knowledge-types）或分层披露（progressive-disclosure）
- **与原理优先（golden-circle）的差异**：本模式把"为什么"放在最后——先让读者会用，再解释设计；golden-circle 把"为什么"放在最前——以动机锚定读者。读者需要先被说服"值得学"时，选 golden-circle
- **组合使用**：本模式可作为分层披露（progressive-disclosure）的**内层顺序**——每一层内部仍按学习路径排列；也可作为按知识类型分组（knowledge-types）中各章内部的排序逻辑
- **反模板提醒**：骨架相同不等于内容相同。两个技能即使同为学习路径模式，章节标题可以一致，但每章内容必须反映该技能独有的内容——说明文没有忠实反映技能本身，就违背了忠实性要求
- 源中没有设计理由时不要编造，按推断纪律处理（见 exposition-guide.md 第 3.3 节）

## 示例说明

假想技能「代码审查助手」（code-review-assistant）：**这是什么**（一句话定义：自动审查代码变更并给出问题清单）→ **怎么用**（配置审查规则、发起审查、阅读报告，示例随步骤给出）→ **边界与规则**（只在本地仓库运行、单文件大小上限、不审查未提交变更）→ **为什么这样设计**（审查在本地进行以保护代码隐私 `[推断: 基于约束反推]`）。
