# rehearsal

技能让 agent 切除作者知识、模拟接收方的首次接触与理解，以卡住之处定位材料的缺陷。约束的是推演过程与推演产出的评估，不是被推演的材料本身。

## 技能的边界

### 推演的结论止于缺陷定位

技能覆盖从推演准备到评估产出，不延伸到报告解读、意见取舍与材料修改，也不给出「通过 / 不通过」类判定。agent 应当能够在推演结束处停下，把结论交给提出问题的人。

### 材料偏离设计意图时如实记录

材料与其设计意图不符时，技能记录偏离与修复方向，不反向修改设计意图使之与材料一致。技能也不把推演当作严谨校对使用，或宣称与严谨校对等价。agent 应当能够在两种意图冲突时保留原意图。

## 推演机制

### 评估只做归类、排序与判断

评估不二次发现缺陷，也不采用固定评分机制；严重程度格式由载体类型决定，1-5 星仅用于跨版本量化追踪。agent 应当能够在评估阶段只处理已经发现的缺陷。

### 向子代理只下发身份、材料与输出格式

技能向子代理下发身份设定、材料与输出格式，不下发推演方法、评估维度、验证点与预期路径。对读中第 n 段的反馈必须先于第 n+1 段送达；上游文本须前置并入，并标注为背景或声明推不到，不静默假设已知。agent 应当能够在分段交付时守住这个先后顺序。

### 缺陷统一以元语境渗漏表述

缺陷的判定只走读者身份检验，不以信号清单替代；修复方向只有删除、归位、转化三类，不新增第四类。从材料未提及处推出的结论须对照作者意图，有意省略不算缺陷。agent 应当能够用同一套判定解释每一处缺陷。

## 技能内容的写法

### 强制措辞只落在推演骨架上

强制措辞只落在准备 → 模拟 → 评估的流程骨架上，不写场景特化规则，也不设「必须记录」类机制。agent 应当能够分清哪些步骤不可省略、哪些可以按场景调整。

### 被模拟的对象一律称 reader

被模拟对象统一称 reader，不以 user 专指；「快速」「零成本」类定位词只留在 description 匹配面，不进正文。agent 应当能够在正文里用同一个词指同一类人。

## 何时加载技能

### 两条进入线都要覆盖

技能的触发面同时覆盖用户请求与交付前自问（没上下文的人读得懂吗），不收纯错别字、标点与格式调整；纯代码逻辑验证仍触发。agent 应当能够在交付前自行判断是否需要推演。
