# web-deep-research 规格

本域约束「从一个未定的问题走到一份读者可独立检验的报告」这一流程如何被规定，而不约束研究结论的内容。

## 边界

- **主题与决策分离**：应当把用户提问提炼为中立的调研主题，但不能在结论里给决策指示或替调用方拍板——研究对象是主题，不是建议。

## 硬性约束

- **问题集只做三类演化**：Q 只承载「还剩什么没答」，答案经交叉验证后转为附来源的发现并离开集合；演化限于消解、转化、新增三类，不能以「问题 + 答案」的形式留存。
- **停点二分不混用**：「不可得」须逐 Q 经实际调查确认无可达来源；「收束」是问题集不再演化的全局停点。收束不能推断出「不可得」——收束时仍开放的 Q 如实进报告信息空白。
- **采信按来源独立性判定**：跨领域、跨语言、跨地区、跨立场的一致构成强验证，同机构、同作者、同引用源头、共同利益、同测量方法的一致不构成独立佐证；领域特化文档的采信规则优先于通用规则，冲突按领域规则执行。

## 内容形态

- **领域文档各自成文**：每份按其研究对象的知识结构组织，不能套统一模板；硬约束单独成文，其余只作启发，用「可以参考」「不是必须步骤」一类软语气，不写成「必须 / 禁止」的结构要求。
- **使用层与内容层分册**：委派、拆分、整合、落盘、跑多深、产出怎么用等使用层指导应为选读参考，不能混入研究方法正文。
- **技能内容自足**：边界判断只作自足表述，不能指向其他技能名；也不写 harness 机制（子代理任务书、调用、验收回传），只写编排策略。

## 触发

- **触发面**：description 应当覆盖用户问法与 agent 自问两路，但不能承载 Phase、clue-chain 等方法论流程名。
