# skill-master 规格

本域是「对象为技能」的工作域：制作侧（设计、修改、审查、快速测试）与使用侧（预评估、后评估）的全部工作归它管，两侧共用同一套内容判据但不互相替代；对象不是技能的事在域外。

## 工作域

- **立场判界**：制作侧与使用侧按委托方立场划分，但两侧不互指——维护者找技能错处属审查（制作侧），使用者评估未用过的技能属预评估（使用侧）。

## 审查

- **三源互校**：审查应当以设计文档、技能正文、支撑论述互为基准比对，但锚点不自动豁免——锚点内部不一致时先报出、再作基准；病灶七类只在比对出不一致后用于归类根因，不作逐项扫描项。
- **排查只定位**：症状排查是审查的第二进入方式，从行为与预期不符沿触发链倒推，但只产出定位并转交修改，不自行修复。
- **审查须委派**：审查的执行固化为委派，但委派契约须要求执行者写明「明知该查而没查的是哪几类」。
- **不明即待核实**：机械项（合规判据）依赖的环境规则不明时标「待核实」入清单，但不得降级放掉，也不得硬判。

## 快速测试

- **推演不执行**：快速测试应当以推演判定零上下文 agent 能否理解、走通、用起来，但不能实际执行被测技能；流程册的流程图、门禁、中止判据与报告格式是硬约束。
- **隔离铁律**：测试子代理不得知道预期效果、其他测试单元的存在、baseline 与实验组的区分或任何对比信息。

## 使用侧

- **预评估不越界**：预评估应当凭手头证据给出带理由的结论，但不能判定技能的实际覆盖面，也不进入采纳决定的解读；某方向信息不足时如实记录缺失，不视为缺陷。
- **后评估不委派**：后评估应当逐条洞察绑定本次使用的实证、不记印象式结论，实际执行形态照实记录且偏离指引是信号不是过错；但评估不委派，证据在使用者经历里，委派即丢失。

## 触发

- **两侧工作请求**：触发面覆盖对象为技能的工作请求——制作侧与使用侧均命中，用户请求与 agent 自问两条路径都算；但要求真实执行被测技能的测试类请求不触发本技能；description 不得使用触发词穷举或 `Triggers:` 类结构化标签。
