## [2.0.1] - 2026-08-20

非功能调整（Patch）：元语境渗漏概念融入缺陷分类法（术语统一 + 判定标准 + 修复三分）与审计驱动修复轮合并发布——均为既有机制的修补与补强，不涉及功能调整。

### Added

- **元语境渗漏统一术语与判定标准**：缺陷分类法以「元语境渗漏」（英文对照 Context Leak）统一「悬空参照」与「身份边界错位」两类形态，锚定技能既有的作者身份/读者身份框架——判定标准是读者身份检验（这段内容是读者身份需要的，还是只有作者身份才懂、才在乎的），不引入独立的语境模型
- **修复三分**：渗漏修复分删除/归位/转化三类穷尽——删除（读者身份不需要）、归位（另一载体读者需要：设计意图 → 设计文档类、历史 → changelog 类）、转化（当前读者需要但形态是作者身份的，保持约束强度同档）
- **「不正确的暗示」缺陷类型**（偏差方向）：材料通过结构/顺序/标题/措辞暗示作者未意图的关系；与「概念关系未显式说明」并存（后者缺关系说明，前者暗示错关系），并补两类归类判据（主动误导结构 → 暗示；仅缺说明 → 未显式说明；并存分别记录）
- guide P3 留意清单新增「元语境渗漏」「不正确的暗示」两条识别条目；guide P5S5 补充「多处元语境渗漏 → 讨论后立即写作」错误模式示例
- **P1 准备完成标志**：三条可检查完成判据（范围声明一句话说清 / 读者画像与作者侧要素齐备 / 意图清单覆盖构思、决策、信息三类来源），停笔标准从严——意图清单是 P5S1 复现对照的唯一基准，残缺时对照在残缺基准上进行且推演者无法自知
- **P3 留意清单收束步骤**：产出最终理解状态后逐条过一遍留意模式，每个模式给出「检查过、无发现 / 检查过、有发现」，不允许「没检查」——与 P5S4 覆盖检查互补闭环
- **「嵌入优于收网」切换时机**：材料合稿时停止逐段推演，合稿后必做一次全景推演；覆盖完范围声明全部衔接带即为完成
- **P4 边界尝试操作化**：「上游已保证」定义为材料中显式声明且读者能找到声明位置；边界尝试与 P5「边界覆盖」维度挂钩（除载体确无边界外至少尝试 4 类）
- **委派条件操作化**：「材料比较简单」给出可检查近似（单文件、逻辑单元 ≤ 10、读者单一、决策路径 ≤ 3）；批量执行以场景数为准不受复杂度限制
- **taxonomy 重复方向归类理由**：补充「重复」方向引子，与劣化/偏差/过度三向对齐

### Changed

## [2.0.0] - 2026-08-08

本次为推演框架全面重构（Major）：通用论述全量重写，10 篇参考文档全量重写，设计锚定与项目规范重构，术语体系统一。

### Added

- **四向复现**：复现质量检查从三向（劣化/偏差/过度）扩展为四向，新增「重复」方向——同一概念或描述被重复定义、重复展开，读者收到同一内容的多份拷贝。精确定义：引用（后文指向前文定义）与提及（点到不展开）不是重复，只有完整的重复定义或描述才是
- **推演步骤 P1-P5 结构**：P1 准备工作（P1S1 载体与范围 / P1S2 视角锚定与期望效果 / P1S3 作者意图）、P2 身份转换、P3 模拟阅读过程、P4 推演过程回顾、P5 评估整理（P5S1 复现对照 / P5S2 发现归类 / P5S3 严重程度判定 / P5S4 修复优先级与覆盖检查 / P5S5 错误模式提取）
- **范围确定机制**：起步声明 + 主动搜索焦点；阅读范围 ⊇ 推演范围（衔接带：提前阅读入口依赖、延后阅读出口回链、覆盖被引用处与调用方）；上下文材料只读不推演；发现不设限（无范围内外标记）
- **P3 阅读机制**：「阅读和理解是两个动作」——阅读是逐段摄取，理解是持续累加流转的动态过程；每段产出理解状态（复述暴露边界 + 期待作探针），读完全程产出最终理解状态作为 P5S1 输入
- **留意之处清单**：静态模式 5 条（信息缺失/错误输入/非标准进入退出/边界变化/身份边界错位）+ 动态信号 2 类（流畅性问题含信号后行为模拟、决策点/分叉点显式标注）
- **身份边界错位概念**：材料混入作者身份内容（编写行为约束、开发侧知识、施工痕迹、作者的声音）——读者能解析但收到不该收的内容，与 Context Leak（无法解析的悬空参照）区分
- **「推演止于评估」定位**：推演的作用是提供指导性评估，是否修改、如何修改、是否通过、如何交付都不在推演技能的工作范畴（固化于 SKILL-DESIGN）
- **委派并行推演执行策略**：guide 执行策略层推荐，采纳时按方法文档执行——单推演者委派子代理代读（prompt-instruction-rehearsal「委派推演」）、多场景批量执行（batch-execution）
- **defect-taxonomy 新增三类缺陷**：重复呈现/冗余定义（重复方向）、身份边界错位与过度承诺/强度放大（过度方向）
- **通用技能设计方法论固化到 AGENTS.md**：新增 §4.6 description 规范（匹配面定位 + 5 条不变量）、§4.7 references 组织原则（特化是补充非替代/按需加载/触发机制分目录/路由维护/修改纪律）；§2.7 补「开发速记不泄漏」
- guide P5S3 通用严重程度格式示例补充计划文档、知识库（原有遗漏）
- guide 路由表 plan 条目维度描述修正（原「执行路径完整性」不在 9 项评估维度中，改为实际维度名）

### Changed

- **通用论述全量重写**：三元素（客体/载体/链路）+ 四步流程（清空/逐帧跟/边界刨/评估整理）→ P1-P5 结构；「为什么推演管用」「局限性」「与其它方法的区别」三节合并入首章「推演是什么」（推演者定位移入首章；局限性删除——同体模拟是手段事实而非方法特征）；「快速/零成本」等定位词从正文移除
- **术语统一：客体 → 读者**（通用语境），场景特化称呼保留（执行者/模型/操作者/调用者/执行引擎）——同步 guide、SKILL.md（含 description）、SKILL-DESIGN、全部场景文档
- **10 篇参考文档全量重写**：场景文档不再映射 guide 行文结构，改为自由组织的载体特化补充（读者定位、特有信号、边界场景、评估维度提示、错误模式候选）；doc-guide 全流程跨文档推演保留，并与 knowledge-base 特化差异（文档库=单一范畴、树状有序 vs 知识库=多范畴、网状关联）
- **defect-taxonomy 按四向复现重新组织**（劣化 5 类/偏差 4 类/过度 2 类/重复 1 类）；脚手架残留从 Context Leak 拆分，与身份边界错位对齐；每类标注方向归类理由
- **SKILL-DESIGN 全量重写为方向锚定版**：删除历史性内容（起源、三元素结构决策、场景文档新增记录、v1.x description 反例）；新增三个设计定位（提示性框架非工作流设计、轻量模拟非严谨校对、准确复现是总目标）与推演止于评估；description 节改写为本技能特有的五构成元素理由
- **AGENTS.md §2.5/§4.2 SKILL-DESIGN 定位强化**：锚定设计方向、设计目标和关键决策，不是技能设计的历史记录；不得包含设计决策的历史记录、随时变化且不影响方向的内容
- **委派推演三处层次化**：guide=策略推荐（补方法指向）、prompt-instruction=委派阅读如何做（含子代理提示词原则与模板）、batch-execution=批量执行如何做（定位明确为知识库多场景推演的执行方法）
- 各场景文档评估维度表标注「额外提示，非硬性指标」（与 guide 维度表同为提示，不强制对齐；覆盖检查仍以 guide 表为基准）
- plan-rehearsal 与 design-doc-rehearsal 的边界声明修正（design-doc 验证方法论本身是否自洽，plan 验证执行路径通/不通）
- logic-chain「唯一模拟对象非人」断言修正（兄弟文档存在 agent 执行者与模型读者），改为「唯一模拟无理解、无判断、纯机械精确执行」
- doc-guide 常见问题 Q2 与「嵌入优于收网」执行策略对齐（写作过程中分段推演 + 最终全景推演）
- batch-execution 术语修正（测试用例→推演场景）、补打分机制与聚合呈现≠修复顺序说明、补异常处理（子代理失败/报告矛盾/无发现）

### Removed

- **通过标准**（doc-guide 单文档/全流程、plan）——推演止于评估，不判定通过与否、不循环「修改到通过」
- **局限性与同体模拟论述**——同体模拟是「推演者只有自己的脑子可用」的手段事实，非方法特征；局限性无指导价值且产生干扰
- **三元素、四步流程、边界刨、责任边界/边界范围约束、逐帧跟、清空、作者视角步骤**等旧框架术语与概念
- **guide 完整示例节**——就地微型示例已覆盖具象化；完整示例维护成本高、易被当模板照抄，与「提示非规范」定位冲突
- **「每个维度必须有记录」「检查 N 个维度是否均有记录」等硬性表述**——改为提示性（空维度需回答「确实没问题还是没检查」）
- doc-guide 常见问题 Q1（推演 vs 审阅——与 ≠ 自查重复）
- design-doc 微型示例（无特殊步骤/处理/要求）；knowledge-base 大示例表压缩为角色矩阵节选（承载角色矩阵与多轮迭代设计方法的示例保留）
- 各场景文档中「看作者视角/设定阅读身份/显式清空」三步重复模板（场景文档只保留本载体特有的划掉清单）
