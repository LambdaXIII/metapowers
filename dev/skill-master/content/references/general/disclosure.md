# 技能的披露设计

## 披露是什么

- **披露 (Disclosure)** 是技能向加载器与用户呈现自身的全部接口：
  description（匹配面文本）、触发面（description 与触发词共同决定的
  「会被语义匹配命中」的词汇面）、命名（目录名与 `name`，兼作称呼通道）。
- description 字段的长度与必含内容是标准层面的约束，见
  [standards.md](standards.md)；本册写的是措辞怎么命中。
- 正文质量决定「加载后好不好用」，披露决定「会不会被加载、被谁加载」。
  命中前 agent 看不到正文；命中失败技能等于不存在，命中错误则把「表面
  合理、实际无关」的内容注入执行流——比不命中更隐蔽，因为它被当作权威
  使用。
- 目标不是「短」而是「精准」：正匹配信号足、与相邻技能区分度高、常驻成本
  小，三者同时成立才是好披露。

## 加载器机制

- 加载器把全部技能的 name + description 注入上下文；匹配是语义判断，
  description 是选择时唯一可见的接口；命中之后正文才被加载。两条推论：
  - description 每次会话常驻，每个词都是净成本——全程占窗口、全程参与
    与其他技能的相互遮蔽。方法论展开、流程清单都不属于这一层。
  - 选择在全部 description 之间进行：某技能的词与相邻技能重叠越多，无关
    任务越容易按表面相似选中它——宽泛词的成本不只属于自己，还抬高相邻
    技能的误选率。
- 触发成败由词的性质决定，不由长度决定：方法论名词堆成的极短 description
  会漏触发，触发者自然语言写成的较长 description 触发良好。判断单位是词
  的性质，不是总长度。

## 逐词判断：正匹配信号 vs 遮蔽源

写 description 时对每个词问：它是正匹配信号，还是遮蔽源？

- **正匹配信号**（保留）：帮助正确技能被命中——删它才伤匹配，是唯一有
  退化风险的方向。
- **遮蔽源**（收敛）：看似扩大命中面、实际增加与相邻技能重叠——删它降
  误选、省常驻成本，是安全收益。
- **纯方法论词**（移入正文）：既不贴近用户说法也无区分价值，不占匹配面。

信号类（保留）：

- **核心名中英双面**：用户可能用中文名或英文名指代技能，双名各占一条匹配
  通道；缺一面，该语言侧的触发路径失明。
- **贴用户说法的触发动词**：用户首话怎么说、agent 自问怎么说，description
  就怎么写——口语化的职责动词与语义判断的相关性最高。
- **when-to-use 一句自然措辞**：让模型判断「当前任务正落在本技能的场景」。

遮蔽源类（收敛）：

- **宽泛适用面声明**（「任何 X 场景均可」）：与相邻技能大面积重叠。
- **方法论名词**（阶段名、框架名、流程行话）：用户不这么说话，相邻技能
  往往也这么宣称——只有遮蔽贡献，没有命中贡献。
- **触发词穷举**：罗列几十个近义动词，边际命中收益趋零，叠加重叠与常驻
  成本。

安全边界：退化风险只存在于删正匹配信号，删宽泛面是安全的；拿不准一个词
属于哪类，问「用户或 agent 会自然说出它吗」。

## 两条触发路径

- 命中来自两条路径，description 必须同时给两条留信号：
  - **用户路径**：用户首话直接提需求——点名技能、说出职责动词、描述场景。
    措辞贴近用户的自然说法。
  - **agent 路径**：agent 执行中自问「现在该不该动用某类职责」，典型是
    交付物完成后的自我检查。措辞贴近 agent 面对状态时的自问句。
- 只覆盖一条是常见的漏触发形态：触发场景全以「做完 X 之后」开头，agent
  交付后的自问就无词可呼应。

## 反向条件最小化

- 不触发条件对命中面没有贡献还有反作用：核心词出现在「何时不使用」的
  语境里，语义命中也会被带偏判负——把技能名写进反向句，等于亲手把命中
  信号变成拒绝信号。
- description 里至多保留一句反向条件，选最关键的单一误触发场景；完整的
  合触发/不合触发/边界判定放 SKILL.md 正文——命中后才加载，不占匹配面。

## 不误指向

- 不指向不存在的独立技能：references 下的文件不是技能，不能被加载器加载。
  写成「详见 XX 技能」，agent 会去找另一个技能而漏触发本技能——反向误导。
- 给读者指路时，给同一技能内的正文位置或功能描述。
- 同一原则的延伸：description 声明的能力必须是技能真实提供的。命中后
  兑现不了的声明，与遮蔽同一种病。

## 与 SKILL.md 的分工

- description 是匹配面，SKILL.md 正文是决策依据：前者常驻、短、只放命中
  所需（做什么、何时用、必要时一句反向）；后者命中后全量加载，承载展开
  的触发判定、能力边界与路由。
- description 被命中后也会被当作简介读一遍，保留一句自然的「是什么」兼顾
  可读；与匹配冲突时匹配优先。
- 检验判据：对 description 每个词问「命中之后这句话还有用吗」，对 SKILL.md
  每句话问「不命中时它会被读吗」——边界由此可机械地扫出来。
- 命名是披露的第三面：目录名、`name` 字段与正文称呼共用同一个核心名；
  改名要三处同步且动摇用户习惯，涟漪比任何正文编辑都大——把命名当作身份
  决定处理，先于 description 措辞稳定下来。
