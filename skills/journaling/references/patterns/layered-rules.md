# 分层规则设计模式

> 一种规则设计的设计模式：规则内容分层——RULES 承载无条件遵循的规则，条件性遵循的规则分入独立文件，按需加载。避免每次全量加载，降低写入时的规则加载负担。

## 核心方法

- RULES 仍为笔记库规则的承载。
- 条件性遵循的规则内容分入规则子集——一套记述按需加载规则指令的独立文件。
- 子集在设计时明确其适用加载条件，RULES 的引用处说明该条件，条件命中时才加载对应子集。

## 规则的条件性

- 规则子集可以是某类规则中的一部分（分类规则中「知识类的细分」），也可以是某种条件下的一类规则（归档补充规则）。
- 但它们一定是**条件性遵循**的——无条件遵循的规则没有必要外置文件。
- 子规则文件的命名和组织方式不限定，由笔记库按自身情况自行设计。

## 一种可能的做法

这是一种做法参考，不直接照搬，按笔记库自身情况调整。

RULES 中：

```
## 分类规则

- 经验类放入 `经验` 目录
- 知识类放入 `知识` 目录，另外遵循[知识类笔记的细分规则](rules/knowledge-subclass.md)

## 归档规则

归档时遵循 [归档补充规则](rules/archive-rules.md)。
```

`rules/knowledge-subclass.md` 中：

```
知识类笔记的细分：
- 概念类放入 `概念` 目录
- 教程类放入 `教程` 目录
```

`rules/archive-rules.md` 中：

```
归档时：
- 先登记归档理由
- 移入 `archive/` 对应分类
```
