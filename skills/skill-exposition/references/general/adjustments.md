# 边界情况调整

> 输入特殊时，通用论述的方法不变，应用方式需要调整。以下逐条给出：**情况 → 调整建议 → 理由**。遇到对应情况再查阅，不构成流程。

## 技能没有 references/

- **调整建议**：梳理范围收缩为技能包中实际存在的文件（SKILL.md 及其余部分）；说明文不设"参考资料"相关内容，也不为缺失的参考层编造内容。若学习者可能期待扩展阅读，可在说明文中如实说明该技能无参考资料。
- **理由**：references/ 是辅助材料，缺失不影响 SKILL.md 主体内容的阐述；为缺失内容编造或补写 = 添加源里没有的内容（内容失真）。

## 技能没有示例内容（无 examples/ 且 SKILL.md 中无可提取示例）

- **调整建议**：说明文的"怎么用"环节以流程与规则描述为主；不虚构示例。可在说明文中说明该技能未提供内置示例。
- **理由**：示例缺失是源的事实；虚构示例 = 添加源里没有的内容。示例的作用（让抽象规则可感）可用真实的流程描述部分替代，但替代物必须全部来自源。

## 技能极短（说明文可以很短）

- **调整建议**：产出与源厚度相称的短说明文——完整呈现其简短内容，不为"看起来完整"注水；可补的"为什么"按推断纪律标注补充，但补充不为凑篇幅。
- **理由**：篇幅是内容的函数；说明文的长度应反映技能本身的厚度。忠实性约束的是"内容一个不丢"，不是"篇幅达到某长度"。

## 仅有 templates/ 而无 references/

- **调整建议**：梳理时把 templates/ 纳入范围（模板承载技能内容）；说明文中模板相关内容与流程描述就近组织——说明模板的用途、使用场景与关键参数。
- **理由**：模板是可复用结构的载体，是技能内容的组成部分；references/ 缺失不构成遗漏模板的理由（通用论述 2.2：定位分布需覆盖全部可能承载内容的文件）。

## 无 CHANGELOG / metadata（版本信息不可用）

- **调整建议**：版本、作者、历史信息在说明文中标注"不可用"或省略；不从正文推断版本与作者。
- **理由**：版本信息是元数据事实，推断 = 失真。说明文主体（定位、能力、规则、理由）不受影响，缺失的只是元数据层。

## references/ 极多（是否需要分篇）

- **调整建议**：输出形态仍是单篇说明文（逻辑整体）。references/ 极多时，先按通用论述完成全量梳理，再评估篇幅：篇幅过大可拆为章节文件，保持单篇逻辑整体。拆分依据是内容组织轴（如按能力域、按知识类型），不是按源文件一一对应。
- **理由**：交付物形态由"输入范围 → 输出形态"决定（通用论述 §1），与源文件数量无关；按源文件复刻目录结构是把"单篇逻辑整体"做成了目录镜像，且不利于按学习路径组织。

## 用户只指定方面（范围小）

- **调整建议**：范围即用户指定方面。梳理时先在该技能源中定位该方面涉及的全部位置（一个方面可能跨多个文件），只提取范围内内容；说明文只呈现该方面，不展开其他方面。
- **理由**：输入范围由用户指定、不假定完整技能（通用论述 2.1）；范围外的内容不属于本次交付物，不提取不是省略。

## 源语言与学习者语言差异大

- **调整建议**：全文用学习者语言；术语首次出现附源语言原文；差异极大时可附术语对照表。切忌只意译不注原文（术语失去与源术语的对应）或只留原文不译（学习者读不懂）。
- **理由**：语言与学习者一致是硬性要求（通用论述 §1）；术语附原文为防止翻译失真，保证读者能把说明文中的概念对应回源技能。
