# 组织一批问题

一份问卷由若干道题组成，每道题自带论述。进卷之前先分拣，再决定每题写什么、题与题怎么排。

## 先分拣：这题该问谁

只有用户裁决物进卷，这条界限本身在技能入口写着；到了具体一堆问题面前，麻烦的是认不出哪条属于它。

一个当场能用的判据：假设用户回一句「都行」，我的下一步动作会不会变？不变，就不是裁决，别用它占用户的注意力。能查证的先查证——查证本来就不该花用户的时间。

只有一个候选的题，往往是这个症状的外显：答案已经在提问这一侧定型，用户能做的只是追认。

## 什么算已经定下

讨论里已经拍板的点不重问，写进卷首一次，当作全卷前提，题目里不再复述。

关键是「已定」指用户表过态。你自己或用别的 agent 推出来的结论不算：要么标成推定请用户推翻，要么立成一道题。把这一侧的共识当定案，用户就失去了推翻它的机会。

## 论述要写足，别搬运原文

问卷的价值有一半在这里：把作出裁决所需的背景一次带到用户面前，他不必为答一句话再问三轮。每题之前至少交代四件事——这是什么、为什么现在要定、每条路的代价落在哪儿、为什么这一条不能由自己定。写清楚比写短重要。

自检：把这一题的论述、题面、选项单拎出来，没看过这段对话的人能作答吗？

要砍的是两样。一是没消化的原文：贴一整段讨论记录，等于让用户替你读完再替你判断，问卷从「请裁决」退化成「请做我的工作」。二是与题面重复的表述：题面已经问过的话，论述里再说一遍，是让他把同一段读两次。

## 每题自成一体

用户在页面上线性往下读，回翻要么重新滚上去，要么靠记忆。所以每题写完自问：只读这一题，能被解码吗？

- 指代写实：不写「上面那个方案」「前一个选项」，写清它是什么。
- 同一前提不逐题复述：卷首写一次，题内向它指一句，比每题讲一遍更省用户的时间，也比让他自己记住更稳。
- 题与题之间若真有关联（后一题的选项取决于前一题的选择），在论述里说明这层关系，别让他答到一半才发现。

## 依赖链拆批

某个问题的答案会改变后续问题的题目本身时，后续问题等这一批收回再出。硬写进去，就是预设一个答案去编题面——用户选了别的，那一题连题面带选项一起作废，而他没法在答卷里替你改题。

拆出的后一批，卷首带上前一批的定案，省得新问题再解释一遍前提。

## 篇幅

题数由待决点决定，不由「一次问完」的愿望决定：为了少开一次问卷，把还没成形的问题也塞进来，用户要为一堆半成品花时间。反过来，题数多不是问题——只要每道题都自带论述。

卷首的已定事项、题目之间的导航都是可选项，按卷子的长度取用。篇幅服务的是「用户读完就能答」，不是结构完整。
