# 写入口文件

**入口文件**（`SKILL.md`）是技能里唯一必须存在的那个文件：加载器靠它的 frontmatter 认出技能，读者靠它的正文决定去哪。这一册讲这个文件怎么组织、怎么写，包括它 frontmatter 里的 `description` 怎么定稿。

一句内容该不该留在入口文件（而不是下沉到支撑文件），判据在[组织一个技能的结构](../general/standards.md)的分层节；`description` 里某个词该留该删的判据，在[让技能被正确命中](../general/disclosure.md)。本册讲怎么把这些落到文件上。

## 它只承担三件事

- **被加载器命中** —— frontmatter 的 `description` 提供语义匹配面（判据见披露册）。
- **触发决策** —— 读者加载后判断这次该不该启动、走哪条路。
- **路由引导** —— 指向真正的主内容：主干方法文档，以及按需查阅的各册。
- 完整的方法论述、执行流程细节、检查清单展开都不在这里，进支撑文件按需加载。理由不是「简短更好」，是成本结构：入口文件是唯一每次命中都被全额支付的文件，其余文件不读不花。

## 前提：读完这一段就能开工

- 所有支撑文件共享的背景放在入口，读者不必先读别的地方才知道这个技能在说什么。写这段的方法是**枚举各册假设读者已经知道什么，取交集**——交集里的东西才是共享前提，交集之外的留在各自那一册里，不必上移。
- 前提写结论，不写论证。论证属于提出它的那一册；入口把结论摆出来，读者据此判断要不要往下读。写论证会让入口变成各册的摘要，两处从此开始漂移。
- 自检：把前提节删掉，各册会不会出现读者读不懂的跳跃？不会，说明前提里混进了只服务某一册的内容。

## 路由：按读者手里有什么

- 路由的分组轴是**读者手里有什么、缺什么**，不是「本技能有哪几类工作」。按工作类型组织的路由，读者得先把自己的处境翻译成某个工作类型才能用；按情形组织的路由，读者直接拿自己的处境去对。
- 每条路由给三样东西：什么情形下走这条（触发条件）、去哪一册（目标）、去了能拿到什么（内容预告）。缺第一样读者不知道与自己有没有关系，缺第三样不知道值不值得中断当前思路——措辞细节见[编写手艺](writing-craft.md)。
- 入口的完整性按**读者的入口方式**清点，不按文件清点。除了「我要设计 / 修改一个技能」这类按工作进来的，还要覆盖两类：按内容形态进来的（「我要写个脚本 / 一份模板」），以及手里有东西但说不清要干嘛的（读完要能自己判断该走哪条）。漏掉后两类，他们只能扫全表碰运气。
- 路由里的每条指针都指向真实存在的目标位置。断链是静默的——技能照常加载，内容取不到，没有任何报错。

## 索引与路由，一份文件只出现一次

- 入口里每个支撑文件只应在一处带链接出现。路由列过一遍、下面再列一遍完整清单，读者读到的是同一批链接的第二遍（重复披露是净损失），而且两处会各自漂移——改了路由忘了索引，索引就成了过时的地图。
- 想要「给读者一个全貌」时，把路由本身按读者情形分好组就够了：分组的路由既是选择路径也是全貌。确有路由没覆盖到的文件（例如只在特殊情形才用的），作为路由的一节补在末尾，不另起一份清单。
- 目录树不是索引的替代品。用代码块画的树不可点达，与本技能自己立的「引用即加载路径」相矛盾；要画树就给每个条目加链接，或直接不画。

## 不触发条件

- 不触发条件（什么时候不要用这个技能）放进正文，不进 `description`。机制在[披露册](../general/disclosure.md)：核心词出现在「不使用」的语境里，语义命中会被带偏判负，把技能名写进反向句等于把命中信号改成拒绝信号。
- 正文里写什么：读者在**加载之后**才需要判断的边界情形——例如「只想改错别字不算这类工作」「这类工作交给另一个技能」。这些判断在加载前用不上，进 `description` 只会占匹配面。
- 写法用正向陈述为主（目标行为是什么），不列成禁令清单。禁令让被禁行为更可及，且只划边界不给路，机制见[编写手艺](writing-craft.md)。

## description 定稿

- 成文顺序固定：**先写支撑文件，再写入口正文，最后写 `description`**。入口要指向真实存在、真实装着的内容；覆盖面确定之前写的 `description` 必然返工。
- 定稿走两轮，顺序不能反——**先扩命中面，再删遮蔽源**：先补齐缺失的语言侧与触发路径，回归确认命中后再逐词收敛宽泛词与方法论名词。反过来先精简，会把信号和噪声一起删掉，且删完无法判断损失在哪。
- 回归的可用下界是**子串模拟**：拿一批应命中的用户语句，检查它们与 `description` 命中词的交集。语义模型无法直接调来问「你会不会触发」，这个模拟的命中是充分性不足的证据（有假阳性：句子恰好含载体词却缺动词；也有假阴性：表述变体不在清单内），最终判定看**触发动词是否出现**，不看子串集合大小。
- 用例双向组织，每轮修订都跑一遍：应命中（核心名中英双 + 用户提问动词中英双 + agent 自问句 + 载体词）与不应命中（仅改错别字、纯格式化、相邻技能的主场话题）各一批。只准备应命中的用例，等于只测了召回没测误选。
- 改 `description` 之前先过一遍披露册的逐词判据；改完跑回归。压长度本身不是目标——测过 262 字符的版本在英文诉求下被相邻技能抢走了位次，精准比短重要。

## 完成判据

- 读者（零上下文）读完入口，能不读支撑文件就说出这次该进哪一册。
- 每个支撑文件在入口里有且仅有一条可达指针，指向真实存在的位置。
- 两类入口方式（按工作进来、按内容形态进来）都有对应路由，说不清要干嘛的读者读完能自己判断。
- `description` 两条触发路径都有词汇面，反向条件至多一条，且核心名中英双面都在。
