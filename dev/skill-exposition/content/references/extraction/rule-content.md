# 规则/决策型内容的提取提醒

> 梳理时遇到规则/条件/阈值类内容时按需加载。本文只讲「怎么提取不失真」；怎么写进说明文由你自行发挥（行文见 general/readability.md）。

## 这是什么

**定义**：技能中「什么情况下做什么/不做什么」的内容——约束、条件、阈值、例外、决策规则。

**识别线索**（读到以下任一即属此类内容）：

- 「必须/不得/应当/禁止/仅当/除非」
- 「当 X 时」「如果…则…」
- 数字阈值（行数、字数、百分比、时间）
- 决策表（条件 → 动作）
- 「例外」「兜底」「默认」
- 边界声明（「不适用于…」「仅适用于…」）

规则是技能中「可执行性」最强的部分，也是最容易在转述中受损的部分：数字被软化、条件被简化、例外被省略，都会让学习者得到一条与源不同的规则。

## 提取注意点

1. **阈值与数字原样保真**。
   注意：数字、单位、比较方向（大于/大于等于/小于）一字不改——不四舍五入、不改写单位（「5000 行」不写成「约五千行」，「5 分钟」不写成「几分钟」）。
   为什么：阈值是规则的可执行部分，改动数字 = 规则改变；这是内容失真的典型表现（见 exposition-guide.md 3.1）。

2. **条件完整，含 else/兜底分支**。
   注意：「如果 X 则 A，否则 B」的否则分支、「不满足任何条件时默认…」的默认行为都要提取。
   为什么：兜底分支定义规则覆盖不到的输入怎么办，丢兜底 = 学习者遇到未命中情况时无从下手。

3. **例外情况原样保留**。
   注意：规则主体的例外（「除非…」「X 情况除外」）不因「太琐碎」省略。
   为什么：例外是规则的一部分，省略例外 = 规则被写得更宽，学习者会误用。

4. **规则适用对象写清楚**。
   注意：谁被规则约束——作用于哪种输入、哪个环节、哪个角色（「该约束适用于所有输出文件」「仅对超过 400 行的文件生效」）。
   为什么：适用对象决定规则的作用域，丢了对象 = 规则被泛化或错位。

5. **规则语气词是强度标记，原样保留**。
   注意：必须/不得/应当/可以之间的区别保留，不统一改写。
   为什么：语气词标记规则的强制程度——把「禁止 X」弱化成「应避免 X」，规则的边界就变了。

6. **规则层级保留**。
   注意：主规则与子规则、规则与约束的从属关系原样保留。
   为什么：层级关系帮助学习者判断规则冲突时谁优先。

7. **触发条件与约束分离**。
   注意：「何时该用这个技能」（触发）与「使用中必须遵守什么」（约束）是两类内容，提取时保持区分。
   为什么：混淆两者会让学习者把「是否该用」与「如何用」混为一谈。

8. **决策表逐行保真**。
   注意：条件 → 动作表每一行都提取，条件列与动作列都不丢行；数值型条件（「文件 > 500 行」）原样。
   为什么：决策表的一行就是一条规则，丢行 = 丢规则。

9. **规则与理由分离记录**。
   注意：把「规则本身」与「规则旁的理由注释」分开记；理由归 rationale-content.md 处理。
   为什么：防止把理由写成规则，让学习者把背景当约束执行。

## 常见失误

- **反例 1**：源里「超过 500 行则警告」，说明文写成「文件较大时警告」——阈值被模糊化。
- **反例 2**：源里「条件满足时执行 A，否则执行 B」，说明文只写了 A 分支，兜底丢失。
- **反例 3**：「所有规则在 X 例外下不适用」中的例外被省略，规则被写宽。
- **反例 4**：源里「该阈值仅对输出文件生效」，说明文没写适用对象，学习者以为对输入文件同样生效。

## 自查提示

- 每个数字（阈值、时间、比例）与源逐字一致吗？单位、比较符号、约等都没有改动吗？
- 每条「如果…则…」都检查过是否有否则/兜底分支吗？
- 每条规则都写清了约束对象（谁/什么被约束）吗？
- 例外是作为规则正文的一部分保留的吗？
- 规则的强制语气（必须/不得/可以）与源一致吗？
