# 文档/指南质量验证推演
> 场景文档 — 配合推演通用论述（`../rehearsal-guide.md`）参考使用，补充文档/指南载体的特化内容。

将推演方法应用于文档/指南写作的质量验证。适用于：
- 写作者完成单篇文档后的自我验证（单文档推演）
- 一个文档库全部完成后的全流程跨文档推演（全流程推演）

---

## 单文档推演

### 读者定位（P2 身份设定的要点）

目标读者（预期的接收方）。已知工作上下文，但**从未读过刚写的这份文档**。目标是"读完后知道怎么执行对应工作"。

初始状态：
- 知道有相关参考文档但没读过
- 知道有上下游模块但没看过它们的文档
- 目标是"执行本文描述的工作"

### 模拟阅读的特有信号（P3 补充）

按阅读顺序逐段走，记录心理反应：

| 反应 | 含义 |
|------|------|
| "这里停住了" | 信息密度过高 / 措辞模糊 / 跳过了必要前置 |
| "这里不知道做什么" | 缺少明确可执行的下一步 |
| "这里跳过去了" | 结构没抓住注意力，重要的东西被埋没 |
| "这里误解了" | 措辞有歧义，可能被理解为错误的意思 |
| "这里需要回头看" | 引用了还没定义的概念或术语 |

### 边界与异常场景（P4 补充）

| 场景 | 检查目标 |
|------|---------|
| 信息缺失 | 读者没读引用的参考文档，这篇文档还站得住吗？ |
| 错误输入 | 读者误解了一条关键指令，会走到什么死路？ |
| 跨模块跳转 | 读者从上个模块跳过来，期望的输入和本文档的起点匹配吗？ |
| 边界变化 | 极简/极繁输入、大量分支、不确定步骤下，文档的指引还成立吗？ |
| 元语境渗漏（身份边界错位） | 文档是否混入了写作约束、开发侧知识、作者的声音（如"本文不出现 XXX"被写成正文）？ |

### 评估整理（P5 的要点）

**严重程度格式：** 阻塞/缺陷/建议。三级定义：

- **阻塞**：读者无法完成目标（如关键步骤缺失）
- **缺陷**：读者能走完但质量受影响（如引导不足）
- **建议**：可读性或措辞改进

**评估维度提示（额外提示，非硬性指标）：**

| 评估维度 | 含义 |
|------|------|
| 入口明确性 | 读完标题/首段，知道该不该继续读 / 从哪里开始 |
| 步骤可跟踪性 | 每一步都有明确可执行的行动，不是抽象原则 |
| 术语全局统一 | 术语与其他文档一致（依 P1S1 阅读范围大于推演范围，以衔接带材料核对——只读不推演） |
| 缺失场景覆盖 | 边界情况、异常路径有覆盖 |
| 独立性 | 虽然引用但不依赖，能独立指导执行 |

**复现对照注意（P5S1）：** 回到 P1S3 整理的作者意图（编写时的理解），将模拟读者的复现理解按四向（劣化/偏差/过度/重复）对照。

发现的记录要素与缺陷类型标注见通用论述 P5S2，覆盖检查见 P5S4。

**错误模式搜索候选（P5S5）：**

- **路径末端无收束** — 提供信息后忘记给出「下一步做什么」的引导
- **隐含前置知识假设** — 文档假设读者已知某些概念但未定义
- **术语全局不统一** — 同一概念在不同文档中用了不同名字

## 全流程跨文档推演

文档库全部完成后，对整个文档库做一次完整的端到端推演。

### 与知识库推演（[knowledge-base-rehearsal.md](knowledge-base-rehearsal.md)）的区别

两者都涉及多文件推演，但载体形态不同：

| | 文档库（本文档） | 知识库 |
|---|---|---|
| 范畴 | 通常针对**单一对象或范畴**（如项目文档库、技术方案） | 通常包含**多种不同范畴**的知识和实体 |
| 关联方式 | **树状且有序**——按工作流程的天然顺序消费（决定性判据） | **网状关联**——按决策树分支选择路径（决定性判据） |

推演前先确认载体形态（以关联方式为决定性判据）：文档库按本文档的全流程方法；知识库（多范畴、网状、决策树入口）用知识库推演。

### 读者定位（P2 身份设定的要点）

读者是从零开始接手一个完整项目的执行者。已知各模块的定义，但从未实际操作过。

载体是全部相关文档（通用指南 + 各模块特定文档）；消费顺序按工作流程的天然顺序：起点的模块 → 下一站 → 直到终点（对应 P1S1 的载体范围与衔接带）。

### 逐模块推演（P3 的执行方式）

模拟读者逐个模块的工作流。在每个模块转换点推演：

```
模块 A → 模块 B：
 - 模块 A 的输出是否在模块 B 的文档中被引用为输入？
 - 关键术语在两个模块中是否一致？
 - 完成模块 A 后读者自然能知道下一步去模块 B 的哪个文件吗？
```

### 边界与异常场景（P4 补充）

| 异常场景 | 检查目标 |
|---------|---------|
| 跳过某模块直接进入下一站 | 文档是否提供必要的上下文或警告？ |
| 只读了通用指南没读模块指南 | 通用指南是否足够支撑执行？ |
| 两个模块对同一概念的不同表述 | 有没有矛盾？需不需要统一？ |
| 项目规模/参数超出标准范围 | 各文档是否覆盖了变体情况？ |

### 评估整理（P5 的要点）

**严重程度格式：** 阻塞/缺陷/建议。三级定义见单文档推演。

**评估维度提示（额外提示，非硬性指标）：**

| 评估维度 | 含义 |
|------|------|
| 全流程可执行性 | 从起点到终点，按文档走能完整走通吗？ |
| 模块流转清晰度 | 每个模块的输出/输入契约清晰吗？ |
| 术语全局统一 | 关键术语在所有文档中一致吗？ |
| 覆盖完整性 | 全部工作内容被覆盖了？ |
| 异常容错 | 跳步、逆行、跨读时能 recover 吗？ |
| 引用完整性 | 所有相对链接指向真实文件 |
| 独立可读性 | 每个文档自身站得住 |

**复现对照注意（P5S1）：** 回到 P1S3 整理的全流程作者意图（编写时的理解），按四向对照复现理解。发现的记录要素与缺陷类型标注见通用论述 P5S2，覆盖检查见 P5S4。

**错误模式搜索候选（P5S5）：**

- **模块流转契约缺失** — 模块 A 的输出未在模块 B 的输入中被引用
- **术语全局不统一** — 关键术语在多个文档中表述不一致
- **跳步无恢复指引** — 跳过某模块后文档未提供必要的上下文

## 常见问题

**Q: 单文档推演是写完后做，还是写作过程中做？**
两者都做但目的不同：写作过程中可以分段推演（通用论述「执行策略」的嵌入优于收网——每完成一段做一次短推演，缺陷发现得越早修复成本越低）；最终的全景推演需要完整载体——跨模块交互问题往往只在完整载体上才能暴露。

**Q: 全流程推演发现很多问题怎么办？**
按影响范围排序：先修导致卡死点的（全流程可执行性阻塞），再修一致性/覆盖性问题，最后修引用和可读性问题。
