# skill-master Specification

## Purpose

本域是技能工作元技能 skill-master：对象是一个技能的全部工作——从值不值得做、怎么组织怎么写、为什么行为不对、够不够好、别人能不能用起来，到该不该改与怎么改。定位由名字界定，不由清单界定：边界只划在**对象**上——对象不是技能的事不归本域；凡是技能的事，不因为尚未写到就划出去。已成文的论述是当前覆盖范围，不是能力边界。

技能的工作有两类委托方：**制作侧**（把它做出来、修好、审对、验能用）与**使用侧**（决定用不用、选哪个、刚用完回顾）。本技能让零上下文 agent 独立走完技能工作的全程。性格是**指导支持而非规范限制**：以要点提示为主、辅以简单推荐流程、给足发挥空间。

## Requirements

### Requirement: 工作域与立场分界
技能工作分两组：制作侧——接下来要改它的工作（设计、修改、审查、快速测试）；使用侧——要用它或刚用过它的工作（预评估、后评估）。分界由委托方立场判定，两侧判据同源（内容四判据：有用、全面、准确、清晰）。各项工作的职责见各自条目。

#### Scenario: 立场判归属
- GIVEN 维护者要找出技能哪里不对、与使用者评估未用过的技能两个请求
- WHEN 判定工作归属
- THEN 前者是审查（制作侧），后者是预评估（使用侧），不互指

### Requirement: 设计
设计是从实践到技能的工作：判定值不值得做、为谁做什么、怎么组织怎么写、怎么交付。

#### Scenario: 设计先于成文
- GIVEN 一项「要不要为某实践沉淀一个技能」的判断请求
- WHEN 判定工作归属
- THEN 属于设计工作——从实践到技能的起点判断

### Requirement: 修改
修改是结构内的改动：判定该不该改与怎么改；改动沿引用链传播，修改一处时评估其引用与被引用位置的连带影响。

#### Scenario: 改动沿引用链传播
- GIVEN 对某技能一处内容发起修改
- WHEN 执行修改
- THEN 评估该改动沿引用链的传播范围，不孤立看待被改位置

### Requirement: 审查
审查判定「写得对不对、说的和做的是不是一回事」，主线是三源交叉比对——设计文档、技能正文、支撑论述互为基准，锚点不自动豁免：锚点内部不一致时先报出、再作基准。症状排查是审查的第二进入方式：从「行为与预期不符」沿触发链倒推，产出定位并转修改。审查与修改是两种注意模式而非固定工序链，审查可在任何时点切入。审查的执行固化为委派，委派契约要求执行者写明「明知该查而没查的是哪几类」；机械项（合规判据）依赖环境规则而环境不明时标「待核实」进入清单，不降级放掉也不硬判。审查册的病灶七类保持为病灶分类（根因定性——判别问句 + 指回权威册的指针），不作为逐项扫描检查项使用。

#### Scenario: 症状排查转修改
- GIVEN 某技能行为与预期不符，沿触发链倒推到根因
- WHEN 输出排查结果
- THEN 产出定位清单并转为修改工作，排查不自行修复

#### Scenario: 病灶不作扫描清单
- GIVEN 审查册的病灶七类
- WHEN 使用它们
- THEN 在比对发现不一致之后归类根因，不拿着七类逐项扫描

### Requirement: 快速测试
快速测试判定「零上下文 agent 能不能理解、走通、用起来」，以推演方式进行，不实际执行被测技能；在技能生命周期中是独立环节——交付闸与修改后回归。快速测试册保持流程刚性：流程图、门禁、中止判据、报告格式是其硬约束。测试委派遵守隔离铁律：测试子代理不知道预期效果、其他测试单元的存在、baseline/实验组区分或任何对比信息。

#### Scenario: 测试子代理零预期
- GIVEN 快速测试的委派下发
- WHEN 检查子代理收到的内容
- THEN 不含预期效果、其他测试单元、分组区分或对比信息

### Requirement: 预评估
预评估凭手头证据给出可辩护的评估结论，供采纳决定作输入；不判定技能的实际覆盖面。评估与解读分离：怎么解读结果、采纳与否不进入评估指导。某评估方向信息不足时，如实记录缺失是预期行为，不是缺陷。

#### Scenario: 评估不越界到解读
- GIVEN 预评估产出了评估结论
- WHEN 检查产出
- THEN 结论含理由，但不包含「所以你该不该用」的采纳决定

### Requirement: 后评估
后评估产出洞察记录（什么真的有效、什么不足或错、想改什么——到「缺什么」为止），每条洞察带本次实证，印象式结论不记入；实际执行形态照实记，偏离指引是信号不是过错。后评估不委派——证据在使用者的经历里，委派即丢失；翻检问句是入手角度，不升格为逐项工序。

#### Scenario: 洞察带实证
- GIVEN 后评估记录的一条洞察
- WHEN 检查其依据
- THEN 关联到本次使用中实际发生的事件，无实证的印象式结论不记录

### Requirement: references 组织与命名
支撑文档按内容性质分三个次级目录：documents/（文本类编写方法）、scripts/（脚本编写方法）、general/（跨类通用册）；快速测试方法细则按工作名分组进 quick-test/，不属内容性质轴。打包/编写分离：内容被打包到目标技能的静态资源不改变其编写论述的归属。文档形态收敛为三：知识（静态客观资料，是查的不是读的）、工作流（照着走）、论述（读了懂自己发挥）；提示是论述的笔法，不作为独立形态。编写手艺（craft）随服务对象走：writing-craft 归 documents/、scripting-craft 归 scripts/。分册命名区分文档身份：工作论述带 skill- 前缀、craft 以 *-craft 命名、论述与规范册用职能名。扩展在既有次级目录内进行，不为单册设顶层目录；新文档形态出现时先有内容、再定分组，不预造框架。

#### Scenario: 命名模式区分文档身份
- GIVEN 新增一份工作论述或 craft 文档
- WHEN 检查文件名
- THEN 工作论述为 skill-<work>.md 形式，craft 为 <object>-craft.md 形式

### Requirement: 论述形态
工作论述以要点并列组织（每要点讲清是什么、为什么、给个具体场景），整体路径只轻轻带过，不设阶段门禁——仅内容本身是程序时才用流程形态。

#### Scenario: 要点论述无门禁
- GIVEN 某工作论述文档
- WHEN 检查其形态
- THEN 以要点并列组织，无阶段门禁；流程形态仅出现在内容本身是程序的文档（如快速测试册）

### Requirement: 措辞风格
正文用确定性陈述——不出现「待定 / 开放问题 / 将来可考虑」。术语以术语定义为单一权威，正文首次出现按需就地定义。开发讨论的速记/代号不进入正文。标题表述读者的工作（如「设计一个技能」），不宣布文件身份；宣布式开头（「本文档是……」「读者默认已读……」）不出现。写前推算读者的信息状态：按加载序列判断此位置读者已知什么，已披露不重述、未披露不依赖。

#### Scenario: 宣布式开头不出现
- GIVEN 任一论述文档的开头
- WHEN 检查首段
- THEN 直接进入读者的工作或判断内容，无「本文档是……」式自我定位

### Requirement: 术语表述——工作与论述组
术语统一指称，正文用词不漂移到禁用同义词：**工作 (Work)**（六类工作领域，分两组）——Avoid 任务、阶段、流程、验证；**论述 (Discourse)**（对一种工作或一类内容编写方法的完整知识呈现，要点提示形态）——Avoid 教程、手册、指南；**前提 (Premise)**（所有工作共享的背景判断）——Avoid 理念、原则；**症状排查**（审查的第二进入方式）——Avoid 调试；**病灶 (Defect class)**（根因定性的七个高发类别：转发、自违、占位、空转、悬空、断链、化石）——Avoid 维度；**审查 (Review)**——Avoid 走查；**快速测试 (quick test)**——Avoid 验证；**预评估 (pre-assessment)**——Avoid 审查、审计、评分、选购；**后评估 (post-assessment)**——Avoid 复盘、总结；**推演**（不实际执行被测技能的检验方式）——Avoid 实测、执行；**被测技能**（快速测试的对象）；**能力模拟**（推演中对外部能力的模拟执行与假设记录）；**推演中止**（同类系统性失败的判据）；**测试单元**（一次独立推演场景）与**触发测试单元**（测触发面语义匹配的盲测单元）；**隔离铁律**。「验证」不是术语——该词随其历史指代退出正文。

#### Scenario: 禁用同义词不出现
- GIVEN 技能正文与支撑文档
- WHEN 检查术语用词
- THEN 各概念用统一指称，未出现对应 Avoid 词指代该概念

### Requirement: 触发语义
触发面覆盖对象是技能的工作请求：制作侧（设计、修改、审查、快速测试）与使用侧（预评估、后评估），用户请求与 agent 自问两条路径都命中。反向条件：要求真实执行被测技能的测试类请求不触发本技能——本技能的快速测试是推演，不实际执行。description 不使用触发词穷举或 `Triggers:` 类结构化标签——穷举只贡献常驻成本与重叠面。

#### Scenario: 技能工作请求命中
- GIVEN 用户请求评估一个未用过的技能是否值得采纳
- WHEN 判定触发
- THEN 属使用侧工作，命中触发面

#### Scenario: 执行类测试请求不触发
- GIVEN 用户要求实际运行某技能验证其行为
- WHEN 判定触发
- THEN 不触发本技能——真实执行不在快速测试的推演范围内
