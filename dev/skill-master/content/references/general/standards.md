# 技能包的打包规范

## 定位

- 本册回答一个底线问题：技能包按什么格式打包，加载器与分发渠道才认。
  标准的规定不可协商——不满足就不是合法技能包；底线之上如何组织、如何
  写准，是各工作论述的发挥空间，本册不越界。
- 中立转述，只立基线：本册内容是外部开放标准（Open Agent Skills）的转述，
  不是本技能或本仓库的自创约定。仓库或运行环境若有追加约束，以各自规则
  为权威，与本册基线分开维护；一份技能包要同时满足两套约束，但两套各有
  出处。
- 打包与编写两轴正交：成品放哪个目录（本册）与按什么形态编写（documents/
  scripts/ 各册）是两回事。工作流文档即便打包成 asset，编写方法仍按工作流
  册——按打包位置找编写方法是常见错路。

## 目录结构

- 技能是一个目录，目录名与 frontmatter 的 `name` 字段一致，加载器按目录
  发现技能。最小合法结构只有一个文件：技能根的 `SKILL.md`。
- 标准允许的可选支撑目录：

| 目录 | 存放什么 | 标准要求 |
|---|---|---|
| `scripts/` | 可执行代码 | 自包含或显式写出依赖；含友好报错；优雅处理边界情形 |
| `references/` | 按需阅读的文档 | 每份聚焦单一主题、尽量小 |
| `assets/` | 静态资源（模板、图片、查表数据） | 供查阅的客观资料，不是主阅读路径 |

- `templates/`、`examples/` 等扩展目录不在标准统一清单里：环境不认识的
  目录名等于不存在，其内容永远不会被加载。先确认目标环境认哪些目录名，
  再谈内容归属。

## frontmatter 约束

SKILL.md 由 YAML frontmatter 与 Markdown 正文组成；标准只约束 frontmatter，
正文格式不受限制。

| 字段 | 必须 | 约束 |
|---|---|---|
| `name` | 是 | 1–64 字符；仅小写字母、数字、连字符；不得以连字符开头或结尾；不得含连续连字符；须等于父目录名 |
| `description` | 是 | 非空且不超过 1024 字符；同时说明技能做什么与何时用；含帮助匹配任务的触发词 |
| `license` | 否 | 许可证名，或对技能包内许可证文件的引用 |
| `compatibility` | 否 | 不超过 500 字符；环境需求（目标产品、系统包、网络等）；多数技能不需要 |
| `metadata` | 否 | 字符串键值映射；容纳标准未定义的附加属性（版本、作者等） |
| `allowed-tools` | 否 | 空格分隔的预批准工具列表；实验性，实现间支持度不一 |

- `name` 与目录名双向一致：技能名同时是加载器标识与用户称呼核心，改名
  牵动目录、字段与文档引用多处——技能交付后改名是结构性变更，命名在写
  description 之前定稳。
- `description` 的「含触发词」是字段层面要求；触发词怎么选是披露设计的
  方法论（见 [disclosure.md](disclosure.md)）——标准规定字段必须有什么，
  披露论述规定措辞怎么命中。
- 标准未定义的附加属性走 `metadata`；识别只看 `name` 与 `description`，
  加载器不依赖 metadata 做识别。

## 渐进式披露

标准按上下文成本把技能内容分成三层，组织必须与加载行为对齐：

1. **元数据层**：全部已发现技能的 `name` + `description` 在会话期常驻——
   匹配与选择只发生在这层。
2. **指令层**：技能被命中后，SKILL.md 正文一次性全量加载。
3. **资源层**：references/、scripts/、assets/ 等被链接的文件需要时才读。

- 三层成本形态不同：常驻层每个 token 全程付费，资源层只在真正需要时付费。
  组织方向：匹配信号留在元数据，决策依据放 SKILL.md，长论述后置到资源层。
- 规模指引（标准的建议而非硬限）：SKILL.md 正文不超过约 5000 tokens、500
  行；支撑文件每份聚焦单一主题、尽量小。
- 引用纪律：技能内引用一律从技能根用相对路径写；引用深度保持一层
  （SKILL.md → 支撑文件），避免深层引用链——每多一层链就多一次「要不要
  追读」的决策和一个断链点。

## 校验

- 结构合规是机械问题，可检查项三类：frontmatter 完整性（必填字段齐全、
  `name` 合规且与目录名一致）；引用无断链（正文指向技能内文件的相对路径
  目标确实存在）；目录合法（只出现标准允许或被目标环境识别的目录名）。
- 标准生态提供官方校验器，机械检查 frontmatter 合法性与命名约定——交付
  前跑机器校验，不靠自觉：设计过程靠判断，越接近交付越该让机器兜底。
- 断链的失效形态是静默的：技能被加载后，指向不存在文件的引用让该部分知识
  在需要时不可达，作者收不到任何报错信号——机器校验是交付前发现它的可靠
  手段。
