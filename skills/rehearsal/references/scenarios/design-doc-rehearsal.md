# 设计方法论文档推演
> 场景文档 — 配合推演通用论述（`../rehearsal-guide.md`）参考使用，补充设计方法论文档载体的特化内容。

将推演方法应用于**设计方法论文档**的质量验证。这类文档的读者是执行设计任务的接收方（如 AI 模型在设计阶段按方法论执行），不是人类终端用户。

以下各节按推演时的关注点组织，各节标注了对应的通用论述步骤。

## 本载体的核心差异

| 普通操作文档 | 设计方法论文档 |
|----------------|--------------|
| 读完后执行任务 | 读完后按方法论设计 |
| 验证"步骤是否可跟踪" | 验证"逻辑是否在不同输入形态下成立" |
| 单链路走通即可 | 需验证多场景推演完整性 |
| 关注操作正确性 | 关注逻辑正确、线索清晰、前后一致、可复现深刻理解 |

因此本载体的推演重心不在"读者能否跟上步骤"，而在"方法论在不同输入形态下是否始终成立"。

## 读者定位（P2 身份设定的要点）

执行设计任务的接收方，已知工作上下文（项目结构、依赖关系），但**从未读过这份方法论文档**。目标是"读完这份文档后，按其中流程完成一个设计任务"。

初始状态：
- 知道有相关参考文件存在但没读过
- 理解该领域设计的一般概念
- 已通过需求锚定阶段（前置阶段已完成，不在本载体推演范围）

P2 身份转换时特别需要划掉的方法论作者知识：不知道某个步骤为什么这样设计、不知道设计中舍弃了哪些替代方案、不知道哪些约束是后来追加的。

## 四维验证框架

推演设计方法论文档时，评估维度提示（额外提示，非硬性指标）：

| 维度 | 自问 | 典型缺陷 |
|------|------|---------|
| **逻辑正确** | 序列是否自洽？不同场景下方法论的判决是否一致？ | 步骤顺序颠倒、条件互斥失效、范围声明与实际覆盖矛盾 |
| **线索清晰** | 读者能否理解每一节为什么存在、如何衔接到下一节？ | 节间跳跃无过渡、流程图与实际节序不符、引用与引用主题松散 |
| **前后一致** | 前文的承诺在后文是否兑现？数字约束是否自相矛盾？ | 产出表漏列阶段、阈值数字前后不对应、陷阱表与流程表不对齐 |
| **可复现深刻理解** | 读者再次阅读时能否复现设计意图？关键决策的"为什么"是否显式写出来了？ | 只是"这样做"缺"为什么这样做"、强制性步骤缺后果说明、约束收集漏了重要隐性规则 |

其中「可复现深刻理解」是通用论述总目标**准确复现**（读者复现的理解与编写时的理解相同）在本载体的具体化检查项——它不是一套独立的目标，而是"准确复现"落到设计方法论文档时最需要检查的侧面：方法论文档的价值恰恰在于让读者复现设计者的判断逻辑，而不仅是执行步骤。

## 边界与异常场景（P4 补充）

P4 推演过程回顾中，选取**载体自身可预料的合理变化**场景（通用论述 P4 的主动尝试边界/极端条件在本载体的场景库）——每个场景必须在方法论声称的处理范围内，上游阶段已保证的条件不需要专门测试：

| 场景类型 | 测试目标 | 示例 |
|---------|---------|------|
| 极简输入 | 方法论对极简情况是否过重？ | 2-3 步就能完成的任务，流程是否产生不必要的子节？ |
| 极繁输入 | 方法论的阈值和上限是否起作用？ | 30+ 步的任务，分层/拆分阈值是否触发正确？ |
| 极端分支 | 分支宽度限制是否有效？路由表引导是否充足？ | 10+ 路分支，是否触发路由表设计？ |
| 范围边界 | 入口条件是否能正确拦截不该进来的场景？ | 探索/诊断型流程，是否在入口被拦截？ |
| 并行复杂度 | 优化阶段的约束是否防止过度并行？ | 10+ 可并行步骤，是否触发简化建议？ |
| 不确定输入 | 步骤的输入形态不确定时，方法论是否给出处理依据？ | 上一步输出可能缺失/畸形——是否有明确的状态检查或降级路径？ |

## 交叉引用验证（本载体特有留意点）

设计方法论文档通常引用大量参考文件。推演时（P1S1 阅读范围覆盖衔接带的基础上）额外检查：

1. **存在性检查**：每条引用指向的文件真实存在
2. **方向一致性**：引用的文件主题与引用处的上下文一致（方向不能相反）
3. **完备性扫描**：引用是否有明显盲区——某节应该引用但没引用的文件

## 模拟阅读的要点（P3 补充）

对每个边界场景，按方法论逐节走一遍（P3 模拟阅读 + P4 边界尝试结合）：

- 记下每节的输入/输出是否在上下文中成立
- 记录决策判断：该节给出的引导是否足够做出决策？是否有决策引导真空？
- 走到最后，检查产出表是否覆盖了该场景应有的产出

## 评估整理（P5 的要点）

**严重程度格式：** 阻塞/缺陷/建议（以可行动性为导向）。三级定义：

- **阻塞**：逻辑矛盾或流程卡死点——直接导致执行者无法完成设计
- **缺陷**：引导不足或覆盖面缺口——执行者能走完但设计质量受影响
- **建议**：可读性或措辞改进——不影响设计结果

**复现对照注意（P5S1）：** 回到 P1S3 整理的作者意图（编写时的理解），按四向对照复现理解。偏离期望时有两条路：方法论需要修正，或设计意图需要调整。

**修复优先级（P5S4）：** 阻塞项最先修，缺陷按影响范围排序（核心链路 > 边缘场景）。**错误模式提取（P5S5）：** 未发现重复模式时记录「未发现重复模式」即可。

**错误模式搜索候选（P5S5）：**

- **步骤承诺未兑现** — 前文说「详见下文」但下文不存在或内容不匹配
- **约束收集遗漏** — 方法论声称覆盖 N 个维度但实际只写了 M 个
- **决策引导真空** — 该节给出的信息不足以让执行者做出决策

## 与文档推演的关系

本文档描述的是**设计方法论文档**的验证方法。如果被推演对象是普通操作指南或最终用户文档，应使用 [doc-guide-rehearsal.md](doc-guide-rehearsal.md)。判断标准：文档的读者是执行设计任务的接收方吗？如果是，用本参考；如果文档的读者是执行具体操作，用文档推演。
