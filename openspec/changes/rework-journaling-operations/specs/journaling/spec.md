# Spec Delta

## MODIFIED Requirements

### Requirement: 行为边界
本技能提供「为自己设计一套 journal 长期记忆系统」的指导：启发、引导 agent 为自己设计 journal，而非直接定义 journal 运行的细节。技能内容陈述设计考量与可改的默认方案，对任何具体 journal 的运行细节（分类方案、字段、目录、维护安排）不做规定。

#### Scenario: 分类归属不由技能裁定
- GIVEN 某 journal 的规则文档定义了分类方案
- WHEN 判断一条新内容的目录归属
- THEN 依该 journal 规则裁定，本技能不预设任何强制分类

#### Scenario: 维护不自动启动
- GIVEN journal 存在条目过期或标签蔓延迹象
- WHEN 判断是否启动维护
- THEN 只在用户明确要求时执行；agent 不自行启动维护，可提醒用户触发，并建议在专门会话中进行

#### Scenario: 维护论述的非执行阅读
- GIVEN agent 在用户引导下进行小规模整理或日常写入
- WHEN 需要整理与维护相关的判断依据
- THEN 可读取维护协议的论述作为启发性参考，这不构成维护协议的执行，其流程义务不被触发

### Requirement: 协议的指称
「协议」在本技能中是对特定操作的称呼：技能内容提及一个协议，即指名该项操作并指引向这项操作的论述。协议条目不展开操作步骤——方法在论述中。技能的加载指引（协议表）除协议条目外，还可包含非协议的参考条目，参考条目指名其覆盖的操作族并指引到共同论述。

#### Scenario: 协议条目即指引
- GIVEN 技能内容中的某个协议
- WHEN 检查其表述
- THEN 它指名一项特定操作并指引到该操作的论述，不在条目内展开操作步骤

#### Scenario: 参考条目指名操作族
- GIVEN 加载指引中的非只读操作参考条目
- WHEN 检查其表述
- THEN 它指名该参考覆盖的操作族（改变 journal 状态的操作）并指引到共同论述，不伪装成单一操作的协议条目

## ADDED Requirements

### Requirement: 非只读操作参考
技能设一篇非只读操作参考，承载改变 journal 状态的操作（编写、收录、移动、删除等）共享的概述、提示、原则与遵守 journal 规则的义务。移动、删除等操作在该参考中只作最小指引——具体语义（删除的退场规则、移动的归属判断）由 journal 规则承载；技能不设删除协议，不预设删除语义。

#### Scenario: 删除请求路由到 journal 规则
- GIVEN 用户要求删除某条 journal 条目
- WHEN agent 按加载指引寻找操作去处
- THEN 从非只读操作参考获得最小指引并读取该 journal 规则的删除约定执行，不落入维护协议，也不将维护协议的操作规范当作删除规程

#### Scenario: 族义务单处定义
- GIVEN 编写、收录、移动、删除各操作路径
- WHEN 陈述「读取并遵守 journal 规则」的义务
- THEN 该义务在非只读操作参考中定义一次，各操作路径引用它，不逐字重复

#### Scenario: 操作参考入口可见
- GIVEN agent 因非只读操作加载技能
- WHEN 检查技能入口
- THEN 非只读操作参考在加载指引中占有一行，无需打开其他参考文件即可发现其存在

### Requirement: 收录并入写入
现存文档收录为 journal 条目时，将文件拷贝到 journal 对应位置，再在其上修改调整（避免手工抄写）；frontmatter、summary、链接、分类等加工与写入流程一致。技能不设独立收录协议，不设收录准入判断流程与收录专用安全边界。

#### Scenario: 收录走写入路径
- GIVEN 用户要求将一份现存文档存入 journal
- WHEN 执行收录
- THEN 拷贝文件到目标位置后按写入流程加工，不执行独立的收录协议

#### Scenario: 收录价值判断承接自写入
- GIVEN 待收录内容与 journal 既有条目高度重叠或无长期价值
- WHEN 判断是否收录
- THEN 按写入协议「判断是否值得写」的判据处理，技能内容不另设收录准入步骤

### Requirement: 发现合约的模板与方法
技能内容同时承载发现合约的注入文本模板与设计方法论述。模板保留「会话开始时读取 INDEX」的强制底线与跨宿主通用要素；设计方法论述给出注入文本的要素框架（定位立场、使用路由、操作边界）与写作原则，表述按宿主实际机制适配（如具备 INDEX 快照注入机制的宿主以快照说明替代读取动作）。agent 对宿主提示词只能提案、提醒、编写草稿；写入或更改由用户执行或经用户批准。

#### Scenario: 模板保留读取底线
- GIVEN 使用发现合约的注入文本模板
- WHEN 检查模板内容
- THEN 「会话开始时读取 INDEX」的指令存在且为强制表述，不因宿主差异从模板中移除

#### Scenario: 按宿主机制适配表述
- GIVEN 宿主具备 INDEX 快照注入机制，INDEX 内容随会话自动可见
- WHEN 编写该宿主的注入文本
- THEN 依据设计方法论述将读取动作表述调整为快照说明，要素框架不缺项

#### Scenario: 宿主提示词的更改权限
- GIVEN agent 发现注入文本与设计方法论述存在实质缺口
- WHEN 处理该缺口
- THEN agent 向用户提案或提醒，可编写草稿文本，写入或更改由用户执行或经用户批准
