# 脚本用法

脚本是单文件 `scripts/multi_ask.py`，只依赖 Python 3 标准库。下文命令里的路径相对技能目录：不在技能目录里执行时，换成脚本的完整路径。宿主上 `python` 不可用时改用 `python3`，Windows 上通常是 `py`。

## 全流程

1. **起草**：按 [问卷格式](questionnaire-format.md) 写一份 markdown；哪些题进这一批看 [组织一批问题](organizing-questions.md)，单题怎么写看 [写好一道题](writing-questions.md)。
2. **校验**：`python scripts/multi_ask.py validate <问卷.md>`，按错误行的修复指引逐条改，直到 `OK: <n> 题`。把 n 与打算问的题数对一遍——校验只认格式。
3. **收卷**：`python scripts/multi_ask.py show <问卷.md>`。它会一直阻塞到用户提交，所以要按长驻进程跑，从它的输出里取答卷路径。
4. **读答卷**：读答卷 JSON 的 `answers` 与 `global_comment`。
5. **回读**：`python scripts/multi_ask.py assemble <答卷.json>`，得到问卷全文、问题块位置换成作答结果。要把裁决连同原论述放回上下文，用它；手工按 id 回查问卷还得自己补全题干与选项文本。

## 命令

### `validate`

```
python scripts/multi_ask.py validate <问卷.md>
```

只校验，不开交互页。

- 通过：stdout 输出 `OK: <n> 题`，退出码 0。
- 不通过：不开交互页，一次列完全部错误，退出码 1。每条形如 `<问卷文件>:<行号>: <问题描述> → <修复指引>`。

校验覆盖面：全卷至少一个白名单问题块；块首行是 `<块 id> 题面`；题面非空；选项行格式合法；选项文本非空；选项 id 块内唯一；`single-choice` / `multi-choice` 不得只有一个选项；`yes-or-no` 的选项标签只能是 `yes` / `no`；块 id 全卷唯一；围栏闭合；围栏名接近题型名时提示拼写。

校验不出来的：题面是不是一句命题、选项集合有没有漏掉用户想选的那一项、全卷前提该不该写进论述。这些只能自己过一遍。

### `show`

```
python scripts/multi_ask.py show <问卷.md>
```

前提：脚本与用户的浏览器在同一台机器上。交互页只监听 `127.0.0.1`，用户在别的机器（容器、远程主机、另一台电脑）上打不开，脚本没有别的通道。

1. 先校验；不通过即终止，退出码 1。
2. 在 `127.0.0.1` 的随机端口起本地服务并打开浏览器；浏览器自动打开失败时服务照常运行，打印 URL 供手动打开。
3. 一直阻塞到用户提交。提交后写答卷文件（位置与命名见本文件「答卷」节），页面原地切成「已提交，可以关闭本页。」并禁用控件，不跳转、不自动关闭；脚本单独打印一行答卷路径，退出码 0。
4. 进程被 Ctrl+C 或外部超时终止：不写答卷文件，退出码 130（被外部杀掉时可能没有退出码）；用户已经答过的内容不会保留，重新 `show` 会从头再来。

页面在打开时读取一次问卷，此后用户答的是那一份快照：作答期间改问卷，改动不会出现在页面上。提交后不能修改，任何一题都可以留空。

窗口够宽时，正文左侧的空白区有一份目录，列出问卷的各级标题，点击跳转、滚动时高亮当前所在的一节；窗口偏窄时目录自动隐藏。目录只是标题的索引，问题块不会单独列进去。

输出有两行：就绪时打印 URL，提交后打印答卷路径。传入相对路径时打印的也是相对路径；跨目录回读只认答卷 JSON 里的 `questionnaire`。

### `assemble`

```
python scripts/multi_ask.py assemble <答卷.json>
```

按答卷的 `questionnaire` 记录的问卷路径找到问卷（找不到时退回答卷同目录的同名文件），把每个问题块替换为作答结果，整份文档输出到 stdout，退出码 0。答卷或问卷缺失、JSON 非法、答卷引用的块 id 或选项 id 在问卷中不存在时，按 `validate` 的同一错误行格式报错并给出修复指引，退出码 1。

配对只认 id：问卷里的题面与选项文本被改过、选项顺序被换过，拼装不会察觉，读出来的会是「旧裁决 + 新文字」。若在作答之后动过问卷，重新 `show` 收下一份答卷，或手工核对改过的那几题。

## 答卷

答卷文件命名为 `<问卷名去扩展名>.answers.<YYYYMMDD-HHMMSS>.json`，与问卷同目录，时间取提交时刻的本地时间，例如 `release-plan.answers.20261107-143205.json`。同一秒内已有同名答卷时，再追加三位序号（`.001`、`.002`……），序号按该时间点已有的序号文件名递增；时间点不同就不带序号。同一份问卷可回收多份答卷，文件只增不改。问卷本身也留在原处——答卷里的选项 id 只能靠它解释，问卷丢了，答卷就只剩一串 id。所以问卷放一个能长期找到的位置，别放临时目录。

```json
{
  "questionnaire": "/home/user/notes/release-plan.md",
  "answers": [
    { "block": "scope", "selected": ["narrow"], "free": "" },
    { "block": "docs-gaps", "selected": ["migration", "errors"], "free": "" },
    { "block": "canary", "selected": [], "free": "先内部一周，但别超过三天。" },
    { "block": "open", "selected": [], "free": "" }
  ],
  "global_comment": "整体太赶，文档优先。"
}
```

- `questionnaire`：问卷路径，`show` 记录绝对路径。
- `answers`：每个问题块一条，顺序与问卷一致。`block` 为问题块 id；`selected` 为选项 id 数组；`free` 为自由输入，可为空串。答卷不回显题干，也不含选项文本——定位题目看问卷。
- `global_comment`：总评文本，可为空串。

## 读答卷

- 有选中项：按选项 id 回问卷取文本，裁决就是它。
- 整题空（空数组加空串）：用户跳过了这一题，不等于否决。别替它补一个答案，把它连同题干列出来再问一次。
- 只有自由输入：自由输入就是裁决，引用原文推进，不要改写成你的说法。
- 选中项与自由输入矛盾：以自由输入为准，并在回复里把自己读到的裁决复述一次，让用户能纠正。
- `global_comment` 不是附言，是跨题意见：它可能推翻逐题结论，动手前先读它。

## 拼装答卷

问卷正文原样保留，每个问题块替换为「题面 + 引用块作答」（不显示块 id）：

```markdown
第一批收窄到核心命令，其余功能留到第二批。

> 选：收窄：本月能上线，用户暂时看不到导出与批处理。
> 补充：导出功能在文档里标成「暂未提供」。
```

- 有选择：`选：<选项文本>`，多选以 `；` 连接；`yes-or-no` 显示该题实际标签，未覆盖时即「同意」或「驳回」。
- 有选择且有自由输入：另起一行 `补充：<文本>`。
- 无选择、只写了自由输入：`> 答：<文本>`。
- 整题未答，或答卷缺该块记录：`> 未答`。
- 有总评：文末追加 `---` 分隔线与 `**总评**` 段落。
