# Design

## Context

`dev/skill-master/content/references/general/structure.md` 现有结构（全文已读，共四节）：

1. 开篇：四条原则（清晰、有条理、便于查看、便于维护）作为取舍判据；
2. `## 按加载成本分层`（三层成本表 + 「入口只留每次命中都要用的」+「references 内部是分层的」两个小节）；
3. `## 内容该放哪一层`；
4. 末尾无收束。

散落在正文中的模型碎片：「上移/下沉」（预设偏序）、「可达性/真实阅读路径」（预设根与可达）、「链上每多一跳」（预设边）——都指向一个未被立起来的有向图模型。动机见 proposal.md（Why）。

写作约束（来自 `openspec/specs/skill-master` 的 Requirement，改稿必须遵守）：正文用确定性陈述，不出现「待定/将来可考虑」；术语不漂移（本文件现用「论述」「指针」等既有术语）；要点式组织——每要点讲清是什么、为什么、给具体场景；标题表述读者的工作，不宣布文件身份；按加载序列推算读者信息状态，新增总纲节位于最前，其后的既有内容不得假设读者已读过它没读过的东西（反过来说，总纲是读者进入的第一节，后文引用它的概念是合法的前向引用）。

## Goals / Non-Goals

**Goals:**

- 在 structure.md 内立起顶层结构模型：根（SKILL.md 不被指向）→ 树干（按领域/话题递归切分）→ 允许横向互指成网 → 单链为合法退化态。
- 明确无环约束落在实质论述依赖上（A←B←C←A 式循环依赖不合法），导航/回访指向不构成论述依赖。
- 划开「展开/参照方向的合法互指」与「互相补洞的病态互指」的边界。
- 把既有各节重新定位为该模型之下的推荐配置与推论，调整越位措辞（把三层当作结构唯一形态的口吻）。

**Non-Goals:**

- 不改 `skill-md-writing.md`、`standards.md`、`scoring-rubric.md`、`skill-design.md` 等任何其它文件；`skill-design.md` 中「互相引用、各自不完整」的表述与本模型天然一致（那正是病态互指），不需改。
- 不重构现有四节的顺序与标题层级——总纲插入即可，不重排。
- 不引入图论术语堆砌（「入度」「拓扑排序」等不进正文）；模型用读者工作语言表述。
- 不动 specs（已 skip）。

## Decisions

**D1：总纲节的位置与标题。** 插在开篇四条原则之后、`## 按加载成本分层` 之前，新增 `## 文档集合是一张有向图`（暂定名，标题表述读者的工作可再斟酌为「先看文档集合的整体形状」一类）。理由：四条原则是判据，模型是判据作用的对象，先立对象再给判据的推论（三层）；放在最前让「上移/下沉」等后文词汇首次出现时已有定义。备选：放在三层节之后作总结——否决，那样读者仍先带着「三层即结构」的误解读完核心节。

**D2：总纲节的内容骨架（要点式，四点）。**
1. 根：SKILL.md 是唯一入口，不被任何其它文档指向——读者永远从根进入，回指入口是冗余（读者手里正拿着它）。
2. 树干：除根外的文档按领域、话题切分，组内可继续递归细分；现有「references 内部分层」「分组轴」讲的就是这条边的局部。
3. 网：参考文档之间允许互相指向，合法方向是展开与参照；判断一条互指是否合法问「它在展开什么」——有明确被展开/被参照的对象就是边，两边各缺一块靠对方补是病态（skill-design 判过的硬拆症状）。
4. 链与无环：单链是无分叉的树，完全合法（顺序展开的内容天然成链）；无环约束落在实质论述依赖上——「做 A 要依 B 的要求、B 的做法在 C、C 又说该话题的论述在 A」这种循环依赖不合法，它会让读者绕圈且每处都看似有理；纯导航/回访类指向（「所属工作」「返回主流程」）不承载论述依赖，不在此约束内，因此既有文档中的回访链接不需要改。

**D3：既有节的再定位方式——改措辞，不改结构。** 「按加载成本分层」节首句补一句定位：三层是该图在加载成本维度上的一种推荐配置（成本只解释了纵深方向的取舍，解释不了横向切分），把该节从「结构是什么」降为「结构怎么组织得省」。逐句核查该节与总纲冲突的表述：现文「组织方向因此确定」语气过强，改为在推荐语境下成立的表述。`## 内容该放哪一层` 的「上移/下沉」在总纲已有偏序定义，无需改动。开篇四条原则段落补一句「具体建议都是原则在图上的应用」的衔接（现文说「在具体问题上的应用」，语义已兼容，仅在总纲加入后微调指向）。

**D4：与三层表的关系。** 三层成本表（元数据/指令/资源）保持原样——它是成本模型，不是拓扑模型，总纲不重复它；总纲只声明「本节讲形状，下一节讲成本」的分工，避免两节互相转述形成转发病灶（spec 病灶七类之一：转发）。

**D5：不写场景与测试。** 本变更是论述增强，验证方式是按 spec Requirement 通读改后全文（确定性陈述、术语不漂移、要点三件事、加载序列信息状态），以及推演自检：一个零上下文 agent 读总纲节，能否独立判断「我这个技能只有两份顺序文档」合法、「两份文档互指补洞」不合法。不新增永久测试。

## Risks / Trade-offs

- **总纲与三层节的重复风险**：两节都谈「怎么组织」时容易互相转述。缓解：D4 的分工声明，总纲只谈形状与合法性，成本取舍全部留在原节。
- **无环论述过度学术化**：读者是要写技能的 agent，不是图论学生。缓解：D2 第 4 点只给具体环例与判断问句，不给定义。
- **改动诱发连锁改稿冲动**：读总纲时容易觉得 rubric、skill-md-writing 的相关措辞也该顺手改。缓解：Non-Goal 明确排除；若实施中确实发现冲突表述，记录到变更讨论里再定，不在本变更内扩scope。
- **篇幅**：总纲控制在 4 个要点以内，否则入口文档自身违反「入口只留每次命中都要用的」的现文判据。
