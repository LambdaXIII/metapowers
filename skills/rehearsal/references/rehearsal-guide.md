# Rehearsal（推演）— 通用论述

## 推演是什么

**Rehearsal（推演）= 暂停作者身份，完整走一遍另一个视角的「首次接触 → 理解 → 决策」链路。**

它和载体无关（载体 = 被推演的产物）——可以推演文档、代码、UI 流程、API 设计、教学大纲、定价页、演讲脚本、审查清单。
它也不限定读者——读者可以是 AI 模型、真实用户、学生、顾客、新人同事，也可以是执行引擎（逻辑链路的机械执行者，不需要模拟心理，只需模拟机械执行）。

推演的目的是为推演材料提供**有指导价值的优化依据**——既不为否定而否定，也不附和。优化方向是**准确复现**：材料在全新状态（无作者上下文）下被重新阅读时，读者复现的理解与编写时的理解相同。复现质量从四个方向检查：

- **劣化**：复现比编写时浅——"为什么"、取舍理由、核心洞察在传递中丢失
- **偏差**：复现与编写时不同向——歧义、误导、理解错方向或侧重点等
- **过度**：复现超出编写时——过度承诺、强度放大，读者获得了编写时未意图的内容
- **重复**：同一概念或描述在材料中被重复定义、重复展开——读者收到同一内容的多份拷贝，重点图景与阅读体验偏离编写时意图。区分：**引用**（后文指向前文定义，如"见上文"）与**提及**（点到概念但不重新展开）不是重复；只有完整的重复定义或重复描述才是

**推演不是**：

- Rehearsal ≠ 测试：测试需要真实读者（真实用户、真实模型）。Rehearsal 是模拟，只能给出预判。已有真实反馈数据时，以反馈为准，推演仅作补充视角。
- Rehearsal ≠ 自查：自查是作者视角的重读——你仍带着"我知道要表达什么"的知识。Rehearsal 是放下作者身份，以读者视角走一遍。
- Rehearsal ≠ 同行评审：同行评审有另一个真人参与。Rehearsal 是你在自己的脑子里跑另一个人的模拟。

**为什么用它**：写作时你掌握全部上下文——每个术语的定义、每步取舍的理由、每段的意图——因此无法可靠判断：一个没有这些上下文的人会怎么理解这份材料。真实读者在交付之前又往往不可得。推演是唯一不依赖外部资源、由推演者自己就能执行的读者视角检查：它把"未来某个人第一次接触这份材料"的场景搬到当下，在脑子里完整跑一遍——跑完你就知道哪里会卡、哪里会误解、哪里会获得你没打算给的信息。在交付之前，它是可用的手段里最接近真实消费的一种。

**推演者定位**：推演的核心是站在评估者位置，模拟读者视角——不是变成读者。推演者需要同时维持两层观察：**内容表达层**（措辞是否准确、语义是否清晰）和**逻辑执行层**（按规则走下去得到什么结果）。每步自问"我现在是评估者还是读者"，不要滑入读者角色放弃对载体的判断。同时保持中立：不为否定而否定（凑数不是发现），也不为材料辩护（推演者常是作者本人，容易为"这里其实有原因的"开脱）。发现要真实，没有问题的部分如实确认。

## 推演步骤

推演包含五个步骤：P1 是推演前的准备工作，P2-P4 是推演过程，P5 是推演后的评估整理。

### P1 准备工作

推演开始前，先准备好推演所需的全部要素——它们支撑推演过程，并在评估整理阶段被使用。需要准备：

- **载体与范围**（P1S1）：推演的对象与覆盖范围
- **读者画像**（P1S2）：目标读者是谁——背景知识、所处状态、前置假设
- **期望效果**（P1S2）：读者消费后应达到的效果——笼统的、最终的目标
- **作者意图**（P1S3）：编写时的理解——具体条目，可逐条校对、尽量可量化

其中读者画像在推演中保留，作为 P2 身份设定的锚点；载体与范围是推演对象参数，贯穿全程；期望效果与作者意图是作者侧要素，P2 身份转换时划掉，P5S1 复现对照时重新启用。

**准备完成的标志**：以下三条全部满足才进入 P2——

1. 范围声明能一句话说出：推演对象、覆盖到哪，阅读范围（前文依赖/出口回链/被引用处）已枚举
2. 读者画像已写出背景知识、所处状态、前置假设；作者侧要素（编写意识、期望效果）已写出，且期望效果是笼统的最终目标
3. 意图清单已覆盖最初的构思、讨论的决策、必要的信息三类来源——逐条问「读者理解这条需要什么前文」，答不出的条目即缺漏，补全后再停笔

清单残缺的代价在 P5S1 才暴露：复现对照在残缺基准上进行，且推演者无法自知——对照之前看不出缺了什么。因此准备阶段的停笔标准从严。

#### P1S1 划定推演载体和范围

确定本次推演的对象——一个文件、一个章节、一个多文件体系、一组操作路径。载体（被推演的产物）决定"什么形式、按什么顺序消费"；范围圈定"具体哪份材料、哪部分"，是起步声明——它让推演得以开始，也决定主动搜索的焦点。

**阅读范围大于推演范围。** 推演时适当提前阅读——读者从哪进入、范围开头依赖什么前文；延后结束——出口、路径末端、回链；覆盖周边——被引用处、调用方。载体"何时因何如何被读到"——它的**被消费情境**——是推演评估的内容。

**上下文材料只读不推演。** 衔接带（被引用处、上游文件）是阅读路径，不是推演对象——不对它们做推演，但推演中撞上的问题照常记录。

**发现不设限。** 推演中连带发现的问题就是本次推演的发现，没有范围内外之分。发现了就是有，没发现就没有。

#### P1S2 视角锚定

确定读者是谁：描述目标读者——他有什么背景知识、处于什么状态；你假定了读者已经知道哪些事、手边有哪些工具。

然后解离作者和读者身份：作为作者，编写时有哪些编写意识（编写意图、目的、期望用途、编写规范等）？作为读者，消费这些内容时，应该达到什么样的效果才算有效？

注意：这里期望的读者理解是**笼统的、最终的**——它是目标，不是细节。具体条目在下一步整理。

#### P1S3 作者意图

延续视角锚定，把作者的意图整理为**具体条目**——细节、可逐条校对的、最好可以量化的。形式是回顾编写推演材料**之前**的过程：罗列最初的构思、讨论的决策、必要的信息等。这是"编写时的理解"的显式化。

这些整理将作为复现对照的基准：P2 身份转换时划掉，P5S1 评估整理时回到它，将模拟读者的复现理解与编写时的理解对照。整理是 P2 划掉的前提——没有显式清单，P2 就无物可划，推演中你会不自觉地带着作者身份阅读，从而放过材料中的元语境渗漏（作者身份的语境进入文字、读者无法解析或不该收到；识别方法见 P3 留意之处）。

### P2 身份转换

转换身份为读者。显式划掉 P1 中整理出来的作者侧要素——编写意识、期望效果（P1S2）与作者意图（P1S3）：没写 = 不存在。然后设定阅读身份：

- 我是 [ 读者描述 ]，我此刻的状态是 [ 初始状态 ]
- 我手里有 [ 材料名称 ]，除此之外没有任何其他参考
- 我的目标是 [ 读完后要做什么 / 决定什么 ]

身份设定越精确，推演越有效。模糊的身份（「我是一个用户」）产生的信号也模糊（「这里有点 confusing」）。精确的身份（「我是一个刚入职两周的开发者，第一次读部署文档」）产生可操作的信号（「读到第三步时我不知道 `deploy-key` 在哪里找——文档没有说明生成位置」）。

### P3 模拟阅读过程

这是推演的核心步骤——模拟读者如何理解这份材料。**阅读和理解是两个动作**：阅读是逐段进行的摄取，以较细粒度逐步进行；理解发生在每次阅读之后，并且绝非割裂行为——随着阅读更多内容，理解本身持续累加和流转，这是一个动态的过程。推演关注的正是这个过程，以及这个过程如何引导至预期结果——模拟读者读完后的复现理解（P5S1 的对照输入）。

**阅读纪律：**

1. **真实读取材料并理解**。推演材料为文件时，重新真正读取它并理解，而非基于历史中的记录进行。凭记忆推演等于带着作者视角阅读。
2. **渐进式阅读**。较长的材料，或多处链接的关联材料，尽量避免一次性阅读所有内容。按逻辑单元（节/章/功能块，而非自然段）分段，单元划分由材料的自然结构决定。

**理解状态：** 每读完一个逻辑单元，停下来以读者身份产出当前的理解状态——

- **复述**：用读者自己的话讲出"读到这里，我认为这份材料在讲什么、我接下来该怎么做"。复述要具体到能暴露理解的边界："我知道 X，但 Y 还不知道。"
- **期待**：说出"我期待接下来会讲什么"。期待是探针——后续内容是否印证它，直接检验读者理解与作者意图是否同向。

继续读下一单元，验证期待：实际读到的与期待相符，理解顺滑累加，此时只需一句确认（"与期待相符，继续"），不必展开复述；不符——停顿，记录这个偏离。新信息会刷新旧理解、修正旧理解、或与旧理解冲突——冲突点是材料最需要检查的地方。信号的记录价值在偏离处，不在顺滑处——对每个单元都展开完整复述只会淹没真正的信号，长材料尤其如此。

**读完全程后**，产出**最终理解状态**：这份材料讲了什么、读完我能做什么、还缺什么。这是 P5S1 复现对照的输入——模拟读者读完后的复现理解。

#### 一些可能需要特别留意之处

以下模式在阅读过程中常见，随时对照检查是否遗漏。

静态的、内容层面的：

- **信息缺失**：读者缺少某条前置知识——他还能继续吗？材料有没有给出替代路径？
- **错误输入**：读者做了错误操作，或误解了某条指令——材料能否把他拉回来？
- **非标准进入/退出**：读者从中间进入、跳过某部分、从另一条路绕过来——材料还能被理解吗？
- **边界变化**：极简/极繁输入、大量分支、不确定步骤、并行链路——材料在这些变化下还成立吗？
- **元语境渗漏（Context Leak）**：作者身份的语境（设计意图、讨论背景、写作时的自我定位）泄漏进了材料。材料只应承载读者身份的内容——判定标准：读者身份检验——这段内容是读者身份需要的，还是只有作者身份才懂、才在乎的？读者身份不需要的内容：无法解析的是悬空参照，能解析的是身份边界错位。先确认这段文字最终停在哪个载体、被谁读（将被直接拷贝的模板/种子/示例，其读者是拷贝产物的最终使用者，不是读模板的 agent），再逐句问「读者身份用它吗」。典型信号与修复方向见[缺陷分类法](supplementary/defect-taxonomy.md#🟡-元语境渗漏悬空参照)「元语境渗漏（悬空参照）」与「元语境渗漏（身份边界错位）」条目。
- **不正确的暗示**：材料通过结构、顺序、标题、措辞暗示了作者未意图的关系——把互补概念列成「替代方案」、用先后顺序暗示优先级、只列部分选项暗示全集。推演时除了核对「写了什么」，还要问「读者会从这里的结构和措辞推断出什么」——暗示出来的结论同样要核对。

动态的、过程中的：

- **流畅性问题**：留意阅读和理解过程中的停顿、惊讶、疑惑、跳读等信号，记录信号出现的位置与原因（信息密度过高、措辞模糊、警告过多、缺少下一步等）。信号出现后，继续模拟读者接下来的行为——重读、猜测、跳过还是放弃？材料有没有给出出路？
- **决策点/分叉点**：留意阅读或理解过程中出现的决策点、分叉点——读者在这里做了选择、这里存在另一条路、这里歧义可作两种理解。遇到这些地方，显式标注推演过程中进行了什么选择、为什么这样选择——这是下一步推演过程回顾的输入。

**留意清单收束**：产出最终理解状态后，逐条过一遍上述留意模式——每个模式给出「检查过、无发现」或「检查过、有发现（已记录）」，不允许「没检查」。这一步与 P5S4 的覆盖检查（针对评估维度表）互补：留意清单管阅读过程，评估维度表管评估整理，两者各自闭环，静默遗漏才会被拦截。

### P4 推演过程回顾

回顾 P3 中标注的决策点/分叉点，想象在这些节点做不同选择会发生什么——读者选了另一条路、跳过某部分、从中间进入、作了另一种理解。

**建议：**主动尝试边界/极端条件——载体自身可预料的合理变化（列举见 P3 留意之处"边界变化"）。「上游已保证」指材料中显式声明了该条件由谁负责或由前置步骤产出、且读者能找到声明位置；凡未显式声明的条件一律按需测试。

边界尝试是 P5 评估维度「边界覆盖」（见评估维度表）的输入：除载体确无边界可言（如单段说明文字）外，至少尝试 P3「边界变化」列举的 4 类边界。不做边界尝试，P5S4 覆盖检查中「边界覆盖」维度就必须回答「确实没问题还是没检查」。

必要时可回溯 P3 并重新推演。如果重试，载体、范围、读者身份不变，如无必要不扩大化。新发现并入评估整理。

### P5 评估整理

将推演过程的发现整理为结构化的评估结果——告诉你发现了什么、多严重、先修哪个、有没有遗漏。

#### P5S1 复现对照

回到 P1S3 整理的作者意图（编写时的理解），将模拟读者读完后的**复现理解**与**编写时的理解**对照，从四个方向检查（定义见"推演是什么"）：**劣化、偏差、过度、重复**。

偏离的地方：是材料的问题，还是你的设计意图本身需要修正？不要偷改整理好的意图来让推演"合格"——偏离的发现恰恰是盲区。

#### P5S2 发现归类

将模拟阅读、过程回顾与推演中连带发现的原始信号填入评估维度。每条发现记录四个要素：

| 要素 | 说明 |
|------|------|
| 评估维度 | 该发现属于哪个评估维度 |
| 实际效果 | 推演中观察到的实际接收/行为（来自 P2-P4 的原始信号） |
| 预期效果 | 此处应该达到的效果——因为未达到才成为问题 |
| 严重程度 | 按 P5S3 的格式判定 |

"预期效果"是关键：推演发现的问题之所以是问题，是因为实际效果偏离了应有的效果。写出预期效果让修复者知道目标状态是什么，而不只是"这里有问题"。

同时为每条发现标注缺陷类型（参见 [缺陷分类法](supplementary/defect-taxonomy.md) 中的分类体系）。同一缺陷类型出现 2 次以上 = 结构性缺陷，需要从载体架构层面修复而非逐处修补。

维度根据载体类型选择（见 P5 末尾的评估维度表）。

#### P5S3 严重程度判定

根据载体类型推荐的格式，判定每个发现的严重程度：

| 格式 | 适用场景 | 示例 |
|------|---------|------|
| 阻塞/缺陷/建议 | 通用格式（可排序、无虚假精度、直接映射修复优先级） | 文档、提示词、交互流程、API 设计、设计方法论、计划文档、知识库 |
| ★ 1-5 | 仅用于跨版本量化追踪（测量工具，非严重程度格式） | 知识库的多轮推演追踪 |
| OK/异常 | 二元判定——行为要么符合预期要么不符合 | 逻辑链路 |

#### P5S4 修复优先级与覆盖检查

根据严重程度排序修复优先级。排序依据：

1. 阻塞级发现最先修——它们直接导致读者无法完成目标
2. 影响核心链路的发现优先于边缘场景
3. 同一缺陷类型的多个发现合并修复比逐个修更高效

最后检查覆盖完整性：审视评估维度表，是否每个维度都检查过？空维度需要回答——"确实没有问题"还是"这个维度我没有检查"？

#### P5S5 错误模式提取

完成 P5S1-P5S4 后，审视全部发现，寻找重复出现的根因：

- 多条发现是否源于同一个写作/设计习惯？（例如：多处"路径末端无收束"→ 作者习惯在提供信息后忘记给出下一步引导）
- 多处元语境渗漏 → 作者习惯在讨论后立即写作、把讨论背景直接搬进文字 → 未来写作时在落笔前做读者身份检验（写时判断），而不是依赖推演兜底
- 能否抽象出一条可复用的规则？（例如："每条约束必须附带'否则'的后果描述"）

错误模式是面向**未来写作**的产出——修复当前载体是治标，识别并避免错误模式是治本。模式提取不是强制产出：简单载体的推演可能没有重复模式，此时记录"未发现重复模式"即可。

**评估维度表**（按载体类型推荐）：

| 载体 | 评估维度 |
|------|---------|
| 提示词/指令 | 因果方向清晰度、违规模式覆盖、自检可执行性、后果说服力、边界覆盖 |
| 文档/教程 | 入口明确性、术语全局统一、步骤可跟踪性、缺失场景覆盖、独立性 |
| 设计方法论 | 逻辑正确、线索清晰、前后一致、可复现深刻理解 |
| 知识库 | 全流程可执行性、模块流转清晰度、术语全局统一、覆盖完整性、异常容错 |
| 交互流程（UI/CLI） | 首次可执行性、困惑点密度、放弃率预估、错误恢复路径 |
| API 设计 | 命名一致性、默认值合理性、错误信息可操作性、缺失端点覆盖 |
| 逻辑链路 | 控制流正确性、边界条件覆盖、状态一致性、资源生命周期、异常安全 |
| 计划文档 | 背景充分性、意图完整性、逆向排除度、步骤可判定性、粒度一致性、依赖可见性、边界清晰度、异常覆盖、执行策略充分性 |

## 执行策略推荐

以下策略是推荐，不是规定——按你的场景选择使用。

**嵌入优于收网**：推演不必积攒到最终一次性做。每完成一段时做一次短推演（只测刚完成的部分），比最后做一次全量推演更有效——缺陷发现得越早，修复成本越低。但阶段性推演只解决"有没有明显问题"，取代不了最终的全景推演——跨模块交互问题往往只在全景推演中暴露。**切换时机**：材料合稿（各部分定稿、不再单段增删）时停止逐段推演，合稿后必做一次最终全景推演；全景推演覆盖完范围声明（P1S1）中的全部衔接带即为完成。

**委派并行推演**：材料比较简单且推演目的特别明确时，可以考虑委派子代理针对不同的侧重点并行推演（如多个读者、多个维度），各自产出发现后汇总。「材料比较简单」的可检查近似：单文件、逻辑单元 ≤ 10 个、读者单一、决策路径 ≤ 3 条。若采纳此策略：单推演者委派子代理代读，按 [提示词/指令集推演](scenarios/prompt-instruction-rehearsal.md) 中的「委派推演」方法进行；推演场景较多（≥ 5 个）的批量执行，按 [batch-execution.md](supplementary/batch-execution.md) 的方法进行——批量执行以场景数为准，不受材料复杂度限制；材料复杂度只在「单推演者委派 vs 自我模拟」之间路由。
