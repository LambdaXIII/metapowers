# skill-master

技能承担所有「对象是技能」的工作：制作侧的设计、修改、审查与快速测试，使用侧的预评估与后评估。两侧共用同一套内容判据，但不互相替代。

## 工作域的划分

### 制作侧与使用侧按委托方立场划分

制作侧与使用侧按委托方立场划分，两侧不互指：维护者找技能错处属于审查（制作侧），使用者评估未用过的技能属于预评估（使用侧）。agent 应当能够按谁在提要求判断当前处在哪一侧。

## 审查

### 审查以设计文档、技能正文与支撑论述互校

审查以设计文档、技能正文、支撑论述互为基准比对；锚点不自动豁免，锚点内部不一致时先报出、再作基准。病灶七类只在比对出不一致后用于归类根因，不作逐项扫描项。agent 应当能够从三处不一致的位置定位根因。

### 排查只定位、不修复

症状排查是审查的第二进入方式，从行为与预期不符沿触发链倒推，只产出定位并转交修改，不自行修复。agent 应当能够在排查后交出定位而不改动技能。

### 审查的执行固化为委派

审查的执行固化为委派，委派契约要求执行者写明「明知该查而没查的是哪几类」。agent 应当能够从委派结果里看出漏检发生在哪。

### 环境规则不明时标待核实

机械项（合规判据）依赖的环境规则不明时标「待核实」入清单，不降级放掉，也不硬判。agent 应当能够把不确定项留成待核实，而不是猜一个结论。

## 快速测试

### 快速测试用推演、不执行

快速测试以推演判定零上下文 agent 能否理解、走通、用起来，不实际执行被测技能；流程册的流程图、门禁、中止判据与报告格式是硬约束。agent 应当能够在不运行技能的情况下给出可用性结论。

### 测试子代理不知道预期

测试子代理不得知道预期效果、其他测试单元的存在、baseline 与实验组的区分或任何对比信息。agent 应当能够在设计测试任务时把预期留在自己手里。

## 使用侧

### 预评估只凭手头证据

预评估凭手头证据给出带理由的结论，不判定技能的实际覆盖面，也不进入采纳决定的解读；某方向信息不足时如实记录缺失，不视为缺陷。agent 应当能够交出有证据支撑、边界明确的评估。

### 后评估不委派

后评估逐条洞察绑定本次使用的实证、不记印象式结论，实际执行形态照实记录，偏离指引是信号不是过错；评估不委派，证据在使用者经历里，委派即丢失。agent 应当能够在事后复述证据，而不是复述印象。

## 何时加载技能

### 对象为技能的工作请求都触发

技能的触发面覆盖对象为技能的工作请求，制作侧与使用侧都命中，用户请求与 agent 自问两条路径都算；要求真实执行被测技能的测试类请求不触发技能。description 不使用触发词穷举或 `Triggers:` 类结构化标签。agent 应当能够按工作对象判断是否加载。
