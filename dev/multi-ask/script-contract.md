# multi-ask 脚本契约

本文件是 multi-ask 技能脚本层的权威工件契约：问卷 DSL、校验规则、命令行接口、答卷 JSON 与拼装格式的唯一定义。脚本实现与 SKILL.md 使用说明都以本契约为输入，两者不得各自发明词形或字段名。设计理由随本文留档，技能内容（SKILL.md）只记操作事实，不引述本文。

技能设计规格见 [SPEC.md](SPEC.md)。本文裁定 SPEC 未展开的实现层细节，含设计讨论问卷（`test-space/2026-11-01-skill-design-discussion.md`）Q1–Q7 的取舍。

## 1. 术语

- **问卷**：agent 编写的 markdown 文档，含任意论述正文与若干问题块。
- **问题块**：问卷内语言标记为 `qa` 的 fenced code block，是唯一的交互与校验单元。
- **开放题**：不含任何选项的问题块，只收自由输入。
- **自由输入**：每题恒定附带的自由文本框；**总评**：整卷末尾恒定附带的自由文本框。两者都不占块结构，由渲染层提供，问卷作者无需声明。
- **答卷**：用户提交后产出的 JSON 纯数据文件，不含题干。
- **拼装答卷**：问卷正文原样保留、问题块替换为作答结果后得到的派生文档，按需现算、不落存储。

## 2. 问卷 DSL

### 2.1 文档结构

问卷是普通 markdown：标题、段落、列表、链接、mermaid 等 fenced 块均可自由使用。问题块散布在论述中，块外正文即题面论述——**问题块内只放结构数据，不放题面文本**。无脚本时整卷降级为普通可读 markdown。

### 2.2 问题块字段

块体为 `key: value` 行，只接受三个字段，出现其他字段即校验错误：

| 字段 | 必需 | 取值 |
|---|---|---|
| `id` | 是 | 问题块标识，规则见 §2.4 |
| `type` | 是 | `radio`（单选）/ `checkbox`（多选）/ `yes-no`（判断） |
| `options` | 否 | 选项列表；radio/checkbox 缺省即开放题，yes-no 缺省用默认标签「是/否」 |

选项行格式（`options:` 下的列表项）：

```text
- <选项id> — <选项文本>
```

选项文本为空即校验错误；选项文本自由，可含中文标点与空格。`yes-no` 题的 `options` 若给出，必须恰好为 `yes` 与 `no` 各一次；选项文本可覆盖（如「同意/反对」），不给出 `options` 时渲染层提供默认标签「是/否」。`yes-no` 渲染恒为单选，答卷恒记 `yes`/`no`。零选项的 `radio`/`checkbox` 即开放题。

### 2.3 题型语义

| 题型 | 提交约束 | 答卷记录 |
|---|---|---|
| `radio` | 至多选 1 项 | 选项 id 数组（0 或 1 个） |
| `checkbox` | 任意多项 | 选项 id 数组 |
| `yes-no` | 恰选 1 项 | `["yes"]` 或 `["no"]` |
| 开放题 | 无选项 | 空数组 |

任何题型都可附加自由输入；用户可以不选只写自由输入，可以整题跳过（答卷条目为空数组 + 空文本）。

### 2.4 id 规则

- **问题块 id**：作用域为整卷，全卷唯一。
- **选项 id**：作用域为所属问题块，块内唯一。
- 所有 id 不得含空格，命名不设模式约束（不要求 Q1/A1 之类）。
- 校验点：问题块 id 重复 → 不通过；选项 id 块内重复 → 不通过；id 含空格 → 不通过。

## 3. 校验

### 3.1 校验清单（8 条）

1. 问题块仅出现 `id`/`type`/`options` 三个字段，其余字段报错；
2. `id` 存在、非空、不含空格；
3. 问题块 id 全卷唯一；
4. `type` 存在且属于 `radio`/`checkbox`/`yes-no`；
5. 选项行符合 `- <选项id> — <选项文本>` 格式；
6. 选项 id 非空、不含空格、块内唯一；
7. 选项文本非空；
8. `yes-no` 题的 `options` 若给出，必须恰好为 `yes` 与 `no` 各一次。

### 3.2 错误反馈格式

校验错误一次列完（不是逐条停下），每条形如：

```text
<问卷文件>:<行号>: <问题描述> → <修复指引>
```

修复指引必须告诉 agent 怎么改（例如「选项 id 含空格 → 改用不含空格的 id，如 `my-id`；选项文本写在 `—` 之后」），不得只报错误名。校验不通过即终止，不开交互页。

## 4. 命令行接口

脚本为单文件 `scripts/multi_ask.py`，Python 3 标准库实现，无第三方依赖、无网络服务。三个子命令：

### 4.1 `validate <问卷.md>`

只校验不渲染。通过：输出 `OK: <n> 题`，退出码 0。不通过：按 §3.2 一次列完全部错误，退出码 1。

### 4.2 `show <问卷.md>`

1. 先校验（同 validate）；不通过即终止（退出码 1）。
2. 在 `127.0.0.1` 随机端口起本地服务，前台打开浏览器展示交互页；浏览器打开失败时服务继续并打印 URL 供手动打开。
3. 阻塞等待提交。用户提交后写答卷文件（§5），响应提交成功页，打印答卷文件路径，退出码 0。
4. Ctrl+C 中断：不写答卷文件，退出码 130。
5. 交互页把问卷正文按 markdown 渲染（§7 降级范围），问题块渲染为交互组件：选项控件（radio/checkbox/yes-no 单选）、每题自由输入框、卷末总评框、提交按钮。

### 4.3 `assemble <答卷.json>`

读答卷，按 `questionnaire` 字段在答卷同目录找问卷，逐块替换为作答结果（§6），输出到 stdout，退出码 0。失败情形（答卷/问卷缺失、答卷引用的问题块或选项在问卷中不存在）：按 §3.2 风格报错并给修复指引，退出码 1。

## 5. 答卷 JSON

```json
{
  "questionnaire": "2026-11-01-skill-design-discussion.md",
  "answers": [
    { "id": "schema-width", "selected": ["narrow"], "text": "若后续需要控件再扩。" }
  ],
  "global_comment": "结构清楚。"
}
```

- `questionnaire`：问卷文件名（不含目录），答卷与问卷同目录存放。
- `answers`：每个问题块一条、按问卷顺序；`id` = 问题块 id；`selected` = 选项 id 数组；`text` = 自由输入（可为空串）。不回显题干。
- `global_comment`：总评文本（可为空串）。
- 文件名 `<问卷名去扩展名>.answers.<NNN>.json`，`NNN` 为三位起始序号（`.answers.001.json`），取同目录现有同名族的最大序号 +1。同一问卷多份答卷即多个文件，只增不改。

## 6. 拼装答卷格式

问卷正文原样保留，每个问题块替换为引用块：

```markdown
> **[naming]** 选：按序号命名
> 补充：并发多再换时间戳。
```

- 有选择：`选：<选项文本…>`（多选以 `；` 连接；`yes-no` 记「是」/「否」或所覆盖的选项文本）。
- 有自由输入：另起一行 `补充：<文本>`。
- 全题未答：`> **[<id>]** 未答`。
- 开放题有输入：`> **[<id>]** 答：<文本>`。
- 卷末有总评时追加 `---` 分隔线与 `**总评**` 段落。

## 7. 实现约束

- 单文件脚本，Python 3 标准库（`http.server`、`webbrowser`、`json`、`argparse` 等），不引入第三方包；技能装上即用。
- 服务只绑定 `127.0.0.1`，随用随停，不留常驻进程。
- markdown 渲染范围（手写最小渲染器）：标题、段落、无序/有序列表、粗体、斜体、行内代码、链接、引用、分隔线、fenced code block。表格与 mermaid 等其余结构降级为预格式化文本展示，不阻塞收卷。
- 输出与文件一律 UTF-8；答卷 JSON 采用 `ensure_ascii=false` 的可读缩进格式。
