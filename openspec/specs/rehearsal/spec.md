# rehearsal Specification

## Purpose

本域是推演（rehearsal）检查技能。作者无法感知接收方的第一视角体验——作者知道自己想表达什么，因而看不到「不知道目的的人会在哪里卡住」。推演强制切除作者知识，模拟接收方的首次接触 → 理解 → 决策全过程，卡住之处即材料的问题。任何「给别人看 / 用」的交付物（文档、提示词、计划、API/UI 设计、教程、知识库、指令集等）都可以推演。

本技能的定位：提示性框架而非工作流设计——运行时结合场景的判断优于预先规定的机械规则；轻量模拟而非严谨校对——不依赖外部资源、可反复执行。总目标是**准确复现**：材料在全新状态（无作者上下文）下被重新阅读时，读者复现的理解与编写时的理解相同；推演为材料提供有指导价值的优化依据——不为否定而否定，也不附和。

## Requirements

### Requirement: 行为边界——指导范围止于推演结论
本技能指导推演本身：从推演准备到推演结论（评估依据）的产出。推演结论产出之后的工作——推演报告如何解读、其中意见如何取舍、材料是否修改与如何修改——属于使用者当前任务的一部分，不由本技能定义；本技能指导任务中的推演步骤，不替代使用者的任务。评估结论本身不含对错判定，不设「通过 / 不通过」类出口。推演是轻量模拟手段（不依赖外部资源、可反复执行），不作为严谨校对使用，也不宣称与严谨校对等价。

#### Scenario: 修改决策不越界
- GIVEN 推演发现材料存在偏差
- WHEN 产出评估
- THEN 交付归类、排序后的发现与修复方向建议，不直接修改材料、不给出通过与否的判定

#### Scenario: 偏离如实记录
- GIVEN 推演发现材料偏离其设计意图
- WHEN 处理该发现
- THEN 如实记录偏离，不修改设计意图使其与材料一致

#### Scenario: 范围声明不写作流程约束
- GIVEN 技能正文表述指导范围的边界
- WHEN 检查该表述
- THEN 它声明技能指导范围与使用者任务的分界，不使用可读作「推演到某一步骤停手」的流程约束措辞

### Requirement: 三层文件结构
推演内容按三层组织：通用论述（方法全貌，必读入口）、场景文档（按载体类型特化）、补充参考（跨场景小块知识）。场景文档假定读者已读通用论述，是在通用论述基础上的补充说明，而非独立论述；补充参考假定读者已读对应的通用论述或场景文档。新增场景文档同步注册到通用论述末尾的路由表，移除场景文档同步移除路由项。

#### Scenario: 场景文档以通用论述为前提
- GIVEN 某场景文档
- WHEN 检查其设计前提
- THEN 它假定读者已读通用论述，在该基础上补充本载体的内容，而非独立成篇的论述

#### Scenario: 场景文档增删同步路由
- GIVEN 新增了一个场景文档
- WHEN 检查通用论述末尾的路由表
- THEN 路由表已注册该文档；移除文档时路由项同步移除

### Requirement: 提示性框架边界
硬性约束只保留在流程骨架层面（准备 → 模拟 → 评估）；具体操作给判断空间——不写场景特化规则，「有则有，无则无」。不引入「必须有记录」类强制机制——过度机制化违反准确复现。

#### Scenario: 强制记录要求即违规
- GIVEN 技能内容要求「每个推演模式必须产出记录」
- WHEN 检查机制化程度
- THEN 判定违规，记录要求属于强制机制，不在骨架硬性约束范围内

### Requirement: 完成判据操作化
推演各步骤可补充完成判据，判据表述为可检查的条件（推演者自行判断这一步是否做完），不引入强制记录要求。「上游已保证」类排除条款有显式声明位置——材料中声明由谁负责或由前置步骤产出，读者能找到该声明处。

#### Scenario: 排除条款无声明处即违规
- GIVEN 材料以「上游已保证」为由排除某检查
- WHEN 检查排除条款
- THEN 材料中存在显式声明位置，指明由谁负责或由哪个前置步骤产出

### Requirement: 评估整理形态
评估整理不采用固定评分机制；发现与评估分离——模拟阶段完成缺陷发现，评估整理只做整理与判断，不二次发现。严重程度格式由载体类型决定，场景文档显式声明该载体的推荐格式。★ 1-5 仅是严重程度格式选项之一，仅用于跨版本量化追踪。

#### Scenario: 载体决定严重程度格式
- GIVEN 逻辑链路推演与设计方法论推演两种载体
- WHEN 查看各自场景文档声明的严重程度格式
- THEN 分别为二元判定（OK/异常）与可行动分类（阻塞/缺陷/建议），不是统一打分

### Requirement: 委托路由
简单的推演检查可以整体委托给子代理：子代理自行加载本技能并运行完整推演（含评估），主 agent 读到 SKILL.md 正文前部的委托路由节即可停止阅读。材料复杂或需要全面覆盖与严谨评估时，主 agent 继续阅读完整流程。

#### Scenario: 委托后主 agent 即可停止
- GIVEN 推演简单快速，主 agent 决定委托
- WHEN 主 agent 读到 SKILL.md 正文前部的委托路由节
- THEN 子代理加载本技能执行完整推演，主 agent 不再继续阅读

### Requirement: 委派推演形态
委派推演的形态在通用论述的执行策略处集中并列记述，共三形态：单推演者委派（材料整体交接给一个子代理）、批量委派（按场景交接给多个子代理）、代理对读（分段流水交接）。三形态共用同一机制——将模拟阅读委派给独立的子代理，以隔离推演者的隐含假设——形态的区别在委派的结构；各形态记述其委派结构、由此导出的适用条件与代价。通用方法（推演者自我模拟）为基座，始终完整可用，不因委派能力存在而被替代。各形态的选用条件表述为能力前提下的裁量——具备委派与通信能力时可考虑选用——不由能力存在而自动触发。

#### Scenario: 三形态入口集中
- GIVEN agent 阅读通用论述执行策略的委派推演论述
- WHEN 检查形态记述
- THEN 三种形态并列记述、入口集中，各形态写明委派什么、怎么委派、适用什么、代价是什么

#### Scenario: 通用方法不依赖委派
- GIVEN 推演者不具备委派能力或选择不委派
- WHEN 执行推演
- THEN 通用论述的推演步骤（准备、模拟、评估）完整可用，不需要委派能力即可完成推演

#### Scenario: 选用条件为裁量表述
- GIVEN 技能正文表述委派形态的选用条件
- WHEN 检查其表述
- THEN 条件以「有能力委派时可考虑选用」的裁量口径表述，不表述为「能用则选」的能力触发

### Requirement: 批量委派
批量推演（场景数量较多时）中，子代理只承担模拟阅读的逐段记录。下发内容限于四项：身份设定、任务目标与入口、材料、输出格式；推演方法、评估维度、验证点、预期路径不下发——只给入口，不给路线。验证点留在推演者处作为复现对照基准，汇总打分由推演者产出。

#### Scenario: 下发不含评估框架
- GIVEN 批量推演正在向子代理下发任务
- WHEN 检查下发内容
- THEN 只含四项，评估维度、验证点、预期路径不在其中

### Requirement: 代理对读
代理对读是委派推演的形态之一：推演者承担推演准备、按材料自然结构切分片段、逐段传递与评估整理；子代理只以设定的读者身份阅读当前片段，对每段产出理解状态反馈（复述、期待、困惑）。反馈时序约束：子代理对第 n 段的反馈先于收到第 n+1 段。下发内容限于身份设定、当前片段与反馈任务，不含材料其余部分、推演方法与评估维度。适用条件：具备委派与多轮通信能力时可考虑选用，适用于篇幅长、前后依赖强的材料——读者形成的预期要到后文才核对得上，预知后文会使核对失效。方法文档如实交代方法边界：切分依材料自身的结构单元进行，不为推演效果另设边界；片段依赖的上游文本前置并入并标注为背景，或声明该路径推演不到；适用面为线性消费的材料，分支消费形态按路径多轮对读或如实声明不适配。

#### Scenario: 反馈先于下一段
- GIVEN 代理对读正在进行
- WHEN 检查传递顺序
- THEN 子代理对当前片段的反馈发生在下一段传递之前，对后续内容的预期先于该内容被记录

#### Scenario: 下发不含材料全貌
- GIVEN 推演者向子代理传递片段
- WHEN 检查下发内容
- THEN 只含身份设定、当前片段与反馈任务，不含材料其余部分、推演方法与评估维度

#### Scenario: 上游依赖显式处理
- GIVEN 某片段的理解依赖上游前文
- WHEN 推演者准备该片段
- THEN 上游文本前置并入并标注为背景（不作推演对象），或声明该路径推演不到，不静默假设子代理已知

#### Scenario: 分支消费如实声明
- GIVEN 材料为决策树分支消费形态（如多路径知识库）
- WHEN 判断代理对读的适用
- THEN 按路径做多轮对读或如实声明不适配，不做万能宣称

### Requirement: 活体系扩展纪律
缺陷分类法可随实践扩展缺陷类别，但不引入「因载体差异导致的伪类别」。评估维度表可添加新的推荐维度组合，已验证维度不轻易移除；新增维度先在通用论述中定义，场景文档可扩展本场景的特殊维度。

#### Scenario: 新维度先定义后使用
- GIVEN 计划为某载体新增评估维度
- WHEN 检查定义位置
- THEN 该维度先在通用论述中定义，之后才在场景文档中使用或扩展

### Requirement: 元语境渗漏术语群
缺陷分类法以「元语境渗漏」（英文对照 Context Leak）为统一术语，指作者身份的语境（设计意图、讨论背景、写作时的自我定位）泄漏进材料。术语约束：(1) 不引入「元语境 / 文字语境」「写过程 / 读过程」等独立语境模型术语——语境概念一律通过「作者身份 / 读者身份」表述；(2) 判定标准只有读者身份检验一条（这段内容是读者身份需要的，还是只有作者身份才懂、才在乎），任何信号清单扩展都不成为替代判定；(3) 观察形态保留两名：悬空参照（无法解析，归偏差方向）与身份边界错位（能解析但读者身份不需要，归过度方向）；(4) 修复方向三分——删除 / 归位 / 转化——已穷尽，不新增第四类，转化保持约束强度同档；(5) 「不正确的暗示」是偏差方向的独立缺陷类型，不与元语境渗漏合并。暗示的来源包括材料写了什么（结构、顺序、标题、措辞），也包括材料没写什么——材料未提及某项，读者会推断该项不需要、不存在、不被支持或不危险——以及详略与措辞强度的对比：对一处详加说明或使用强制措辞，而对同地位的事项从简或不用，读者会推断后者不重要或不受约束。缺席不都是暗示：有意省略与依赖外部约定的省略不构成缺陷，核对标准不变——读者做出的推断是否为作者意图；(6) 不显式区分「内容完整 / 表述准确」两个操作层面——推演一次性完成两层检查，显式分层制造「分别对待」的错误暗示。

#### Scenario: 判定只走读者身份检验
- GIVEN 一段疑似元语境渗漏的文字，其措辞无任何作者现身信号
- WHEN 判定是否渗漏
- THEN 用读者身份检验判定（读者身份是否需要），不依赖措辞信号清单

#### Scenario: 修复三分不得扩类
- GIVEN 一处元语境渗漏的修复方向归类
- WHEN 检查分类集合
- THEN 归入删除、归位、转化之一，不存在第四类

#### Scenario: 缺席推断对照意图核对
- GIVEN 材料未提及某能力或选项，模拟读者由此推断其不存在或不被支持
- WHEN 处理该信号
- THEN 对照作者意图核对读者从缺席做出的推断：推断非作者意图且由材料触发的，按偏差或过度方向记录；有意省略或依赖外部约定的缺席不构成发现

### Requirement: 语言与指称约定
被模拟对象以 reader 称呼，不以 user 专指。「准确复现」及复现质量四方向术语（劣化、偏差、过度、重复）统一使用。定位词（「快速」「零成本」等）不出现在技能正文——只保留在 description 匹配面；推演的成本是推演者的认知投入。

#### Scenario: 定位词只留在匹配面
- GIVEN SKILL.md 正文与 references/ 文档
- WHEN 检查「快速」「零成本」类定位词
- THEN 正文不出现此类词，它们只出现在 description 中

#### Scenario: 被模拟对象称谓统一
- GIVEN 技能内容指称被模拟的接收方
- WHEN 检查用词
- THEN 统一使用 reader，不以 user 专指

### Requirement: 表述朴素性
技能正文（SKILL.md 与 references/ 全部内容）的表述遵守朴素性约束：自创术语在首次出现处给出定义或朴素解释，后续使用与定义一致；不使用未经铺垫的隐喻与比喻承载判断——比喻旁有直白表述，判断依据不依赖比喻；方法论框架以要素展开的方式介绍，不以要素名压缩成的连字串替代解释。

#### Scenario: 自创术语先定义
- GIVEN 技能正文引入一个自创术语
- WHEN 检查其首次出现
- THEN 术语在首次出现处有定义或朴素解释，读者不参与编写过程也能凭该处文字理解术语含义

#### Scenario: 判断依据不依赖比喻
- GIVEN 正文使用比喻或隐喻
- WHEN 检查该处表述
- THEN 比喻不作为唯一解释载体，其所指的判断以直白表述在同处可获取

#### Scenario: 框架要素展开介绍
- GIVEN 一个多要素方法论框架进入正文
- WHEN 检查其介绍方式
- THEN 各要素被逐一介绍或指向其定义处，不以「A-B-C」式连字串替代解释

### Requirement: 触发语义
触发面覆盖对交付物（文档、提示词、计划、API/UI 设计、教程、知识库、指令集等）的推演请求，用户提问用语（推演 / 验一下 / 检查 / 走一遍等）与 agent 交付前自问（能不能被没上下文的人读懂 / 交付出去会不会卡住等）两条路径都命中。反向条件：仅改错别字、标点、纯格式调整的请求不触发本技能。触发判定细则展开在 SKILL.md 正文，不由 description 承载。

#### Scenario: 无需模拟人的载体照样触发
- GIVEN 某载体（如纯代码逻辑验证）看似不需要人的视角模拟
- WHEN 判定触发
- THEN 仍触发本技能，按对应场景文档推演，不因「无需模拟人」而漏触发
