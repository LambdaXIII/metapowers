# 代理对读——分段流水委派推演

> 按需参考 — 被引用时加载。假设已读通用论述（`../rehearsal-guide.md`），本文只补充代理对读的操作方法，不重复通用论述已有内容。

代理对读是委派推演的三形态之一（形态并列与选用口径见通用论述「执行策略推荐」）：单推演者委派把材料**整体**交接给一个子代理，批量委派**按场景**交接给多个子代理，代理对读把材料**分段、按阅读顺序逐段**交接——每次只下发一个片段，子代理只读到当前片段。

## 适用什么

- **材料篇幅长、前后依赖强**：读者在前段形成的理解与预期（「接下来会讲什么」）要读到后段才核对得上。逐段的期待核对（通用论述 P3 的「期待」反馈）是这类材料的核心检查点——预期是否在后文得到印证，直接检验读者理解与作者意图是否同向。
- **消费形态是线性阅读**（读者从头读到尾）。决策树分支消费形态（如多路径知识库）单轮对读覆盖不了；需要时按路径做多轮对读，或如实声明本方法不适配、改用其他形态。

**代价**：通信轮数 = 片段数，显著高于单推演者委派的一次交接。片段不多、前后依赖不强的材料不值得这个成本。

**为什么分段有效**：材料整体交接时，子代理读到后段之前已经读过前段——它对每一段的首次接触不再成立，读到后段时的理解已被前文影响，期待与后文的核对变成已知答案的核对，测不出真实读者会怎么理解。分段传递让子代理的阅读顺序与真实读者一致：读第 n 段时不知道第 n+1 段写了什么，期待建立在未知之上。

## 怎么做

**主侧（推演者）承担**：P1 全部准备（载体与范围、读者画像、期望效果、作者意图）、按材料结构切分片段、逐段传递与收集反馈、P5 评估整理。

**子代理承担**：以设定的读者身份阅读当前片段——它只看到主侧下发的这一段，每段产出理解状态反馈：

- **复述**：这段在讲什么；读到这里为止我的理解
- **期待**：我期待接下来会讲什么、做什么
- **困惑**：读这段时卡住、疑惑或无法理解的地方

前两项即通用论述 P3 的理解状态（复述、期待），困惑是阅读障碍信号。

**切分**：按材料自身的结构单元切分（节/章/功能块，与通用论述 P3「渐进式阅读」的逻辑单元同一口径），不为推演效果另设边界——切分边界本身会影响阅读体验，非自然结构的切分测出的是切分的产物，不是材料。

**上游依赖**：某片段的理解依赖上游前文时，主侧把必要的上游文本**前置并入下发内容并标注为背景**（标注部分不作推演对象），或如实声明该路径推演不到——子代理只读到当前片段，无法自行补齐上游内容。

**下发边界**：每段下发给子代理的内容仅限三项——身份设定、当前片段（含标注为背景的上游文本）、反馈任务。不下发材料其余部分、推演方法与评估维度；透露这些会改变子代理的阅读行为（约束逻辑同提示词场景文档「子代理提示词原则」）。

## 反馈时序约束

**子代理对第 n 段的反馈先于收到第 n+1 段。** 期待反馈必须在读者尚未读到后续内容时记录——先看到后文再补写的期待不是期待，是复述。这条约束由传递顺序从结构上保证（逐段下发，收到当前段反馈再下发下一段），不依赖推演者或子代理的自觉。

## 与其他两形态的关系

- 单推演者委派（见提示词场景文档「委派推演」一节）：一次交接，成本低；适合材料比较简单、推演目的特别明确的场景，但逐段的期待核对不成立。
- 批量委派（见 `batch-execution.md`）：解决多场景各自需要一次独立、不受污染的首次接触；代理对读解决单次阅读中阅读顺序的真实性。两者解决的问题不同，可以组合（多场景 × 各自分段对读），组合成本 = 场景数 × 片段数，需要如实评估。
