# web-deep-research Specification

## Purpose

本域是系统化深度网络研究技能，解决「把这个话题研究透——怎么系统地逼近真相」的问题：从明确意图，到收集线索，到交叉比对，到交付一份结论可由读者独立检验的报告。它不解决「怎么搜得快」「怎么用某个工具」「怎么判断单条信息准不准」——那是工具使用与评估方法论的事；它解决研究本身的流程设计。深度研究以彻底性优先于速度。

## Requirements

### Requirement: 行为边界
本技能的边界 MUST 保持三条，同时作为触发判定依据：(1) 不是快速查询工具——单点事实查询不需要本技能的方法结构；(2) 不是工具选择指南——搜索工具的选择不属本技能；(3) 不是纯咨询——没有多信源调查维度的「你觉得我该怎么做」不是研究。技能 MUST NOT 控制研究的启动决策——触发与委托决策发生在主会话，技能被加载时研究意图已定；MUST NOT 设置触发闸门或按问句形式判定输入。输出形态 MUST 按问题类型与用户预期缩放——完整报告 / 决策简报 / 精选列表，内部方法流程不随形态变化。搜索方法本身 MUST NOT 要求报告落盘为文件——是否保存、存到哪里由使用层判断。

#### Scenario: 单点查询不进入方法结构
- GIVEN 用户只问一个可直接查证的单点事实
- WHEN 判定方法适用性
- THEN 属快速查询边界，不启动深度研究的方法结构

#### Scenario: 决策型问句合法进入
- GIVEN 用户的问句是「该不该换 Rust」这类决策问句
- WHEN 判定输入合法性
- THEN 主会话可将其合法委托为对比研究，技能不按问句形式拒绝；研究主题另行制定

### Requirement: 收集与评估严格分离
收集阶段与评估阶段之间 MUST 保持硬边界：收集阶段 MUST 只做线索与来源记录（含 URL），MUST NOT 做采信判断——MUST NOT 因「看起来不可靠」跳过、MUST NOT 因「听起来有理」当成事实；评估阶段 MUST 统一按信息性质评估。MUST NOT 边收集边判断。

#### Scenario: 收集期不做采信
- GIVEN 收集阶段遇到一条来源可疑的线索
- WHEN 处理该线索
- THEN 记录线索与来源，采信与否留到评估阶段统一判定

### Requirement: 问题集结构
问题 Q MUST 作为与线索 S、发现 F 并列的一等公民状态，问题集（Q-set）是活的 frontier，研究循环由它驱动。Q MUST 是原子问题，不是目标的分片；目标在主题制定后分解出初始 Q 集。Q 集的演化 MUST 限于三类：消解（Q 的答案经验证转为 F/S，Q 离开集合）、转化（旧 Q 因新知过时，换成更精确的新 Q）、新增（新线索生出新 Q）。MUST NOT 以「问题 + 答案」形式持久化——答案成为发现即转 F 离开，Q 只存未答的开放状态。消解 MUST 以交叉验证为闸门：该信息类型的验证达标才转 F，单来源或未验证的答案 MUST NOT 构成完整消解（重要 Q 保持开放补证，或以低置信度标注消解且不作结论支柱）。「不可得」与「收束」MUST 严格区分、MUST NOT 交叉：不可得是逐 Q 的可得性事实判定（经实际调查确认无可达来源 → 产出可得性 F，Q 关闭）；收束是全局停点（Q-frontier 稳定化 → 仍开放的 Q 进报告「信息空白」，标注「还开放」而非「不可得」）。

#### Scenario: 答案不留 Q
- GIVEN 某 Q 已找到答案并通过验证
- WHEN 更新问题集
- THEN 答案转为 F（附来源 S），Q 离开集合，不以「问题+答案」形式留存

#### Scenario: 不可得不从收束推断
- GIVEN 研究循环达到收束（多轮无变化）
- WHEN 处理仍开放的 Q
- THEN 进报告「信息空白」标注还开放；只有逐 Q 经实际调查确认无可达来源才判「不可得」

### Requirement: 主题制定
研究对象 MUST 是主题（可调查对象），不是用户的问题本身。主题 MUST 满足：中立（无倾向性——决策意图转为考察型表述）、可研究、服务于主会话话题。目标清单与问题拆解 MUST 基于主题展开，MUST NOT 基于用户原话直接拆。主题制定 MUST 区分核心关切与支撑性论据：核心关切（用户真正想问的评价校准，如「配不配 / 值不值」）保留为考察框架；支撑性论据（用户用来质疑的具体理由）纳入相关维度，MUST NOT 升格为独立研究目标——但若核心关切本身是具体对比，对比基准 MUST 保留；去倾向 MUST NOT 变成去维度。研究结论支撑决策，MUST NOT 替用户作决策。

#### Scenario: 支撑论据不升格
- GIVEN 用户以「相比更年长的某人没突出之处」为理由质疑某候选
- WHEN 制定主题
- THEN 该理由纳入相关维度，不升格为独立探查目标；核心关切保留为考察框架

#### Scenario: 决策意图转考察型
- GIVEN 用户意图是「要不要换 X」
- WHEN 制定主题
- THEN 主题转为中立的考察型表述（如「X 与现状的对比考察」），不带倾向

### Requirement: 验证强度与领域规则优先
交叉验证的效力 MUST 按来源独立性双向判定：差异增强——跨领域、跨语言、跨地区、跨利益立场的一致是强验证；关联削弱——同机构、同作者、同引用源头、共同利益、同测量方法的一致是伪验证，MUST NOT 当作独立佐证。领域特化文档定义的采信规则 MUST 优先于通用规则；两者冲突时按领域规则执行，MUST NOT 让执行者自行裁决。

#### Scenario: 同源一致不算验证
- GIVEN 同一机构的两份报告方向一致
- WHEN 判定验证强度
- THEN 属关联削弱情形，不构成独立佐证

#### Scenario: 领域规则裁决冲突
- GIVEN 通用规则「单来源不赋置信度」与领域规则「官方原文单源可采信」冲突
- WHEN 执行采信
- THEN 按领域规则执行

### Requirement: 文档组织与编排策略边界
领域特化文档 MUST 各按其研究对象的知识结构组织，MUST NOT 套统一模板；硬约束与启发参考 MUST 截然分开（有不可妥协采信规则的领域硬约束单独成文，其余只作启发）；纯背景知识 MAY 独立成章；收束方式 MUST 因领域而异；启发提示 MUST 用软语气（「可以参考」「试试看」「不是必须步骤」），MUST NOT 写成结构要求。使用层指导（搜索策略——何时委派、拆不拆、怎么整合、跑多深、产出怎么用）MUST 与内容层方法分离成选读参考。技能内容 MUST 零跨技能引用——MUST NOT 硬编码指向其他技能名，任何「何时用本技能」的边界判断 MUST 自足表述。技能 MUST NOT 写 harness 机制——子代理任务书、调用、验收回传不进技能内容，只写编排策略。执行模式判定 MUST 以 if 链组织：有能力委派时——有主线话题且多轮搜索干扰大 → 完全委派；话题复杂 → 拆分委派（可中途改委派策略、动态响应）；否则 → 自行执行。

#### Scenario: 启发提示不写成要求
- GIVEN 某领域文档中的提示性建议
- WHEN 检查语气形态
- THEN 以软语气呈现，不写成「必须 / 禁止」类结构要求

#### Scenario: 跨技能指向即违规
- GIVEN 技能内容中出现指向另一技能名的依赖表述
- WHEN 检查引用
- THEN 判定违规，边界判断以自足表述给出，不指名其他技能

### Requirement: 术语表述
以下术语 MUST 精确且排他使用，MUST NOT 与近似概念混用。(1) **问题（Q）**：研究过程中产生、需要证据消解的研究子问询（原子问题），与「目标」「线索 S」「发现 F」并列。(2) **主题**：制定的可调查对象（研究什么），由用户的问题/意图转化而来；目标 = 主题拆出的研究维度；问题（Q）= 目标的原子问询。(3) **消解**：Q 的答案通过交叉验证变成 F/S、Q 消失——是转化，不是状态迁移。(4) **转化**：一个 Q 的答案让另一个旧 Q 过时，旧 Q 移除、换成更精确的新 Q。(5) **不可得**：某 Q 经实际调查确认无可达来源 → 产出可得性 F 的终态（可得性事实，逐 Q 判定）。(6) **收束**：Q-frontier 稳定化 → 循环全局停点，仍开放 Q 进报告「信息空白」（全局判定，区别于不可得）。(7) **排除**：某 Q 被判断不值得追或超出范围而关停（价值判断，区别于不可得）。(8) **搜索方法**：从话题到报告的整个研究过程（内容层）；**搜索策略**：如何使用本技能的指导（使用层），两者 MUST NOT 混称。SKILL.md MUST 用英文编写，references/ MUST 保持中文。

#### Scenario: 不可得与收束不混用
- GIVEN 报告「信息空白」一节中的某条目
- WHEN 检查其判定词
- THEN 用「收束后仍开放」表述，不写成「不可得」

#### Scenario: 方法与策略分称
- GIVEN 技能内容分别指称研究过程与使用编排
- WHEN 检查术语
- THEN 分别用「搜索方法」与「搜索策略」，不混称

### Requirement: 触发语义
description MUST 保持中英双触发面：核心名含中文面「深度调研」；when-to-use 用自然措辞——用户问法（查透 / 彻底了解 / 深挖等）与 agent 自问（是否值得深挖）；反向条件限一条（simple fact lookups，对应「不是快速查询」边界）。description MUST NOT 承载方法论流程名——Phase、clue-chain 等只作正文流程名，MUST NOT 占用匹配面（description 是选择层非方法层，纯方法论名词不产生触发信号）。

#### Scenario: 流程名不占匹配面
- GIVEN 本技能的 description
- WHEN 检查词汇构成
- THEN 只含业务措辞与触发面词汇，无 Phase、clue-chain 等方法论名词

#### Scenario: 中文问法可命中
- GIVEN 用户以「帮我查透 X」发起请求
- WHEN 判定触发
- THEN description 中文触发面命中，技能可被语义匹配选中
