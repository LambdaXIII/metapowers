# web-deep-research — 会话账本（domain-modeling 工作记录）

> 开发期会话账本：记录设计讨论中定案/澄清的术语与决策。决策正式载体为 `../SKILL-DESIGN.md`，本文保留决策来历。本文不随技能分发。

## 术语（本轮澄清）

- **搜索方法**：本技能指导的、从「话题」到「报告」的整个过程——Phase 0-4 方法论（明确话题 → 建立线索起点 → 追踪线索链 → 交叉比对 → 整理交付）。是技能的核心内容，现状已较完善。
- **搜索策略**：**如何使用本技能**（以及其中介绍的搜索方法）的指导——使用层/元层。与「搜索方法」（内容层）相对。为新增内容。
- **问题**：研究过程中产生、需要证据消解的研究子问询。与「目标」（Phase 0 固定的研究维度）、「线索」（待追踪来源）、「发现 F」（评估产出）并列的独立状态类别。**（定义待确认）**

## 已定案的决策

- **D-A1（Branch A 根决策）：把「问题」提升为一等公民状态。** 问题与线索 [S]、发现 [F] 并列，在 Phase 2/3 循环中流转；当研究成本达到一定程度（收束点）时，仍存留的问题随研究一起进入报告（报告模板已有「信息空白」章节作为承接）。此决策源于：方法层的改进应落在「结构机制」（Agent 无法可靠自造、需要技能命名的 artifact），而非「判断节点」（Agent 本可自行权衡的步骤）。

- **D-A2（Q 的演化模型）：问题 Q 是「原子问题」，问题集合是活的 frontier。** 目标在 Phase 0 分解为一组原子问题（Q1/Q2/Q3…）。循环中问题集合持续演化，存在三类变换：
  - **消解**：Q 的答案找到 → Q 变成 F（发现）+ S（来源），离开集合。绝不用「问题+答案」的持久化形式（用户明确否决：问题带答案留存会与 F/S 重复）。
  - **转化**：一个 Q 的答案让另一个旧 Q 过时 → 旧 Q 移除，可能换成更精确的新 Q（例：答了「X 是什么」得到产品定位，原「X 是什么市场」过时，换为「xx 产品属于什么市场」）。旧 Q 未成为 F，是被新知重构。
  - **新增**：研究推进中发现新线索/空白 → 生出新 Q。
  - Q 唯一持久化之处：收束时仍开放的问题 → 报告「信息空白」。
  - 三类状态完整（Q 瞬态 + S + F），无需新增分类。

- **D-A3（消解闸门 = 交叉验证）：Q 的消解门槛是该信息类型的交叉验证达标，不是"找到答案"。** 消解发生在 Phase 3（交叉比对），不在 Phase 2——Phase 2 只产出候选答案，Phase 3 验证后才转成 F；Q 在验证期间保持开放。单来源/未验证的答案不构成完整消解：重要 Q 保持开放补证，或以低置信度标注消解（F 标"单来源，未经交叉验证"，不能当结论支柱）。按类型的验证条沿用 Phase 3 现有机制（事实→置信度、数据→方法论、知识→系统性、意见→争议、经验→可迁移），不动。**新 Q 模型不消解 Phase 3 的作用，而是把它变成 Q 生命周期里的验证闸门。**

- **D-A4（不可得是独立终态，非收束推断）：**「不可得」（经实际调查确认无可达来源 → 产出可得性 F，Q 关闭）是**逐 Q、基于实际尝试**的可得性事实判定；「收束」（Q-frontier 稳定化 → 仍开放 Q 进「信息空白」，标注"还开放"，不是"不可得"）是**全局停点**。两者不交叉：循环无变化只能推出饱和（收束），推不出"这些 Q 不存在可达来源"。判定都是 Agent 判断，非固定计数规则。

## Branch B（搜索策略）设计约束（已定案）

- **B-C1：技能不能硬编码引用其他技能（§4.5 技能无硬性依赖）。**「进入决策」即使放 SKILL.md，也必须自足表述（如"多信源系统调查→适用；单点/无调查维度→过度"），**不指名任何其他技能**（web-entity-search、web-search-protocol 等一律不出现）。搜索策略 reference 同理，零跨技能引用。
- **B-C2：子代理调用机制（任务书怎么写、怎么调用、怎么验收回传）是 harness 的事，不是技能的事。** 搜索策略 reference 只装**编排策略**：何时委派（完全/部分/不委派）、是否拆分子话题、如何整合、跑多深、产出如何回灌。不写任何子代理调用/任务书/验收的机制细节。

- **B-D1（执行模式 if 链，用户原话）：**有能力委派时——①有主线话题、多轮搜索干扰大 → **完全委派**；②搜索话题比较复杂 → **拆分委派**（可中途改委派策略、动态响应）；③全否 → **自行执行**。以用户给出的 if 链为唯一权威版本，不再另拟。
- **B-D2（选读路由条件）：**`search-strategy.md` 的加载条件 = **有能力委派 或 话题不清晰时**读。（SKILL.md Content Index 据此写路由。）
- **B-D3（交付载体，用户新增「总的」条目）：**搜索方法本身不要求报告落盘为文件；但建议提前判断"是否有必要保存、存哪里"。委派子代理独立研究时，建议让子代理**直接把报告落盘**，主会话按需读取，不走对话交接。
