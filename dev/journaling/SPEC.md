# journaling

技能指导 agent 为自己的跨会话工作建立并维护一套长期记忆笔记库，使经验、决策、研究与方法论得以沉淀，后续会话可以接续上次的状态继续工作。

## 技能的指导性质

### 技能提供设计笔记库的指导

技能就「如何设计一个持续演化的笔记库」指导 agent，不直接定义笔记库的形态。agent 应当能够依据技能的指导，设计出自维护的笔记库。

### 技能把组织方式的决定权交给笔记库

分类方案、笔记字段、目录安排、入口页板块与维护约定由笔记库自己的规则文档决定，技能只规定笔记库必须具备的结构，不替它选择组织方式。agent 应当能够在规则文档中查到归属判断，不必回到技能里寻找分类答案。

## 技能机制

### 入口页可被发现

技能借助宿主侧提示文本，使 agent 在任何会话都能找到入口页；这条路径由技能提供，不写进笔记库的规则文档。

### 读写不对称加载

读取笔记库内容不加载本技能，任何改动笔记库的操作都加载本技能；这条分工由技能承担，笔记库设计者无法改变。

### 入口页是笔记库的唯一入口

每次操作都从入口页开始，agent 不绕过它直接读写条目。

### 规则文档是组织规则的唯一出处

规则文档必须存在，记录这套笔记库如何组织内容；技能提供的默认方案只在规则文档未覆盖某方面时生效。

### 每条笔记带 YAML 头

笔记文件以 YAML 头开始，承载标题、摘要等可检索字段。

### 技能不为自身机制留覆盖口

笔记库的规则文档只决定组织方式，不能取消或改写技能定下的机制；技能不为这些机制保留例外条款或开关，agent 在设计规则时无从绕过。

### 技能只对不可让步的机制使用强制措辞

分类方案、标签、目录结构、入口页板块与维护安排一律以建议措辞给出，不设必填字段，不假定某些目录存在。agent 应当能够分清哪些是技能定死的，哪些是自己可以改的。

## 加载与宿主提示词

### 触发以操作范围为界

技能的说明覆盖「凡对该笔记库的写入性操作」（创建、写入、编辑、收录、移动、归档、删除、维护），不列场景清单。agent 应当能够在任何写入请求下判定需要加载技能，而不依赖请求措辞是否被列举。

### 宿主提示词的改动归用户

把 agent 引向笔记库的注入文本（宿主提示词），agent 只能提案、提醒、编写草稿；写入或更改由用户执行，或经用户批准。agent 应当能够在发现注入文本有缺口时提出建议，不自行改写。

## 技能内容的写法

### 技能正文只承载操作事实

技能正文只承载运行时读者需要的操作事实与判断依据，不写文档自述、设计理由与权衡、变更沿革、写给未来编辑者的注记。agent 应当能够在正文中直接找到判断依据，不必先读设计说明。

### 维护以知识沉淀为主轴

维护的目标是整理与进一步沉淀知识，不是把文件改合规；合规只作交付检查的底线项。agent 应当能够在维护中先处理知识质量问题，而不是先跑格式检查。
