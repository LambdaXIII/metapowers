# web-deep-research

技能帮助 agent 从一个尚未确定的问题出发，经系统调查写出读者可以独立检验的报告。它规定调研怎么进行，不规定结论该是什么。

## 调研的边界

### 主题中立、不给决策建议

技能把用户提问提炼为中立的调研主题，不在结论里给决策指示或替调用方拍板——研究对象是主题，不是建议。agent 应当能够交出可供他人自行判断的报告。

## 问题集的演化

### 问题集只做三类演化

问题集里的每个问题只承载「还剩什么没答」，答案经交叉验证后转为附来源的发现并离开集合；演化限于消解、转化、新增三类，不以「问题 + 答案」的形式留存。agent 应当能够在任何时刻说清还剩哪些没答。

### 「不可得」与「收束」是两种停点

「不可得」须逐个问题经实际调查确认无可达来源；「收束」是问题集不再演化的全局停点，收束不能推断出「不可得」，收束时仍开放的问题如实进报告的信息空白。agent 应当能够区分哪一条问题查不到、哪一条只是没查完。

## 采信规则

### 采信按来源独立性判定

跨领域、跨语言、跨地区、跨立场的一致构成强验证；同机构、同作者、同引用源头、共同利益、同测量方法的一致不构成独立佐证。领域特化文档的采信规则优先于通用规则，冲突按领域规则执行。agent 应当能够判断两条来源算不算互相印证。

## 技能内容的组织

### 领域文档各自成文

每份领域文档按其研究对象的知识结构组织，不套统一模板；硬约束单独成文，其余只作启发，用「可以参考」「不是必须步骤」一类软语气，不写成「必须 / 禁止」的结构要求。agent 应当能够按领域的知识结构读文档，而不是按固定目录找。

### 使用层与内容层分册

委派、拆分、整合、落盘、跑多深、产出怎么用等使用层指导作为选读参考，不混入研究方法正文。agent 应当能够只读研究方法就完成调研。

### 技能内容自足

技能的边界判断只作自足表述，不指向其他技能名；也不写 harness 机制（子代理任务书、调用、验收回传），只写编排策略。agent 应当能够在不了解本仓库的情况下按技能执行。

## 何时加载技能

### 触发面覆盖问法与自问

技能的 description 覆盖用户问法与 agent 自问两路，不承载 Phase、clue-chain 等方法论流程名。agent 应当能够按任务性质判断是否加载。
