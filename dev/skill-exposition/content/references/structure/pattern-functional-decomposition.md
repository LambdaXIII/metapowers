# 能力树模式（functional-decomposition）

> 组织轴 = 能力层级：核心能力 → 主要功能 → 子功能，自顶向下。

## 模式定位

本模式按**能力层级**组织说明文——先把技能的本质用途凝练为一句"核心能力"，再自上而下拆成"主要功能"、"子功能"的能力树：

```
核心能力
├── 主要功能 A
│   ├── 子功能 A1
│   ├── 子功能 A2
│   └── 子功能 A3
├── 主要功能 B
│   ├── 子功能 B1
│   └── 子功能 B2
└── 主要功能 C
    └── 子功能 C1
```

层级关系有明确约束：层与层之间是**包含**关系，同层之间是**并列**关系，分解到可独立理解的最小单元。组织轴是"能力包含什么能力"，读者沿树自上而下定位任意功能。

## 适用情况

- 技能能力面宽、功能模块化清晰，能力之间可互斥地切分
- 读者可能只想了解"某个功能在哪"，需要快速定位而非顺序阅读
- 内容天然呈包含/并列结构——一组相互独立的功能模块，各自又有子操作

## 结构示意

```
1. 核心能力：一句话定义技能的本质用途
2. 主要功能：为实现核心能力所需的各功能模块（并列）
3. 子功能：每个主要功能下的具体操作（并列，拆到可独立理解）
```

章节顺序即树的自顶向下；每个功能节点配一句该功能的职责说明。

## 权衡与注意

- **树要求干净的层级**：能力之间纠缠时（一个子功能被多个主要功能共享，或功能间互相调用形成网状），强行成树会歪曲真实结构——忠实性受损，此时不宜选本模式
- **过深分解会失去教材感**：拆到很细的叶子后，说明文变成功能清单而非教学材料（可读性风险）。分解深度以"读者能独立理解一个节点"为限
- **缺"怎么配合"的盲区**：纯树只回答"有什么能力"，不回答"怎么组合使用"。树之外至少保留对核心能力的整体说明（对应学习路径的"这是什么"，见 exposition-guide.md 第 4 节），必要时补一段使用顺序
- **与 knowledge-types 的差异**：知识分类模式按**内容性质**分层（知识库/规则/流程/案例）；本模式按**能力包含关系**分层——前者回答"内容是什么类型"，后者回答"能力怎么构成"
- **组合建议**：与学习路径组合最常见——树的"核心能力"充当"这是什么"，功能细节充当"怎么用"；读者先看整体再沿树定位

## 示例说明

假想技能"文档翻译技能"：核心能力"把源文档翻译为指定语言"；主要功能拆为"准备输入（提取文本/校验格式）""执行翻译（调用模型/处理术语表）""交付输出（格式还原/校对）"；每个主要功能下再列各自的子功能。
