# 按知识类型分组模式（knowledge-types）

> 按**知识类别**组织内容：概念 / 程序 / 规则 / 案例 / 元认知分组呈现。可选用的组织方案之一，按需加载。

## 模式定位

组织轴是**知识类别**。技能的内容按所属的知识类型分组成章：概念知识（是什么）、程序知识（怎么做）、规则知识（什么时候做）、案例知识（具体例子）、元认知知识（设计思想）。分组是"抽屉"而非"链条"——章节之间顺序弱，读者可按需直接跳到要查的那一类。

## 适用情况

- 技能内容**类别界限分明**、体量大，按类别索引比按顺序通读更利于使用
- 读者以**有经验者**为主，知道自己要查什么（如只想核对一条规则），而非从头学起
- 技能本质是知识库 / 参考手册型，概念、规则、案例各自成块

## 结构示意

章节顺序（五类并非都必须出现，源中有什么就呈现什么）：

1. **核心概念**（概念知识）：术语定义、核心概念及其关系
2. **工作流程**（程序知识）：操作步骤、先后顺序、输入输出
3. **规则与边界**（规则知识）：触发条件、约束、阈值、例外
4. **典型示例**（案例知识）：场景—输入—输出的具体例子
5. **设计思想**（元认知知识）：设计理由、决策依据（推断按纪律标注，见 exposition-guide.md 第 3.3 节）

要点：

- 分类是组织工具，不是内容本身——某类知识在源中很少时，如实呈现少量内容，不要硬凑
- 类别内部仍需按学习逻辑排序（如规则章内先主规则后例外、流程章内按步骤顺序）
- 源中散落的内容先归类再入章，同一知识点的所有片段应聚合到对应类别

## 权衡与注意

- **何时不选**：技能是一条强顺序的流程链时，按类别切分会打断步骤之间的依赖关系——流程类技能更适合学习路径模式（learning-path）
- **与学习路径（learning-path）的差异**：learning-path 的章节是理解链条（先后强依赖、需通读）；本模式的章节是类别抽屉（顺序弱、可跳读）。零基础新手通读时 learning-path 更顺，有经验者查资料时本模式更快
- **组合使用**：可在每个类别章内部使用学习路径的子结构（如"核心概念"章内按从易到难排术语）；也可用分层披露（progressive-disclosure）控制每类知识的披露深度
- **风险提示**：五类标签不可机械套用——若技能内容无法自然归入这些类别（如纯指令型技能），硬分五章反而破坏可读性，应回到默认的学习路径模式

## 示例说明

假想技能「数据库备份」（db-backup）：**核心概念**（备份 / 快照 / 恢复点的定义）→ **工作流程**（配置 → 调度 → 验证）→ **规则与边界**（备份窗口、保留期阈值、失败重试次数）→ **典型示例**（夜间全量备份的输入与输出）→ **设计思想**（为什么备份与恢复分开设计）。
