# skill-exposition Specification

## Purpose

本域是技能阐述（skill-exposition）技能。Agent 技能把方法论封存在「执行指令形态」中，对 agent 高效，对人类不可直接学习、传承、批判。本技能把技能内容转化为**说明文教学材料**——完整、忠实地呈现为人类可读的形态，让人类通过阅读学会该技能。人类学会之后的应用、设计更好的技能，是学习的结果，不属于本技能范畴。

技能的独特增量是「阐述认知」——怎么想（梳理内容、识别阐述陷阱、组织教学知识），不是文档工程（怎么走流程、怎么写句子）。

## Requirements

### Requirement: 行为边界
本技能只读技能源文件，不修改源文件；不执行或测试被阐述的技能；不评价技能好坏。本技能止于产出教学材料——学习者学会后的应用与再创造不属于本技能范畴。

#### Scenario: 不碰源、不测技能
- GIVEN 一个技能包目录作为阐述对象
- WHEN 执行阐述
- THEN 源文件保持只读原状，未运行被阐述技能的任何流程

### Requirement: 输入与输出形态
输入是技能内容的一个子集，范围由用户指定——完整技能包、技能的部分方面、或多个技能（含跨技能方面，如「这几个技能的委派机制」）；不假定输入是一个完整技能。「技能」的判定标准是含 SKILL.md 的技能包目录。一个方面跨多个源文件分布时，梳理先在源中定位范围内内容的全部位置，再提取。输出形态按输入变化：单技能或单方面 → 单篇说明文（逻辑整体，超长可拆为章节文件但保持单篇逻辑）；多技能批量 → 每技能一篇；跨技能方面整合 → 单篇整合，每段标注来源技能。不恢复多目录文档包输出。

#### Scenario: 部分方面照样承接
- GIVEN 用户只指定某技能的一个方面（如委派机制）作为阐述范围
- WHEN 确定输入范围
- THEN 以该方面为范围，先定位其在源文件中的全部分布位置，不扩为整个技能

#### Scenario: 跨技能方面单篇整合
- GIVEN 用户要求阐述多个技能共有的某个方面
- WHEN 确定输出形态
- THEN 产出单篇整合说明文，每段标注来源技能

### Requirement: 三条硬约束
教学材料满足三条硬约束。(1) **忠实性**：完整、准确，不歪曲、不省略、不劣化源技能内容。(2) **可读性**：流畅、有条理，适合人类阅读。(3) **自包含性**：产物包含理解所需的全部前提与知识——含技能之外但叙述所需的内容（环境前提、外部概念、术语体系）；读者仅以产物为唯一依据；产物不反向链接到技能内部文件（如「详见 SKILL.md 第 X 节」）。

#### Scenario: 反向链接即违规
- GIVEN 一份产出的说明文
- WHEN 检查其中的引用
- THEN 不出现指向技能内部文件的引用或链接，理解所需内容全部在产物内

#### Scenario: 省略或劣化即违规
- GIVEN 源技能中的一条行为约束
- WHEN 检查产物的对应段落
- THEN 该约束被完整、准确地呈现，未被歪曲、省略或弱化

### Requirement: 边界模型——展开指导与效果提及
技能只展开指导三块认知内容：梳理（完整提取技能内容、理清结构，含源一致性矛盾裁决）、阐述陷阱、组织知识（教学逻辑——知识如何排序、分组利于学习）。界外内容（行文、质量检查、工程执行）只以效果提及存在——用「确保……」目标句句式声明要达到的效果，不展开 HOW；方法留给 agent 的通用能力。references/ 可承载界外内容的启发形态（如行文级技巧）——按需加载不构成展开指导。技能不引入流程工程（阶段、门禁、管道）。

#### Scenario: 界外内容展开即违规
- GIVEN 技能内容对「怎么写句子」给出逐步指导
- WHEN 检查边界模型
- THEN 判定违规，行文属于界外，只允许效果级提及

#### Scenario: 效果提及句式统一
- GIVEN 技能内容提及质量检查
- WHEN 检查表述形态
- THEN 以「确保……」目标句声明效果，不展开检查步骤、维度或停止规则

### Requirement: 阐述陷阱框架
阐述陷阱统一为四类框架，作为单一事实来源：内容失真（省略 / 歪曲 / 劣化 / 添油加醋）、视角漂移（阐述主题而非技能）、推断未标注、语体残留（认知面——把说明文写成指令复述，只指认知错误，句式机制不展开）。通用论述给出框架，general/traps.md 承载深化；同一纪律不在多处重复声明。新发现的陷阱先入 general/traps.md，稳定后再评估是否提升到通用论述的陷阱框架。

#### Scenario: 陷阱不在多处重复声明
- GIVEN 一条陷阱纪律
- WHEN 检查其声明位置
- THEN 只有通用论述的框架与 general/traps.md 的深化两层，不在其他文件重复

### Requirement: 参考文档定位与分工
通用论述（exposition-guide.md）自包含——提取基础、陷阱框架、默认结构方案、源一致性裁决纪律齐备——作为必读主入口。参考文档定位为「按需加载、提供启发、非必读」，只做类型提醒、模式手册、深化。

#### Scenario: 通用论述独立站住
- GIVEN 只读通用论述的读者
- WHEN 检查其内容构成
- THEN 提取基础、陷阱框架、默认结构方案、源一致性裁决纪律齐备，不依赖参考文档即可执行方法

### Requirement: 参考文档目录组织
参考文档按环节分三类目录，不按内容性质混放。(1) extraction/（内容提取，输入环节）——按技能内部的内容类型（工作流程型 / 知识库型 / 规则决策型 / 案例型 / 设计思想型）给提取提醒；内容类型是片段级判断，一个技能可同时含多种类型，不做技能级分类（如「纯指令型 / 混合型」）；extraction/ 文件只写该类型内容的提取注意点，不滑向行文指导。(2) structure/（结构规划，输出环节）——每模式一个文件、纯资料性质（参考手册），模式是备选组织方案，模式之间不形成流程依赖；新模式与现有各模式的组织轴不同才可加入，且注册到通用论述路由表并同步 SKILL.md 的路由引用。(3) general/（通用，全程）——横切提示（陷阱专项、边界情况调整、可读性强化、multi-skill 多技能专项）。

#### Scenario: 技能级分类即违规
- GIVEN extraction/ 下的参考文档
- WHEN 检查其分类依据
- THEN 按技能内部的内容片段类型组织，不对技能整体做类型判定

#### Scenario: 新模式须新组织轴
- GIVEN 计划新增一个结构模式
- WHEN 检查其组织轴
- THEN 与现有各模式的组织轴都不同，且已注册到通用论述路由表并同步 SKILL.md 的路由引用

### Requirement: 制式性内容呈现
templates/、examples/ 等制式性内容按价值所在决定呈现形态：价值在格式本身（规范性强的模板、清单、格式规范）→ 原样保留；价值在含义（叙述性示例、场景演示、用例说明）→ 转述为说明文语言。

#### Scenario: 模板保留、示例转述
- GIVEN 源技能中的一个填空模板与一段叙述性示例
- WHEN 转化为教学材料
- THEN 模板原样保留可复制使用，示例转述为说明文语言

### Requirement: 术语与语言表述
核心术语统一指称：**说明文**（交付物形态，exposition 即「说明文 / 说明性文体」义）、**教学材料**（说明文的实质身份——阅读后可理解并运用该技能）、**学习者**（教学材料的读者，目的是学会技能并应用，区别于泛指的「读者」）、**转化**（核心动作——保持内容完整的前提下，将技能从「执行指令形态」重组为「说明文形态」，重组是形式操作，内容一个不丢）、**忠实性 / 可读性 / 自包含性**（三条硬约束，见对应要求）。内容类型名与结构模式名是内部速记，出现在技能内容中时使用全称或首次定义。输出语言与学习者一致，术语首次出现附源语言原文；源内容混排语言时：专业术语（指称内容）保留原文并附学习者语言翻译，行文风格（叙述载体）统一为学习者语言，产物整体语言一致。

#### Scenario: 速记名首现须定义
- GIVEN 技能内容首次出现某结构模式名（如 iceberg）
- WHEN 检查该处表述
- THEN 附全称或定义（如「冰山模式——理解深度分层」），不裸用速记

#### Scenario: 混合语言源分流处理
- GIVEN 源技能内容中英混排
- WHEN 转化为面向中文学习者的材料
- THEN 术语保留英文原文并附中文翻译，行文统一为中文，产物整体语言一致

### Requirement: 触发语义
「技能」判定以含 SKILL.md 的技能包目录为准——不含 SKILL.md 的普通文档或代码库不触发本技能。触发面覆盖两类请求：(1) 用户请求将技能（或指定方面、或多个技能）阐述、整理为文档、生成方法论、输出为人类可读材料；(2) agent 在完成或遇到技能后自问「怎么把这个技能教给别人 / 怎么把它的知识提炼为人类可读材料」。反向条件：技能质量评审、评价、测试、创建新技能不触发本技能——那是其他工作的范畴。不确定时默认触发。

#### Scenario: 非技能目标不触发
- GIVEN 一份不含 SKILL.md 的普通文档请求转为说明文
- WHEN 判定触发
- THEN 不触发本技能

#### Scenario: 评审请求不触发
- GIVEN 用户要求评审或测试某技能的质量
- WHEN 判定触发
- THEN 不触发本技能，技能质量工作属于其他范畴
