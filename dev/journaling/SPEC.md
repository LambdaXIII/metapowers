# journaling 规格

本域是 agent 长期记忆笔记本系统的技能。journal 位于 `<journal-root>`，由 INDEX.md、RULES.md 与笔记条目构成；技能是设计指导，不是运行规程。

## 边界

- **运行细节归 journal 自身规则**：技能应当规定 journal 必须有的结构与机制，但不能规定任何具体 journal 的运行细节——分类方案、字段、目录、INDEX 板块、维护安排均由该 journal 自身的规则裁定。反例：「必须按 PARA 分类」「每条笔记必须填写 status 字段」。

## 硬性约束

- **硬性机制恰五项**：INDEX 的可发现性、读写不对称加载、INDEX 作为入口、RULES 作为规则的单一入口且必须存在、笔记文件含 YAML 段。其余一切机制只能以引导措辞出现，不得使用强制措辞、不得要求必填字段、不得断言特定目录存在。

## 触发

- **以操作范围为界**：description 应当以操作范围为界（凡对 `<journal-root>` 的写入性操作），但不能退回场景枚举；保留中英文操作动词的触发面。

## 权限

- **宿主提示词只提案**：agent 对宿主提示词（注入文本所在的载体）只能提案、提醒、编写草稿；写入或更改应当由用户执行，或经用户批准后执行。反例：agent 自行改写宿主提示词。

## 内容形态

- **内容边界**：技能内容应当只承载运行时读者需要的操作事实与判断依据，不能承载文档自述、设计理由与权衡、历史叙事、写给未来编辑者的注记。
- **维护以知识为主轴**：维护的主轴应当是知识的整理与进一步沉淀，不能是形式合规；合规只作交付检查的底线项。
