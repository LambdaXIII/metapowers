# 案例型内容的提取提醒

> 梳理时遇到示例类内容时按需加载。本文只讲「怎么提取不失真」；怎么写进说明文由你自行发挥（行文见 general/readability.md）。

## 这是什么

**定义**：技能中演示「怎么用」的内容——示例、场景、输入输出对、模板填充样例。

**识别线索**（读到以下任一即属此类内容）：

- 「例如」「比如」「示例」「场景」
- 代码块、JSON 片段、模板填充样例
- 输入 → 输出的配对展示
- 「典型」「边界情况」「极端情况」等标注
- examples/ 目录下的文件、templates/ 中的填充示例

示例是学习者「照做」的模板，也是规则最具体的证据。案例型内容的失真常表现为「抽象化」——具体值被抹成泛指，示例失去了可复现性。

## 提取注意点

1. **场景-输入-输出的完整对应**。
   注意：每个示例的场景（在什么情况下用）、输入（给了什么）、输出（得到什么）三者齐备且一一对应，不拆分、不嫁接。
   为什么：示例的教学价值在完整链路，缺环 = 学习者无法复现。

2. **参数具体值原样保留**。
   注意：示例中的数字、名称、字段名、占位符替换规则都不改。
   为什么：具体值是示例的「可执行细节」，抽象化（把「500」写成「一个数」）会让示例失去示范作用。

3. **示例前提条件保留**。
   注意：示例开头交代的前提（「前提：已安装 X」「在 … 目录下运行」）跟着示例提取。
   为什么：前提是场景的一部分，丢掉前提，学习者照做会在第一步就失败。

4. **典型性标注跟着示例走**。
   注意：源中对示例的定性（典型/常规/边界/反例）原样保留，不自行给示例贴「典型」标签。
   为什么：典型性标注是源作者的教学信号，学习者据此判断示例的适用范围；自行标注 = 添加源里没有的断言（内容失真）。

5. **示例与规则的对应关系明确**。
   注意：每个示例演示/证明哪条规则，按源对应，不张冠李戴。
   为什么：示例是规则的证据，错配会让学习者从示例推出错误规则。

6. **示例完整性——不挑拣**。
   注意：用户指定范围内的示例全部提取，不因「示例太多」自行选代表。
   为什么：忠实性要求完整呈现；挑拣 = 省略源内容。

7. **反例（负面示例）同等重要**。
   注意：「不要这样做」的例子与正面示例一样提取。
   为什么：反例定义边界，学习者靠反例学会「什么不能做」。

8. **占位符与真实值都保留**。
   注意：示例里的占位符（如 `<skill-name>`）与真实填充值原样，不互相替换。
   为什么：占位符是模板的一部分，改动会破坏示例与模板的对应。

9. **示例归属标注**。
   注意：多技能场景下，每个示例归属哪个技能要标注，不张冠李戴。
   为什么：归属纪律防止内容错位（见 general/multi-skill.md）。

## 常见失误

- **反例 1**：示例只有输入和输出，场景（在什么任务中用到）被省略，读者不知道示例何时适用。
- **反例 2**：把示例中的具体值「3 个并行子代理」抽象成「若干子代理」。
- **反例 3**：把源里标注「边界情况」的示例与常规示例混在一起，无差别呈现。
- **反例 4**：示例本意是演示「何时不触发」，却被放到「触发流程」的示例位置——示例与规则错配。

## 自查提示

- 每个示例的场景、输入、输出三要素都在吗？它们的对应与源一致吗？
- 示例中的具体值（数字、名称、字段）都原样吗？
- 源中的典型性标注（典型/边界/反例）都保留了吗？有没有我自行添加的定性？
- 每个示例都能指认出它演示的规则吗？
- 示例的前提条件（「前提：…」）都跟着示例走了吗？
