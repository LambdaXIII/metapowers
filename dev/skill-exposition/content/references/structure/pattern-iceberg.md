# 理解深度分层模式（iceberg）

> 组织轴 = 理解深度：现象/行为 → 模式 → 结构 → 心智模型，由表及里。

## 模式定位

本模式按**理解深度**组织说明文——内容从水面之上的"现象/行为"逐层下沉到水面之下的"心智模型"：

```
        ↑ 水面 ↑
    ┌─────────────┐
    │ 现象/行为   │  看得见：技能做了什么
    ├─────────────┤
    │ 模式        │  可察：反复出现的行为规律
    ├─────────────┤
    │ 结构        │  可推：技能如何组织、如何运作
    ├─────────────┤
    │ 心智模型    │  深层：为什么这样设计
    └─────────────┘
```

每层回答一层问题：做什么（现象）→ 反复怎么做（模式）→ 靠什么组织起来（结构）→ 为什么（心智模型）。读者先看到可观察的事实，再逐层获得解释，理解随阅读由表及里加深。

## 适用情况

- 技能内容存在真实的"由表及里"层次：表层行为可被直接观察，深层机制值得单独解释
- 设计思想（心智模型）是技能的重要部分，且需要前置的行为/模式/结构作铺垫才讲得清
- 读者对象既需要"会用"（前两层）也需要"看懂为什么"（后两层），希望一层层进入

## 结构示意

```
1. 现象与行为
   技能做了什么：可观察的操作、输入输出、执行步骤
2. 模式
   反复出现的方法与套路（如"先检查再执行"、"每步输出中间结果"）
3. 结构
   技能如何组织：文件结构、模块依赖、数据流、阶段划分
4. 心智模型
   为什么这样设计：核心假设、取舍、价值观（推断按 3.3 标注）
```

## 权衡与注意

- **分层要有实据**：本模式要求内容确实存在可分的理解深度。技能没有深层设计思想时，硬凑"心智模型"层会编造源中没有的内容，违反忠实性——此时不应选本模式
- **与 progressive-disclosure 的差异**：两者都分层，但分层依据不同——渐进披露按**阅读时间**分（读者按进度逐步接触内容，未准备好时不暴露）；冰山按**理解深度**分（内容本身由表及里排列）。可组合使用：冰山决定层序，披露控制每层何时向读者露出
- **与 learning-path 的关系**：学习路径（默认模式，见 exposition-guide.md 第 4 节）排序服务于"先概览后细节"的学习顺序；冰山强调纵深——后层是前层的解释而非细节，两者思路不同但可互相借鉴
- **篇幅风险**：只关心"怎么用"的读者可能在前两层就满足，深挖会增加篇幅。若大部分读者止步于行为层，说明本模式不适合该交付物

## 示例说明

假想技能"会议纪要技能"：第 1 章列它做什么（读会议记录、抽决议、生成纪要）；第 2 章归纳反复出现的"先抽取后格式化"套路；第 3 章讲它的模板与 references/ 如何组织；第 4 章讲"纪要必须可追溯"这一设计假设。
