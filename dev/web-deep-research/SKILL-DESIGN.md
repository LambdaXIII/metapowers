# web-deep-research — 设计说明

> 设计锚定文档。记录技能的**设计意图、设计目标、关键架构决策（含理由）、措辞风格约定、维护注意事项**。
> 读者是**维护这个技能的开发者**，不是运行时 agent（运行时 agent 读 `SKILL.md`）。
> 本文不含：版本历史、决策过程的历史记录、随时变化的路由/文件清单、SKILL.md 已有的触发规则与执行流程。

## 设计意图

这个技能解决一个问题：**「我要把这个话题研究透——怎么系统地逼近真相？」**

它不解决"怎么搜得快""怎么用某个工具""怎么判断一条信息准不准"——那些是工具使用指南和评估方法论的事。它解决的是**研究本身的流程设计**：从明确意图，到收集线索，到交叉比对，到交付一份结论可由读者独立检验的报告。

## 设计目标

三个约束定义技能的边界（同时是触发判定的依据）：

1. **不是快速查询工具**——单点事实查询不需要 Phase 结构
2. **不是工具选择指南**——搜索工具的选择是另一个技能的事
3. **不是纯咨询**——"你觉得我该怎么做"如果没有多信源调查维度，就不是研究

## 关键架构决策

### Phase 0-4 流程：收集和评估严格分离

**决策**：Phase 2（纯收集，记录 URL）和 Phase 3（按信息性质评估）之间有一条硬边界。

**理由**：Agent 在收集信息时最容易犯的错是过早下判断——"这条看起来不可靠，跳过"或者"这个说法很有道理，当成事实"。分离收集和评估迫使 Agent 先完整收集再统一评估，避免锚定效应。

**取舍**：这比"边搜索边判断"慢得多，Token 消耗也更大。所以文档开头声明"Use when thorough investigation matters more than speed"。

### 问题集（Q-set）模型：研究的驱动结构

**决策**：把「问题」提升为与线索 [S]、发现 [F] 并列的一等公民状态（Q-set）。问题集是活的 frontier——Phase 2/3 循环由它驱动，而非由线索驱动。

**理由**：方法层的改进应落在**结构机制**（Agent 无法可靠自造、需要技能命名的 artifact），而非**判断节点**（Agent 本可自行权衡的步骤）。现状循环靠线索驱动，但"还差什么没答"没有显式载体——Agent 容易丢"我还没解决哪个问题"。把问题状态化，是给这个循环一个可追的结构。

**关键子决策**：

- **Q 是原子问题**，不是目标的分片。目标在 Phase 0 分解出初始 Q 集；循环中 Q 集演化——**消解**（Q→F/S，答案离开 Q）、**转化**（旧 Q 因新知过时→换成更精确的新 Q）、**新增**（新线索生出 Q）。
- **绝不用「问题+答案」的持久化形式**：答案一旦成为发现就转成 F 离开 Q，Q 只存"还剩什么没答"的开放感，不存答案。
- **消解闸门 = 交叉验证**：消解发生在 Phase 3（交叉比对）——该信息类型验证达标才转 F；单来源/未验证的答案不构成完整消解。Q-set 模型不消解 Phase 3 的作用，而是把它变成验证闸门。
- **不可得 ≠ 收束**：「不可得」是逐 Q 判定（经实际调查确认无可达来源 → 产出可得性 F）；「收束」是全局停点（Q-frontier 稳定化 → 仍开放 Q 进报告信息空白）。两者不交叉。

### 搜索策略参考：使用层与内容层分离

**决策**：新增选读参考文档（`search-strategy.md`），承载「如何使用本技能」的编排策略（执行形态、交付载体），与内容层（Phase 0-4 方法）分离。

**理由**：使用决策（何时委派、拆不拆、怎么整合、产出怎么用）与研究方法论是两个层面——混在一起会干扰方法主线；选读定位让它按需加载，不占主上下文。

**约束**：

- **零跨技能引用**：技能不能硬编码指向其他技能（§4.5 技能无硬性依赖）。任何"何时用本技能/何时用别的"的判断都自足表述，不指名其他技能。
- **不写 harness 机制**：子代理调用（任务书怎么写、怎么调用、怎么验收回传）是 harness 的事，技能不写。技能只写编排策略（何时委派、拆不拆、怎么整合）。
- **执行模式 if 链是组织原则**：有主线话题/多轮搜索干扰大 → 完全委派；话题复杂 → 拆分委派（可中途改委派策略、动态响应）；否则 → 自行执行。

### 领域特化文档：各走各的路

**决策**：每个领域参考文档的组织逻辑由该领域的研究对象决定，不套统一模板。

**设计原则**：

- **先问"这个研究对象的知识结构是怎样的"**——人物适合叙事逻辑、法规适合规范层次、创意作品适合客观性梯度。硬套不对的轴线会出问题。
- **硬约束和启发参考要截然分开**——法规有不可妥协的采信规则；大部分领域只需要启发。
- **纯背景知识可独立成章**——不属操作指引。
- **越详细越需要收束，但收束方式因领域而异**——创意作品收束主观维度、法规收束"从圆心走多远"、学术收束"不深挖单点"。
- **文档长度和领域复杂度匹配**，不削足适履。
- **启发提示用软语气**（"可以参考""试试看""不是必须步骤"），不写成结构要求。

（各领域文档的具体组织逻辑与独特设计，见 `SKILL.md` Content Index 及各文档自身——此处不维护随时变化的路由细节。）

### 来源类别命名：两种逻辑

**决策**：不同领域适用不同的来源组织方式。

- **按信息生产者（"谁说的"）**——适用人物和创意作品研究：同一事实来自"自述""同时代见证""学界评价"性质完全不同。
- **按信息需求（"去哪儿找什么"）**——适用法规研究："条文的唯一来源是官方数据库"比"全国人大发布的信息"更直接有用。
- **学术研究不适合按来源分类**——跨学科、跨来源性质差异太大，按"获取途径"（摘要、综述、同行讨论）组织更实用。
### 主题制定：研究主题与用户的问题分离

**决策**：Phase 0 新增「主题制定」——研究的对象是**主题**（可调查对象），不是用户的问题本身。技能**不控制研究启动决策**；技能被加载时研究意图已定，职责是把意图制定成中立、可研究的主题。

**理由**：触发/委托决策发生在主会话（agent 基于对话上下文判断是否需要研究），技能文档无法也不应规定"什么输入触发"——决策型问句（"该不该换 Rust"）可被主会话合法委托为对比研究，按问句形式判定输入是错误的（曾试图加"触发闸门"，撤销）。技能该管的是主题的质量：中立（无倾向性，决策意图转为考察型）、可研究、服务于主会话话题。

**关键子决策**：

- **主题 ≠ 用户的问题**：用户的问题（要不要换）是主会话的决策，研究不替它作答——结论支撑决策，决策权在用户。
- **目标清单与问题拆解基于主题展开**，而非用户的原话。
- **核心关切 vs 支撑性论据**：主题制定时区分两者——核心关切（评价校准：用户真正想问"配不配/值不值"）保留为考察框架；支撑性论据（用户用来质疑的具体理由，如"相比更年长导演没突出之处"）纳入相关维度而非升格为独立目标。去倾向 ≠ 去维度；若核心关切本身是具体对比，对比基准必须保留。理由：真实对照实测——把支撑性论据升格为独立目标会扩大探查范围（18 来源/20min vs 12 来源/15min），而聚焦处理结论质量相当且更直接回应核心关切。

### 验证强度 · 来源独立性

**决策**：Phase 3 消解闸门新增双向原则——交叉验证的效力取决于来源独立性：**差异增强**（跨领域/语言/地区/利益立场的一致是强验证）、**关联削弱**（同机构/同作者/同引用源头/共同利益/同测量方法的一致是伪验证）。

**理由**：既有"一条学术论文+两条个人博客≠三方确认"只覆盖权威性维度；实测（S01）发现同机构市场报告与分析预测方向一致被当作独立佐证。独立性是「来源独立于结论」原则在来源间关系上的延伸。

### 领域特化规则优先

**决策**：领域文档定义的采信规则优先于 workflow 通用规则（policy-law 条文采信硬约束等）。

**理由**：实测（S02）发现通用「单来源不赋置信度」与领域「官方原文单源可采信」冲突时无仲裁声明，执行者被迫自行裁决。

### 输出形态缩放

**决策**：Phase 4 按问题类型与用户预期选择交付形态——完整报告 / 决策简报 / 精选列表，内部流程不变。

**理由**：误触发时完整报告过重；creative-work 已有「精选列表」先例未泛化。形态缩放降低误触发成本，与主题制定（决策委托研究）配套。

## 措辞风格约定

以下术语在技能内容中必须精确且排他使用，避免与近似概念混用：

- **问题（Q）**：研究过程中产生、需要证据消解的研究子问询（原子问题）。与「目标」（Phase 0 固定的研究维度）、「线索 S」（待追踪来源）、「发现 F」（评估产出）并列，**不可混用**。
- **主题**：Phase 0 制定的可调查对象（研究什么），由用户的问题/意图转化而来——中立、可研究、与用户的问题分离。目标 = 主题拆出的研究维度；问题（Q）= 目标的原子问询。
- **消解**：Q 的答案通过交叉验证 → 变成 F/S，Q 消失。是**转化**，不是状态迁移。
- **转化**：一个 Q 的答案让另一个旧 Q 过时 → 旧 Q 移除，换成更精确的新 Q。
- **不可得**：某 Q 经实际调查确认无可达来源 → 产出可得性 F 的终态（**可得性事实**，逐 Q 判定）。
- **收束**：Q-frontier 稳定化 → 循环全局停点，仍开放 Q 进报告「信息空白」（**全局判定**，区别于不可得）。
- **排除**：某 Q 被判断不值得追/超出范围 → 关停（**价值判断**，区别于不可得的可得性事实）。
