# 评估一个没用过的技能

对象是一个已存在、但你还没用过的技能——可能是用户问「这个技能怎么样」，也可能是几个候选里要挑一个。这个检查叫**预评估**：在还没有任何实际使用经验时，对它做一个有依据的判断。你手里可能已有它的全文（装了没启用，或直接拿到了技能目录），也可能只有介绍信息；下面的方向对两种状态都适用，证据有多少算多少。

这里给的是评估的提示：看哪些方向，怎么让结论站得住。评估的结果怎么用——采纳与否——是评估之后的决定，不归这里；预评估的产出只是那个决定的输入。而采纳是可逆的，用一次不满意就能放弃，所以预评估保持轻量，粗略是形态而不是缺陷。要修它的是[审查](skill-review.md)；刚用过它、要回顾实际表现的，是[评估一个刚用完的技能](skill-post-assessment.md)；自己写的技能要交付，验零上下文能不能用起来的，是[快速测试](skill-quick-test.md)。

## 评估的方向

- **内容**——能读到内容时，对照着读：入口的 SKILL.md 是承诺最集中的地方，支撑文件抽查入口最倚重的那份就够；description 承诺的能力逐条到正文里找对应物，判据是可检查的，还是一句程度话。承诺与内容的落差一旦确定，结论已成立，不必穷尽全文。只有介绍信息时，能看的是承诺本身：具体的承诺（做什么、给谁用）比空泛的宣称可信。介绍写得漂亮是它的本职，不是质量的证据。
- **来源**——出自谁手，作者还做过什么。已经用过的作者，上次用下来的实际表现直接算数。
- **活跃度**——还在不在维护。不再维护的技能，内容再好也会随环境慢慢失效。手头证据里能有的只是弱信号：最近更新只说明最后一次有人碰它，说明不了持续维护。
- **知名度**——多少人在用，别人怎么评价。留意：他人的好评回答的是他的任务，与你要做的事对不上时不作数。
- **合身**——它对你要做的事、你的环境覆盖到什么程度。有用、全面、准确、清晰四判据按用途加权：当操作指导用的，全面与清晰要紧；当判断依据用的，准确要紧。没有具体任务时，按四判据给通用判断，并说明判断的适用范围。质量再高，覆盖不到你的任务，价值就有限。
- **已有**——对照自己的技能清单：是不是已经有覆盖同一能力的——类似的、重复的、或更好的。有，评估的重心就移过去：重叠的部分不必再评，要看的是差异，它比你已有的多什么、强在哪。
- **代价**——采纳之后持续的负担：介绍文本从此常驻每次会话，多一份要信任的指令来源。这是事实面；值不值，由后面的决定去权衡。

每条方向都要落到有依据的结论上：理由指得回证据——哪个方向、看到了什么。口味不算数。

## 几个技能选一个

用同一组方向并排比：先想清楚这次要紧的是哪几个方向，再看每个候选在这些方向上的强弱。比较的产出是强弱对照——谁在要紧的方向上有实际内容，谁只有宣称。怎么取舍，是比较之后的决定。

所有方向加起来，也换不来只有实际使用才能给出的信息——那是使用之后的事。
