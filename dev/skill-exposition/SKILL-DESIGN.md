## 设计意图

**技能是"方法论的可执行载体"**：一个 agent 技能把设计方法论（流程、决策规则、质量机制、设计理由）封存在执行指令形态中。这种形态对 agent 高效，对人类不可直接学习、传承、批判。

本技能解决这个问题：产出**说明文教学材料**，把技能内容完整、忠实地呈现为人类可读的形态，让人类通过阅读学会这项技能。人类学会后可应用、可设计更好的技能——这是学习的结果，不属于本技能范畴。

**设计教训**（本技能规避的反模式，设计依据）：
- 指导层面错误：流程工程与行文规范占据指导主体，而 agent 的通用能力已覆盖这些；技能的独特增量是"阐述认知"（怎么想），不是工程（怎么走流程）
- 参考文档重度冗余：阶段文件逐条复述框架文件，同一约束多处声明
- 过工程化：技能级分类、类型自适应、输出形态铁律
- 输出形态错误：四目录文档包（README/methodology/reference/meta）服务于"查阅"而非"学习"
- 命名不规范：使用非英文词或与定位不符的隐喻词

## 设计目标

- **边界**：指导 agent 的"阐述认知"——梳理内容、阐述陷阱、组织知识；对文档工程（行文、流程执行、质量检查方法）只做效果级提及
- **结构**：遵循 AGENTS.md §4.8「SKILL.md 入口化」——SKILL.md 极简（触发 + 路由），方法主内容在通用论述，参考文档按需加载、提供启发
- **交付物**：单篇说明文（按输入形态变化），忠实性 + 可读性 + 自包含性为三条硬约束（从"学会"目的直接推出）
- **输入**：不假定完整技能——完整技能包 / 技能部分方面 / 多技能（含跨技能方面）皆可

## 关键架构决策

### 1. 边界模型：展开指导 / 效果提及

技能展开指导界内三块（梳理、陷阱、组织）；界外内容（行文、质检、工程执行）只以效果句存在——声明要达到的效果，HOW 留给 agent 的通用能力。

**为什么**：把大量篇幅用于指导 agent"怎么走流程、怎么写句子"是常见失败——这些是 agent 通用能力已覆盖的领域；真正只有本技能能提供的增量是"如何阐述"的认知指导。界外内容展开指导 = 重复造轮子 + 流程捆绑。推论：技能正文很短，由"三块展开 + 几个效果句"构成。

**边界细则**：references/ 可以承载界外内容的启发形态（如 readability 的行文级技巧）——按需加载不构成展开指导。

### 2. 输入范围不假定完整技能

输入是技能内容的一个子集，范围由用户指定：完整技能包、技能的部分方面、或多个技能（含跨技能方面，如"这几个技能的委派机制"）。

**为什么**：用户实际需求覆盖全部四种形态；方面可能跨多个源文件分布，梳理必须先"定位分布"再提取，不能假定"读整个技能包"。

### 3. 内容类型 = 片段级，非技能级分类

extraction/ 参考按**技能内部的内容类型**（工作流程型/知识库型/规则决策型/案例型/设计思想型）给提取提醒；一个技能可同时含多种类型，遇到哪类内容就加载哪类提醒。

**为什么**：技能级分类（纯指令型/混合型）需要阈值判定（知识占比 >80%），无法操作且衍生出类型自适应机制，是过工程化的重灾区。内容类型是提取时的即时判断，不预设技能整体属性。分类法继承 knowledge-types 五分类（概念/程序/规则/案例/元认知），但用法从"给技能分类"改为"按片段识别"。

### 4. 结构模式手册化

structure/ 每模式一个文件，纯资料性质——模式是备选组织方案，agent 选中哪种翻哪本。定案 8 个模式（组织轴各异：使用顺序/原理顺序/知识类型/阅读时间/理解深度/读者场景/维度覆盖/能力树），全部保留独立；金字塔原理为横切行文原则，并入 general/readability.md。

**为什么**：五框架（黄金圈/5W1H/冰山/功能分解/金字塔）若作为"理解框架"使用价值有限（易被逐条复述成冗余），但其核心概念是合法的**组织模式**素材——不作废，按"模式手册"框架（适用情况/结构示意/权衡）重写。模式之间不形成流程依赖，agent 自由选择。

### 5. 输出 = 单篇说明文（逻辑整体）

单技能/单方面 → 单篇；多技能批量 → 每技能一篇；跨技能方面整合 → 单篇整合（每段标注来源技能）。不恢复旧四目录文档包。

**为什么**：教学材料服务于"学习"——从头读到尾、循序渐进；四目录文档包（README/methodology/reference/meta）服务于"查阅"——按需跳转。学习型交付物拆成参考手册形态是形态与目的的错配。超长时可拆章节文件，但保持单篇逻辑。

### 6. 语言 = 学习者语言

输出语言与学习者（用户）一致，术语首次出现附源语言原文。

**为什么**：教学对象是学习者；"语言锁定源语言"是查阅型文档思维（文档与源对应），教学型文档应对学习者。术语附原文是忠实性的补偿机制——翻译不改变术语指称。

源内容本身混排语言时（如中文叙述夹杂英文整节），先识别性质：**专业术语** → 保留原文并附学习者语言翻译；**行文风格**（叙述、句式所用的语言）→ 统一为学习者语言——产物整体语言必须一致。

**为什么**：产物是给学习者读的教材，叙述语言不一致打断阅读；术语是内容指称，保留原文是忠实性补偿（同上）。判断标准是"这段文字的性质：指称内容，还是叙述载体"。

### 7. 陷阱统一为四类框架

内容失真、视角漂移、推断未标注、语体残留（认知面）。旧分散资产（反模板检查、身份保真、推断边界表）整合进统一框架，各自带自查句。

**为什么**：同一纪律曾在多处声明（形态铁律四处重复），导致维护与执行双重混乱。统一框架后，通用论述给框架，general/traps.md 给深化，单一事实来源。

### 8. 产物自包含、不反向链接

产物包含理解所需的全部前提与知识——含技能之外但叙述所需的内容（环境前提、外部概念、术语体系）；读者仅以产物为唯一依据；产物绝不反向链接到技能内部文件（如"详见 SKILL.md 第 X 节"）。

**为什么**：学习者拿到的是说明文，不是技能源文件——读者不应也不需要访问技能内部来理解材料。反向链接让产物退化为"索引"而非"教材"；自包含是"学会"目的的直接推论（学员手里只有材料）。

### 9. 制式性内容：原样保留 vs 转述

templates/、examples/ 等制式性内容先判断呈现形态：内容价值在**格式本身**（规范性强的模板、清单、格式规范）→ 原样保留；内容价值在**含义**（叙述性示例、场景演示、用例说明）→ 转述为说明文语言。

**为什么**：模板/清单的价值在精确格式，转述会损失规范性（学习者需要可复制的东西）；叙述性示例的价值在内容含义，转述成说明文语言符合可读性要求。判断标准是"价值在格式还是含义"。

## 措辞风格约定

- 正文与参考文档用简体中文；术语（阐述/说明文/忠实性/可读性/自包含性/学习者/梳理/组织）定义见 research/CONTEXT.md，全文统一
- 参考文档定位表述统一为"按需加载、提供启发、非必读"
- 效果提及统一用"确保……"目标句句式，不展开方法
- 内容类型名（工作流程型等）与模式名（learning-path 等）是内部速记，出现即用全称或首次定义

## 维护注意事项

- **不变量**：不引入流程工程（阶段/门禁/管道）、不引入技能级分类、不恢复四目录输出结构、不在界外内容上展开指导、产物不反向链接技能内部文件（自包含性）。违反任一 = 设计回归
- **陷阱清单是活的**：新发现陷阱先入 general/traps.md，待稳定后再评估是否提升到通用论述的陷阱框架（避免通用论述膨胀）
- **模式增补纪律**：新模式必须与现有 8 模式组织轴不同才可加入；新增后注册到通用论述路由表（见 AGENTS.md §4.7 路由表维护）
- **内容类型文件纪律**：extraction/ 文件只写"该类型内容的提取注意点"，不得滑向行文指导（行文归 general/readability.md）
- **源一致性**：修改任何参考文件时只在各自范围内修改；路由表变更同步更新 SKILL.md 与通用论述两处引用
