# 交互流程推演
> 场景文档 — 载体符合时必读。按 `../rehearsal-guide.md` 的路由指引加载。

将 rehearsal（推演）方法应用于任何**交互流程**的验证。适用于：
- UI 界面：Web/移动端/桌面应用的界面和交互
- CLI 程序：命令、参数、输出、管道组合
- 表单流程：多步骤填写、校验、提交
- 操作序列：任何需要按特定顺序执行的动作关联

不适用：纯文档阅读（→ `doc-guide-rehearsal.md`）、API 调用（→ `api-design-rehearsal.md`）、代码执行逻辑（→ `logic-chain-rehearsal.md`）。

---

## 客体定位

操作者——第一次接触这个交互的接收方。没有作者/设计者的知识，不知道任何功能在哪里，不知道正确的操作流程，不知道错误发生时的下一步。

初始状态：
- 知道目标（"我要完成 X"）但不知道怎么做
- 首次看到界面/收到第一个命令提示
- 没有预先知道功能位置或命令名称

## 交互模式

根据交互媒介分为两个模式。两种模式共享核心流程，在信号类型上不同：

| | UI 模式 | CLI/程序模式 |
|---|---|---|
| 主要信号 | 视觉可发现性、困惑点、放弃点 | 命令可记忆性、参数合理性、输出清晰度 |
| 失败表现 | 不知道这里能点击、看不懂图标 | 不知道命令名称、参数错误无指引 |
| 恢复方式 | 返回按钮、关闭、尝试别处 | 读 man/help、猜参数名、放弃 |
| 放弃诱因 | 太多选项、不知道下一步 | 命令名称不可记、错误信息不可操作 |

## 四步流程

> 推演前先完成通用论述中的「作者视角」和「清空」步骤。

### 1. 清空

参照通用论述的「作者视角」和「清空」步骤：

1. **回看作者视角**：确认你在推演前已写下「这份交互的目标操作者是谁、期望达到什么效果」。
2. **设定阅读身份**：你是操作者——知道目标（「我要完成 X」）但不知道怎么做。没有预先知道功能位置或命令名称。
3. **显式清空**：扔掉设计者知识——不知道哪个按钮最重要、不知道这个功能的快捷键、不知道菜单的层级结构。只带操作者的初始状态和目标进入。

### 2. 逐帧跟

按操作顺序逐步走。每步记录：

**通用信号（所有交互）：**

| 信号 | 含义 |
|------|------|
| "这里停住了" | 不知道为什么不能前进 |
| "这里不知道该做什么" | 缺少明确的下一步引导 |
| "这里想放弃" | 挫折感累积达到放弃阈值 |
| "这里走错了" | 被误导或误解了上一步的结果 |

**UI 特定信号：**

| 信号 | 含义 |
|------|------|
| "没看到这个按钮/入口" | 视觉层次问题——关键元素不够突出 |
| "这个图标不知道是什么意思" | 缺少文字标签或 tooltip |
| "这个流程比预期长" | 放弃率上升点——需要进度提示 |

**CLI 特定信号：**

| 信号 | 含义 |
|------|------|
| "这个命令记不住" | 命名不直观——无法自然推断 |
| "参数格式不确定" | 缺少清晰的示例或 --help 不够详细 |
| "错误信息不知道什么意思" | 需要外部查询——错误信息不可操作 |

### 3. 边界刨

**通用边界：**

| 场景 | 检查目标 |
|------|---------|
| 跳过某步直接到下一步 | 引导是否依赖线性顺序？跳步者是否迷路？ |
| 从中间进入 | 非预期入口的上下文是否充足？ |
| 操作错误后尝试恢复 | 错误状态是否清晰？恢复路径是否存在？ |
| 第 N 步放弃后重新回来 | 状态是否保留？是否需要重新开始？ |

**UI 特定边界：**

| 场景 | 检查目标 |
|------|---------|
| 不同屏幕尺寸/设备 | 响应式布局下功能和信息是否保持可发现 |
| 失焦/切屏后回来 | 状态保留和重新定位体验 |
| 网络中断/超时 | 错误信息和重试流程 |

**CLI 特定边界：**

| 场景 | 检查目标 |
|------|---------|
| 不同 shell/OS 上执行 | 跨环境兼容性和错误信息差异化 |
| 输出被管道到另一个程序 | 输出格式是否可预测和解析 |
| 标志组合爆炸 | 大量标志组合的交互复杂度 |

### 4. 打分

**核心维度（所有交互通用）：**

| 维度 | 含义 |
|------|------|
| 首次可执行性 | 首次接触时无需外部帮助就能完成目标 |
| 困惑点密度 | 操作过程中疑问、停顿的频率 |
| 放弃率预估 | 最可能放弃的步骤和原因 |
| 错误恢复路径 | 操作错误后能否自行回到正确路径 |

**UI 扩展维度：**

| 维度 | 含义 |
|------|------|
| 视觉发现性 | 关键功能和状态是否可被注意到 |
| 操作反馈及时性 | 每次操作后是否有明确的系统反应 |

**CLI 扩展维度：**

| 维度 | 含义 |
|------|------|
| 命令可记忆性 | 命令名称和参数格式是否易于记忆 |
| 输出可解析性 | 输出是否清晰、可预测、可被程序解析 |

## 常见陷阱

- **把设计者知识当作操作者知识**：你知道每个功能在哪里，操作者不知道
- **只测试正常路径**：80% 的缺陷在边界路径上——操作错误、网络中断、好奇心点击
- **混淆 UI 和 CLI 信号**：同一问题在不同模式中表现不同——不要用 UI 框架推演 CLI
