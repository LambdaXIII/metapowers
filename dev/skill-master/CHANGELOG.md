## [0.3.0] - 2026-09-07

判 Minor 而非 Major：技能的对外承诺未变（仍是设计/修改/找出问题三块能力），
改动全在内容层；且 1.0.0 被「验证环节未走完」这条义务锁着，不因本次重写解除。

### Changed

- `references/skill-review.md` 重写，标题由「审查一个技能」改为「找出一个技能的问题」（7,744 → 11,300 字符）：审查从「三工作之一」降为一种**注意模式**——生命周期上不存在「设计→编写→验证→审查→修改」这条链，它可在任何时点切入；与修改的区别是两种注意模式而非两个工序（边看边改会让剩下的面没人扫）。决策 1 据此改写：原表述只论证了「调试不独立」，从未论证审查凭什么独立，是从 journal 六阶段框架继承的残留
- 方法主线由七维清单扫描改为**三源交叉比对**（设计意图 / 正文声明 / 别册已有判据，任两处不一致即问题）。依据 n=3 实测（`test-space/review-ab/`）：清单扫描查的是存在性（这条写了没有），交叉比对查的是一致性（说的和做的是不是一回事），后者才是大头——旧版跑出的最硬一条是「metadata 缺字段」，新版跑出的是「设计文档划的边界被正文越过、而另一册恪守着它」，两者互抓不到对方的强项
- 七审查维度改为七类病灶，用途从「扫描检查项」变为「不一致之后的根因分类」，本册只留判别问句与指回权威册的指针：合规→机械项（指组织册）、触发面→机械项（指披露册）、零歧义→悬空、no-op→空转、结构→占位、一致性→自违与转发、化石保留。理由是旧版七维里有五维的判据权威不在本册只是转发，按 writing-craft 的重复披露标准属净损失；「自符合边界」一条与 design 册编写节一字不差重复，直接删除回指
- 新增「机械项：逐条对表，不凭印象」节：高发漏法是只核对想到的那一两项（实测中出现只查引号格式、漏掉字段完整性）。环境侧约束读不到规则时标「待核实」进清单，不降级也不硬判——实测中执行者遇到环境不明的合规判据会自行降级，把真缺陷放掉
- 断链拆两层：浅层（路径可达，可脚本兜底）与深层（目标存在但没装承诺的方法）。三次实测中前两版都只查了浅层，深层零命中；而实战里最硬的一条正是深层
- 锚点不自动豁免：实测抓到设计文档「设计意图」一句与自身详细设计及正文整章打架。三源互为基准，锚点自洽优先
- 委派节要求执行者附过程记录，写明明知该查而没查的部分——三次实测的方法改进全部来自这一段，没有一条来自问题清单
- 自违修正：找出问题册开头原写「这是从成品倒推问题的工作」，与紧接的「找出问题和修好问题是两种注意模式」及决策 1 冲突——本册刚把「写完之后按维度过一遍」判为无效，自己却仍自称工序。改为「注意模式」
- 连带清理旧术语：`general/standards.md` 两处维度表述（「结构维度」「唯一不需要判断力的一维」）随七维改病灶类更新；`skill-modify.md` 执行后检验的「路由与索引覆盖新小节」改为「入口的路由覆盖新小节（路由即索引，不另设一份清单）」——决策 16 已删独立索引，原文仍按两份并存写

### Added

- `skill-modify.md` 补两处与找出问题册的衔接（此前只有单向指针）：从问题清单进来时，清单即现状——每条已带位置与判据、按严重度排好序，按序消费即可，不重查；新增判据前先查别册是否已写过同一条，避免制造转发类病灶。找出问题册此前声明了两条消费方约定（严重度供修改排投入顺序、具体改法留给修改），修改册没有对应接收面
- 完成判据五条（锚点自洽 / 机械项逐字段对表 / 判据归属已追问 / 骨架四类单独过完 / 每条有位置与判据并分级）
- SKILL-DESIGN 决策 17–20（三源比对与病灶分类、自违判据自足、锚点不豁免、委派与过程记录）与术语「病灶」；术语「工作」收缩为设计、修改两类，「症状排查」改为第二个进入方式
- SKILL-DESIGN 同步本轮决策：设计目标「三种工作」改为「两类工作 + 一种模式」；现状节「工作轴（设计/修改/审查）」改为「论述轴（设计/修改/找出问题）」、版本号 0.2.0 → 0.3.0；术语「成品」「知识」的打包目标由 `assets` 改为「静态资源目录（以目标环境白名单为准）」，与决策 15 一致；维护注意事项里两条验证待办合并为一条「下一轮第一项：design 册验证节按『走查不属本技能范畴』收缩」，并注明 `test-space/` 被根 `.gitignore` 忽略、实测记录只存本地不随仓库分发

## [0.2.0] - 2026-09-07

### Added

- SKILL.md「前提《什么是一个好的技能》」节：按三工作论述的共享背景枚举产生——技能靠三层加载生效、读者是零上下文 agent、内容四判据（有用 / 全面 / 准确 / 清晰）。三项是设计定组织与成本、修改定改动边界、审查定判定锚点的共同地基
- 十二册正文按骨架成文，判断依据的来源是 journal Skill Dev 域的实质洞察、开放标准原文、仓库活技能样本三者之一：
  - 三工作论述（设计 / 修改 / 审查）补全机制与判据：症状排查新增沿触发链的六步定位序列；修改新增耦合链三层与条件依赖者、执行后检验三项；审查新增自符合边界与「审查者即被污染者」
  - `general/standards.md` 补全开放标准的逐字段约束与三层披露的词元预算；纠正「行数是词元的安全代理」——中文正文按行估会把预算放大一倍以上
  - `general/disclosure.md` 补全加载器机制实证（全量常驻、纯语义判断、选择在全部候选间进行）、可见性决策先于措辞、正匹配信号与遮蔽源的逐词判据、触发回归的子串模拟与其局限
  - `documents/writing-craft.md` 补全 no-op 的功能归属判据（必要不充分）、读者状态模型、元语境渗漏的四层形态、引导词坍缩、重复显著度效应
  - `documents/` 三册与 `scripts/` 两册补全各自形态的判别与写法：形态分野统一为「读者缺什么」；脚本册补真工具三问（信息缺口 / 手段固化 / 真工具）与以功能角色而非主题词划改动范围
  - 新增 `references/documents/skill-md-writing.md`（写入口文件）：此前入口文件是唯一必存在、每次命中全额支付的文件，却没有一册讲它的形态。内容——三重职责（被命中 / 触发决策 / 路由引导）、前提节的产生方法（枚举各册假设读者已知什么取交集，前提写结论不写论证）、路由按「读者手里有什么」分组而非按工作类型、每个支撑文件在入口里只出现一次（删独立目录节的依据）、入口完整性按读者的进入方式清点（按工作进来 / 按内容形态进来 / 说不清要干嘛）、不触发条件放正文的机制与写法、`description` 定稿流程（先扩命中面再删遮蔽源、子串模拟回归与其局限、双向用例组织）与四条完成判据

### Changed

- SKILL.md 改英文撰写，入口信息架构由「前提 + 三类工作表 + 触发条件 + 目录树」改为「总述（这是什么 / 技能是什么 / 好技能什么样）→ 按情形路由 → 带链接的目录」。改动针对三处推演中确认的失效：前提节排在路由之前，对尚未入状态的读者先下一道「读任何一册之前先过一遍」的指令，六个场景一致地读完前提后自行去找路由；触发节与路由表按「用户说法」与「对象状态」两种口径重复映射同一批工作，读者要在两张表之间挑一张；目录树是代码块，路径不可点达，与本技能自己立的「引用就是加载路径」相矛盾。现按读者手里有什么来组织路由，`Not this skill` 只留加载后核对用途的三条
- 入口补上内容轴：`documents/` `scripts/` `general/` 六个入口此前只以目录树形式存在，只有说「我要设计 / 修改 / 审查一个技能」的读者有路径，说「我要写个脚本 / 一份模板」的读者只能扫目录树碰运气——推演场景 4 正是绕过三册直接命中 `scripts/` 进来的。现按「读者缺什么 / 写的是哪类东西」给入口
- 「验证」一词在入口与审查册之间分家：入口原写「审查是静态的文字质量审查，不加载运行技能」，而设计册的验证环节是委派无上下文子代理跑真实任务，两者共用一个词导致自相矛盾。现分别命名为静态审查（static read，判「对不对」）与走查（walkthrough，判「全不全」），并写明走查卡点可反过来当审查输入
- `description` 经触发面盲测重写定稿：5 版本 × 6 场景 / 24 次子代理委派（按 skill-quick-test 的 trigger-check 单元执行，记录见 `test-space/trigger-check/findings.md`），形态改为「业务措辞骨架 + 一条中文自问信号」，425 → 333 字符。针对「啰嗦」与「汉语标记通用性不足」两条质疑，实测前者成立、后者不成立：24 次决策无一引用过 `Triggers:` 后罗列的穷举动词，被引用的始终是职责句与自问句，故删穷举与结构化标签；而纯英文诉求下子代理仍直接引用中文自问句为命中依据，跨语言语义匹配是通的，故中文信号保留。另测出压到 262 字符会让「判断质量」路径在决策中的位次被 rehearsal 抢走，故不追求最短
- 各册标题改为读者工作表述（打包一个技能 / 设计技能的披露 / 打磨技能文字 / 决定要不要写脚本 / 写技能脚本），去掉宣布文件身份的措辞
- `description` 按披露论述重写：中英双面核心名、用户路径与 agent 路径各留词汇面、反向条件由两条收敛到一条（阐述类误触发），运行时测试类不合触发移入 SKILL.md 正文
- v0 成文整体退缩为章节与要点大纲：产出由编写契约驱动，实为对话碎片的拼接与无来源编造（各册引言自我介绍块、SKILL.md「前提」节的四特征检查清单与「逐条对」工序、无出处的实证数据），经审读判定作废。编造与渗漏内容已清除，跨册链接保留
- `general/standards.md` 重写，标题由「打包一个技能」改为「组织一个技能的结构」：原标题与内容错配——本册实际在讲取舍，却只转述标准约束。改动：约束按来源分「标准」与「环境」两列标注（混淆的实证是 `assets/`——标准推荐而本环境 `content/` 白名单是闭集且不含它，照标准写即违反环境硬性约束；`metadata` 标准可选、本环境必填四子字段）；目录表补 `templates/`、`examples/`、`LICENSE` 并标明各自来源；frontmatter 表按标准原文核对后标注来源；新增分层取舍（留在入口 / 下沉的判据、下沉的代价与过度下沉的症状、上移与拆册判据）与 references 层级模型（顶层主文档 + 按触发机制切分的分组，子目录与文件名前缀两种实现，路径本身承担路由信息）；「打包/编写分离」改为以环境白名单为例（原例用 `assets/`）
- `general/disclosure.md` 收敛为机制与判据，标题改为「让技能被正确命中」：`description` 的定稿流程与回归整节移入入口文件册，本册不再混排操作；「不误指向」补一条——点名真实存在的相邻技能是边界信息而非误指向，禁的是指向不可被加载的东西
- `SKILL.md`：路由新增入口文件一条；两条 `general/` 指针的锚文本与文案随新标题更新；删掉独立的目录节——情形路由已把每个支撑文件指过一遍，第二遍是重复披露，且两处会各自漂移
- 连带指针：`skill-design`、`skill-review`、`essay-writing`、`writing-craft` 指向组织册与披露册的锚文本同步更新；「知识打包归 `assets/`」改为「进静态资源目录（以目标环境白名单为准）」，消除与本环境白名单的冲突；删除 git 未跟踪的空 `content/examples/` 目录
