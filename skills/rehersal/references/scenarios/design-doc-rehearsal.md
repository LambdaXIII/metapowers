# 设计方法论文档验证推演
> 场景文档 — 载体符合时必读。按 `../rehearsal-guide.md` 的路由指引加载。


将 rehearsal（推演）方法应用于**设计方法论文档**的质量验证。这类文档的读者是执行设计任务的接收方（如 AI 模型在设计阶段按方法论执行），不是人类终端用户。

## 与普通文档验证的区别

| 普通操作文档 | 设计方法论文档 |
|----------------|--------------|
| 读完后执行任务 | 读完后按方法论设计 |
| 验证"步骤是否可跟踪" | 验证"逻辑是否在不同输入形态下成立" |
| 单链路走通即可 | 需验证多场景推演完整性 |
| 关注操作正确性 | 关注逻辑自洽、线索清晰、可复现 |

## 四维验证框架

推演设计方法论文档时，用以下四个维度替代普通文档的维度：

| 维度 | 自问 | 典型缺陷 |
|------|------|---------|
| **逻辑正确** | 序列是否自洽？不同场景下方法论的判决是否一致？ | 步骤顺序颠倒、条件互斥失效、范围声明与实际覆盖矛盾 |
| **线索清晰** | 读者能否理解每一节为什么存在、如何衔接到下一节？ | 节间跳跃无过渡、流程图与实际节序不符、引用与引用主题松散 |
| **前后一致** | 前文的承诺在后文是否兑现？数字约束是否自相矛盾？ | 产出表漏列阶段、阈值数字前后不对应、陷阱表与流程表不对齐 |
| **可复现深刻理解** | 重读时能否复现设计意图？关键决策的"为什么"是否显式写出来了？ | 只是"这样做"缺"为什么这样做"、强制性步骤缺后果说明、约束收集漏了重要隐性规则 |

## 推演方法

### 客体定位

执行设计任务的接收方，已知工作上下文（项目结构、依赖关系），但**从未读过这份方法论文档**。目标是"读完这份文档后，按其中流程完成一个设计任务"。

初始状态：
- 知道有相关参考文件存在但没读过
- 理解该领域设计的一般概念
- 已通过需求锚定阶段


### 清空

参照通用论述的「作者视角」和「清空」步骤：

1. **回看作者视角**：确认你在推演前已写下「这份方法论文档的目标执行者是谁、期望达到什么效果」。
2. **设定阅读身份**：你是执行设计任务的接收方，已知工作上下文（项目结构、依赖关系），但从未读过这份方法论文档。目标是「读完这份文档后，按其中流程完成一个设计任务」。
3. **显式清空**：扔掉方法论作者的知识。不知道某个步骤为什么这样设计、不知道设计中舍弃了哪些替代方案、不知道哪些约束是后来追加的。只带执行者的初始状态和方法论文档本身进入。
### 场景选择

选取 4-5 个**文档自身责任范围内**的边界场景。关键是：每个场景必须在方法论声称的处理范围内。不测试上游阶段已保证的条件。

有效边界场景库：

| 场景类型 | 测试目标 | 示例 |
|---------|---------|------|
| 极简输入 | 方法论对极简情况是否过重？ | 2-3 步就能完成的任务，流程是否产生不必要的子节？ |
| 极繁输入 | 方法论的阈值和上限是否起作用？ | 30+ 步的任务，分层/拆分阈值是否触发正确？ |
| 极端分支 | 分支宽度限制是否有效？路由表引导是否充足？ | 10+ 路分支，是否触发路由表设计？ |
| 范围边界 | 入口条件是否能正确拦截不该进来的场景？ | 探索/诊断型流程，是否在入口被拦截？ |
| 并行复杂度 | 优化阶段的约束是否防止过度并行？ | 10+ 可并行步骤，是否触发简化建议？ |

### 交叉引用验证

设计方法论文档通常引用大量参考文件。推演时必须：

1. **存在性检查**：每条引用指向的文件真实存在
2. **方向一致性**：引用的文件主题与引用处的上下文一致（方向不能相反）
3. **完备性扫描**：引用是否有明显盲区——某节应该引用但没引用的文件

### 推演执行

对每个场景，按方法论逐节走一遍：
- 记下每节的输入/输出是否在上下文中成立
- 记录决策判断：该节给出的引导是否足够做出决策？是否有判断真空？
- 走到最后，检查产出表是否覆盖了该场景应有的产出

全部场景走完后汇总问题清单，按严重程度分为：
- **阻塞**：逻辑矛盾或流程卡死点
- **缺陷**：引导不足或覆盖面缺口
- **建议**：可读性或措辞改进

## 示例

场景：推演一个操作型设计方法论在多分支场景下的表现。

客体带着前几个阶段的设计成果进入"设计分支与路由"阶段，面对 14 种文件合并策略。

推演发现：
- 分支指导（5-7 路）和路由表设计正确触发 ✓
- 异常处理部分只给了若干全局问题，未提醒对每条分支逐一检查异常差异 → **缺陷**
- 修复：在异常处理末尾加分支级异常差异检查提示

## 与单文档推演的关系

本文档描述的是**设计方法论文档**的验证方法。如果被推演对象是普通操作指南或最终用户文档，应使用 `doc-guide-rehearsal.md`。判断标准：文档的读者是执行设计任务的接收方吗？如果是，用本参考；如果文档的读者是执行具体操作，用普通文档验证。
