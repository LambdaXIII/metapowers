# multi-ask 脚本契约

本文件是 multi-ask 技能脚本层的权威工件契约：问卷 DSL、校验规则、命令行接口、答卷 JSON 与拼装格式的唯一定义。脚本实现与 SKILL.md 使用说明都以本契约为输入，两者不得各自发明词形或字段名。设计理由随本文留档，技能内容（SKILL.md）只记操作事实，不引述本文。

技能设计规格见 [SPEC.md](SPEC.md)。本文裁定 SPEC 未展开的实现层细节，含示例问卷（`content/examples/release-plan.md`）的取舍。

## 1. 术语

- **问卷**：agent 编写的 markdown 文档，含任意论述正文与若干问题块。
- **问题块**：围栏语言为 `single-choice`、`multi-choice` 或 `yes-or-no` 的 fenced code block；块体是 markdown 任务列表，首行给出块 id 与题面。问题块是唯一的交互与校验单元。
- **题面**：块首行 `<块 id>` 之后的问题文本，可续写在后续行直到第一个选项行。题面写在块内，块外正文只写论述与章节。
- **选项**：块内的任务列表项，形如 `- [ ] <选项 id> 文本`；方括号内写 `x` 表示推荐选项。
- **开放题**：`single-choice` / `multi-choice` 中不含任何选项的问题块，只收自由输入。
- **自由输入**：每题恒定附带的自由文本框；**总评**：整卷末尾恒定附带的自由文本框。两者都不占块结构，由渲染层提供，问卷作者无需声明。
- **答卷**：用户提交后产出的 JSON 纯数据文件，不含题干与选项文本。
- **拼装答卷**：问卷正文原样保留、问题块替换为作答结果后得到的派生文本，按需现算、不落存储。

## 2. 问卷 DSL

### 2.1 文档结构

问卷是普通 markdown：标题、段落、列表、链接、引用、表格、mermaid 等 fenced 块均可自由使用。问题块散布在论述之间，块外正文承担论证、背景与章节组织——**题面写在块内，块外不重复题面**。无脚本时整卷降级为普通可读 markdown（问题块呈现为带任务列表的代码块）。

问题块与题面只呈现交互内容，不承担文档结构：章节须在正文中以真正的标题（`#`–`######`）建立，题面本身是块首行的一段行内文本，块内不得用标题充当题面或章节。

### 2.2 围栏与块首行

围栏语言白名单三种，大小写不敏感（信息串取第一个词并转小写）：

| 围栏语言 | 题型 |
|---|---|
| `single-choice` | 单选 |
| `multi-choice` | 多选 |
| `yes-or-no` | 判断 |

`multiple-choice` 是 `multi-choice` 的兼容别名，行为完全相同；问卷与新文档一律写 `multi-choice`。其他围栏语言不是问题块，按普通代码块展示；围栏名与白名单词形接近（去除非字母字符后相同，如 `multi_choice`、`single_choice`）时给一条校验提示，指明应写成哪个题型。

围栏为三个及以上反引号或波浪号；块在首个同字符、长度不短于开头的围栏行处闭合。缺少闭合围栏即校验错误。

块首行是块内第一个非空行，形如：

```text
<block-id> 问题文本
```

- `<block-id>` 写在尖括号内，非空，不含空白与尖括号；作用域为整卷，全卷唯一。
- 尖括号之后是题面，可续写在后续行，直到第一个选项行（或块末）。题面按 markdown 行内语法渲染，连续普通行合并为一段；题面不承担文档结构，块内不写标题、列表或分隔线。
- 首行缺失、首行不是该形状，或题面为空，都是校验错误。

### 2.3 选项行

选项行是 markdown 任务列表项，两种写法：

```text
- [ ] <option-id> 选项文本
- [x] <option-id> 选项文本
```

- 选项 id 写在尖括号内，非空，不含空白与尖括号，在所属问题块内唯一；不同问题块可复用同一选项 id。
- `[ ]` 为普通选项，`[x]` 为推荐选项。方括号内只接受空格或 `x`（大小写均可）。
- 选项文本写在 `<option-id>` 之后，非空；可续写在后续行，续行以单个空格拼接。文本自由，可含中文标点与空格。
- 行首是 `- [` 但不符合上述形状的行（缺尖括号、缺 id、id 含空白等）即「选项行格式不合法」，并终止题面的续行收集。
- **推荐只是作者的建议标记，不等于预先选中**：交互页不为推荐选项预勾选，用户完全自由作答；推荐信息属问卷元数据，不写入答卷 JSON、不进拼装答卷。同一问题块可标记多个推荐选项，也可以不标记。

### 2.4 选项数量

- **零选项**：`single-choice` / `multi-choice` 的块即**开放题**，交互页不渲染任何选项控件，只保留自由输入。
- **恰一个选项**：`single-choice` / `multi-choice` 校验不通过。修复指引：改成 `yes-or-no` 并把题面写成完整命题，或与同类问题合并为一道 `multi-choice` 多选题。
- `yes-or-no` 的选项数量规则见 §2.5，不受本节约束。

### 2.5 `yes-or-no` 的标签

- 不写选项时，渲染层提供默认标签「同意 / 驳回」，问卷里无需声明，两个选项也不需要写进块内。
- 写了选项时，只接受 `<yes>` 与 `<no>` 两个标签：每个选项的 id 必须是 `yes` 或 `no`，其他标签即校验错误。顺序随意，数量可只给一个（此时交互页只显示该标签，另一侧无法选择，驳回意见只能落进自由输入）。
- 选项文本替换默认标签，例如 `- [ ] <yes> 采纳` 显示为「采纳」；答卷恒记 `yes` / `no`，与显示文本无关。
- 推荐标记可用于 `yes-or-no` 的选项（如 `- [x] <yes> 同意`），语义同 §2.3。

### 2.6 题型语义

| 题型 | 提交约束 | 答卷记录 |
|---|---|---|
| `single-choice` | 至多选 1 项 | 选项 id 数组（0 或 1 个） |
| `multi-choice` | 任意多项 | 选项 id 数组 |
| `yes-or-no` | 至多选 1 项（整题为空合法） | `["yes"]` 或 `["no"]`，未答为空数组 |
| 开放题 | 无选项 | 空数组 |

任何题型都可附加自由输入；用户可以不选只写自由输入，可以整题跳过（答卷条目为空数组 + 空串）。

### 2.7 id 规则与可见性

- **块 id**：作用域为整卷，全卷唯一；**选项 id**：作用域为所属问题块，块内唯一。
- 所有 id 不得含空白或尖括号，命名不设模式约束（不要求 Q1/A1 之类）。
- 校验点：块 id 重复 → 不通过；选项 id 块内重复 → 不通过；id 含空白 → 由首行或选项行的格式校验捕获，不通过。
- **id 只属于对照追踪层**：只出现在答卷 JSON、校验错误反馈与页面 DOM 属性（供脚本配对）；交互页、提交完成页、拼装答卷等一切用户可见面不得显示任何 id。

## 3. 校验

### 3.1 校验清单

共 8 类校验面，另有两条附加约束：

| # | 校验面 | 判定 | 修复指引 |
|---|---|---|---|
| 1 | 白名单块 | 全卷至少一个 `single-choice` / `multi-choice` / `yes-or-no` 块，否则不通过 | 用三种围栏之一写问题块，首行写 `<block-id> 问题文本` |
| 2 | 块首行 | 块内第一个非空行必须是 `<块 id> 题面`；缺首行或形状不符即不通过 | 首行写成 `<block-id> 问题文本`，如 `<answer-naming> 答卷文件怎么命名？` |
| 3 | 题面 | `<块 id>` 之后必须有题面文本 | 在 `<块 id>` 之后写题面；题面可跨多行，直到第一个选项行 |
| 4 | 选项行格式 | 每行选项必须是 `- [ ] <选项 id> 文本` 或 `- [x] <选项 id> 文本` | 写成 `- [ ] <选项id> 选项文本`；推荐项写 `- [x] <选项id> 选项文本` |
| 5 | 选项 id 唯一 | 选项 id 在所属块内不得重复 | 同一问题块内选项 id 必须唯一，改掉其中一个 |
| 6 | 选项文本 | 选项文本不得为空 | 在 `<选项 id>` 之后写选项文本；选项文本可跨多行 |
| 7 | 选项数量 | `single-choice` / `multi-choice` 不得恰有一个选项 | 改成 `yes-or-no`（题面写成完整命题），或把同类问题合并为 `multi-choice` |
| 8 | 判断标签 | `yes-or-no` 的选项 id 只能是 `yes` / `no` | 只接受 `<yes>` 与 `<no>`，选项文本写在标签之后，如 `- [ ] <yes> 同意` |

附加两条同属校验面：**块 id 全卷唯一**（重复时报告与首次出现的行号，并建议另取 id）；**围栏闭合**（任何围栏缺闭合即不通过——不报会让后文被静默截断）。另有一条**围栏名提示**：非白名单围栏的名称若与题型词形接近，报提示而非错误。

id 含空白的处置：尖括号内不允许空白，因此 `<my id> 题面` 落在第 2 类、`- [ ] <my id> 文本` 落在第 4 类；修复指引按不含空白的 id 改写。

### 3.2 错误反馈格式

校验错误一次列完（不是逐条停下），按行号升序，每条形如：

```text
<文件>:<行号>: <问题描述> → <修复指引>
```

`<文件>` 为被校验的问卷路径；`assemble` 中答卷侧的问题用答卷路径。修复指引必须告诉 agent 怎么改（例如「选项 id 在块内重复 → 同一问题块内选项 id 必须唯一，改掉其中一个」），不得只报错误名。校验不通过即终止，不开交互页。

### 3.3 答卷侧校验（`assemble`）

`assemble` 先解析问卷并跑 §3.1，再逐条检查答卷，全部错误同样一次列完：

- `answers` 必须是数组，每项是对象且含字符串 `block`；
- 同一 `block` 只出现一次；
- `block` 必须是问卷中存在的问题块 id；
- `selected` 必须是字符串数组；
- 开放题的 `selected` 必须为空数组；
- `selected` 中的每个值必须是该块存在的选项 id；
- `single-choice` / `yes-or-no` 的 `selected` 至多一个；
- `free` 必须是字符串（缺省视为空串）。

## 4. 命令行接口

脚本为单文件 `scripts/multi_ask.py`，Python 3 标准库实现，无第三方依赖、无网络服务。三个子命令：

### 4.1 `validate <问卷.md>`

只校验不渲染。通过：输出 `OK: <n> 题`，退出码 0。不通过：按 §3.2 一次列完全部错误，退出码 1。

### 4.2 `show <问卷.md>`

1. 先校验（同 validate）；不通过即终止（退出码 1）。
2. 在 `127.0.0.1` 随机端口起线程化本地服务（`ThreadingHTTPServer`），前台打开浏览器展示交互页；浏览器打开失败时服务继续并打印 URL 供手动打开。
3. 阻塞等待提交。用户提交后写答卷文件（§5），打印答卷文件路径，退出码 0。页面不跳转：按钮置为「已提交，可以关闭本页。」并禁用全部控件，不尝试关闭标签页。POST 的响应体是静态成功页（`DONE_PAGE`），正常流程下 `fetch` 不渲染它。
4. Ctrl+C 中断：不写答卷文件，退出码 130。
5. 交互页把问卷正文按 markdown 渲染（§7 降级范围），问题块渲染为「题面 + 选项控件 + 每题自由输入框」：`single-choice` 与 `yes-or-no` 为单选按钮，`multi-choice` 为复选框；开放题只有自由输入框；推荐选项以彩虹渐变文字标记，但不预选。正文左侧空白区提供标题目录（h1–h3，点击跳转并高亮当前位置），视口不足以容纳时隐藏；问题块不单独列入目录。卷末提供整卷总评框与提交按钮。

### 4.3 `assemble <答卷.json>`

读答卷，按 `questionnaire` 记录的问卷路径找问卷（找不到时退回答卷同目录的同名文件），逐块替换为作答结果（§6），输出到 stdout，退出码 0。失败情形（答卷/问卷缺失、JSON 非法、答卷未通过 §3.3）：按 §3.2 风格报错并给修复指引，退出码 1。

## 5. 答卷 JSON

```json
{
  "questionnaire": "/home/user/notes/release-plan.md",
  "answers": [
    { "block": "scope", "selected": ["narrow"], "free": "导出留到下一批。" }
  ],
  "global_comment": "结构清楚。"
}
```

- `questionnaire`：问卷路径。`show` 记录问卷的绝对路径；`assemble` 按该路径找问卷，找不到时退回答卷同目录的同名文件。只写文件名无法让答卷独立定位问卷。
- `answers`：每个问题块一条，按问卷顺序；`block` = 问题块 id；`selected` = 选项 id 数组；`free` = 自由输入（可为空串）。不回显题干，也不含选项文本。
- `global_comment`：总评文本（可为空串）。
- 脚本收卷时按问卷重排并清洗：只保留该块存在的选项 id、去掉重复值、`single-choice` / `yes-or-no` 截断为至多一个；每个问题块都写一条记录，缺失的提交项补为空数组与空串。
- 文件名 `<问卷名去扩展名>.answers.<YYYYMMDD-HHMMSS>.json`：时间为提交时刻的本地时间（`time.strftime("%Y%m%d-%H%M%S")`）。同一时间点已存在同名文件时追加三位序号（`<问卷名>.answers.<时间点>.NNN.json`），序号取该时间点已有序号文件名的最大值 +1、从 `001` 起；不与既有文件重名则不写序号。同一问卷多份答卷即多个文件，只增不改。

## 6. 拼装答卷格式

问卷正文原样保留；每个问题块替换为「题面 + 引用块作答」，题面按问卷中的文本逐行保留（题面内的空行不保留），不显示块 id——

```markdown
第一批收窄到核心命令，其余功能留到第二批。

> 选：收窄：本月能上线，用户暂时看不到导出与批处理。
> 补充：导出功能在文档里标成「暂未提供」。
```

- 有选择：`选：<选项文本…>`（多选以 `；` 连接；`yes-or-no` 显示该题实际标签，默认即「同意」/「驳回」）。
- 有选择且有自由输入：另起一行 `补充：<文本>`。
- 无选择、只有自由输入：`> 答：<文本>`。
- 整题未答，或答卷缺该块记录：`> 未答`。
- 多行自由输入：首行带 `选：` / `补充：` / `答：` 前缀，续行以 `> ` 开头，空行写作 `>`。
- 卷末总评非空时追加 `---` 分隔线与 `**总评**` 段落。
- 拼装结果是派生的 stdout 文本，不写文件。

## 7. 实现约束

- 单文件脚本，Python 3 标准库（`http.server`、`webbrowser`、`json`、`argparse`、`threading` 等），不引入第三方包；脚本装上即用，自身不发起任何网络请求。
- 服务只绑定 `127.0.0.1`，端口由系统分配，随用随停，不留常驻进程。
- 问卷解析：按行扫描围栏，信息串取第一个词并转小写；白名单见 §2.2。块体解析按 §2.2–§2.5：首行取第一个非空行，选项行按任务列表正则匹配，其余非空行依次续接到题面或当前选项文本。
- markdown 渲染范围（手写最小渲染器）：标题、段落、无序/有序列表、粗体、斜体、行内代码、链接、引用、分隔线、fenced code block。表格等其余结构降级为预格式化文本展示，不阻塞收卷。`mermaid` fenced 块由交互页在浏览器端按需加载 mermaid 渲染器绘制为图；离线或加载失败时降级为预格式化源码文本，不影响作答与收卷。
- 输出与文件一律 UTF-8；答卷 JSON 采用 `ensure_ascii=false` 的可读缩进格式。

## 8. SKILL.md 要点（内容范围约束）

- frontmatter：`name: "multi-ask"`；`description` 同时覆盖两种入口（agent 攒起待决问题时自主加载、用户显式要求「批量问/问卷」时加载）并与「替用户向第三方征集知识」的问卷技能划界；`metadata.version: "0.1.0"`、`last_updated: "2026-11-06"`、`author: "Cxalio"`；`license: "MIT"`（AGENTS.md §6 已登记）。
- 入口 SKILL.md 只写「是什么 / 为什么 / 怎么做」，「怎么做」为按情形指向参考文档的路由；DSL 参考、三命令、答卷 JSON、拼装、提问技巧（依赖链问题不进同一批、上下文压缩到决策相关、承重假设显式化、讨论文本问卷化、判断题写成完整命题、单选项改写为判断题或多选题）全部在 `references/`（questionnaire-format、script-usage、organizing-questions、writing-questions）。
- DSL 说明必须与本文一致：三种围栏语言、块首行 `<块 id> 题面`、选项行 `- [ ] <选项 id> 文本` 与 `- [x]` 推荐、零选项即开放题、单选项报错、`yes-or-no` 默认「同意/驳回」与标签约束、id 两级作用域。
- 只记操作事实与判断依据；不引述本契约、不写设计理由；路径写技能内相对路径（`scripts/multi_ask.py`），不出现 `dev/`、`test-space/` 等开发层路径。
