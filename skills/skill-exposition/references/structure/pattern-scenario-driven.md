# 读者场景导向模式（scenario-driven）

> 组织轴 = 读者可能的场景：读者带着什么意图来读，就按什么意图组织内容。

## 模式定位

本模式按**读者场景**组织说明文——先问"读者读这段时想做什么"，再把内容归入对应场景章节。沿用 Diátaxis 的四问判断法：

| 读者想做什么 | 场景 |
|-------------|------|
| 跟着做一遍 | 入门走查：从 0 到 1 完整演示 |
| 解决某个问题 | 任务指南：按问题/目标组织步骤 |
| 查某个细节 | 速查：完整、精确、可检索 |
| 理解原理 | 原理说明：概念、背景、为什么 |

判断依据是**读者的意图**，而不是内容主题——同一主题的内容可能出现在多个场景章节中，各讲各的用途。

## 适用情况

- 读者群体多样、阅读目的差异大：既有想快速上手的新学习者，也有回来查参数的老用户
- 技能内容能按"读者要做什么"清晰切分，任务边界相对独立
- 想让读者最短路径到达目标：读者带着问题来，直接翻到对应场景章节

## 结构示意

```
1. 快速入门（"带我跟着做一遍"）
   从 0 到 1 的完整走查，让读者照做成功一次
2. 常见任务（"帮我解决某个问题"）
   按任务组织的步骤，每个任务独立成节
3. 参数速查（"我要查某个细节"）
   完整精确的参数、命令、配置清单，便于检索
4. 原理说明（"为什么这样设计"）
   概念解释与设计背景
```

章节顺序可调整；关键是每一节都能回答"读者此刻想做什么"。

## 权衡与注意

- **意图先于主题**：判断一节属于哪个场景，靠的是读者意图而非内容类别。把"主题相同"当成归章依据，就退化成了按内容主题分类
- **重复与交叉引用**：同一内容可能被多个场景需要（如"委派"既出现在任务章又出现在原理章）。要么按场景各写一遍，要么主写一处、他处交叉引用，避免两处内容漂移不一致
- **场景要来自真实读者**：凭想象凑场景会造出没人会读的章节；读者画像不清晰时，先确定几类典型读者再来选本模式
- **与 learning-path 的差异**：学习路径（默认模式，见 exposition-guide.md 第 4 节）按"读者学到什么"排序；本模式按"读者来干什么"排序——前者是内容顺序，后者是入口顺序
- **与 5w1h 的差异**：5w1h 按覆盖维度组织、保证无遗漏；本模式按读者意图组织、保证路径最短，不追求六个维度齐备

## 示例说明

假想技能"Git 操作技能"：入门章带新读者完整走一遍提交流程；任务章按"撤销误提交""合并分支""找回丢失提交"组织；速查章列全部命令与参数；原理章讲工作区、暂存区、提交三者的关系。
