# 设计一个技能

## 锚定

- 锚定是设计起点：确定技能提供什么、指导什么、不管什么。后续一切设计决定
  （description 收敛、审查判「缺陷还是设计如此」）都以它为依据。
- 锚定三问随材料与讨论逐步精确化：提供什么（以文档承载的知识、方法与判据）、
  指导什么、不管什么。排除边界与提供内容同等必须——没有排除项的定位必然
  过宽；排除项日后固化为 SKILL.md 的不触发条件。
- 「提供什么」的定稿形态是能力句：「提供通过 X 实现 Y 的能力」。判据在时态：
  X 必须是已被走通的做法——写成「打算、将、希望」时，锚定的还是愿望。
- 值不值得做成技能，三项判据缺一不做：非一次性（任务会重复出现）；真知识
  缺口（agent 本来就会、搜索即得的不算）；需结构化封装（散落经验不够用）。
- 可行性：材料撑得起一个入口（SKILL.md）加至少一本支撑内容的结构。
- 身份前提：设计输入是已被走通、被检验的做法，不为推测中的需求设计。
- 一个技能锚不住三项以上独立职责时拆开；拆的判据是每一半都能独立回答锚定
  三问。

## 材料从哪来

- 材料来自真实实践，判据是「反复走通、可复现」。推测、个案、搜索即得的内容
  不算材料。
- 实践材料按形态归位：客观资料（供查阅，打包归 assets）；步骤序列（工作流
  形态，按 [workflow-writing.md](documents/workflow-writing.md) 编写）；
  判断依据（论述形态，按 [essay-writing.md](documents/essay-writing.md)
  组织）；稳定输出框架（模板，按
  [template-writing.md](documents/template-writing.md) 编写）。
- 弯路与失败尝试不扔：它们构成 Gotchas（已知失败模式清单）的素材——失败
  模式是别人付过学费的浓缩。

## 组织与打包

- 文件组织受开放标准约束，规范条目见
  [standards.md](general/standards.md)（开始摆放文件结构、核对合规时读）。
- 打包目录是放置问题：SKILL.md 放技能根，内容按性质进 references /
  templates / scripts / assets。
- 打包与编写分离：放哪个目录与按什么方法写是正交的两轴；按打包位置找编写
  方法是错误路由。
- 展示目录树从技能根开始，不含仓库上层路径。

## 编写

- 成文顺序：先写支持文件，再写 SKILL.md，最后写 description——入口要指向
  真实存在、真实装着的内容；触发面在覆盖面确定前写必然返工。
- 内容形态决定写法：工作流、论述、模板各归对应册取方法，不按打包位置取。
- 句子级手艺——no-op 检验、正向陈述、量化模糊词、指针三要素——见
  [writing-craft.md](documents/writing-craft.md)，落笔前先过一遍。

## 披露

- 披露由 description、触发面、命名构成；设计方法论见
  [disclosure.md](general/disclosure.md)（写 description、定技能名、打磨
  触发词时读）。
- 技能名是双重身份：加载器标识 + 用户称呼。简短、自解释、不与相邻技能
  撞名。
- description 的每个词都是每次会话的常驻成本；覆盖面收敛之前不写它。

## 验证

- 交付前验证自足性：委派一个无上下文的子代理，仅凭技能文档完成目标任务，
  收集卡在哪、误解了什么。验证查的是「写全了没有」；卡点清单是下一轮修改
  的工单。
- 隔离纪律：任务预期与对比信息不进子代理的 context——预期引导会把技能缺
  的环节悄悄补上，那时验证的是提示词而不是技能；场景也不只挑自己能通过的。
- 与审查的分工：验证判「零上下文能不能用起来」，审查判「写得对不对」。卡
  点修不动、或发现是设计意图问题，回锚定重答三问。

## 推荐路径

- 大致走向 锚定 → 组织 → 编写 → 验证，但不是阶段流水线：设计是发现过程，
  卡住随时回头——材料不足回实践补积累，范围没钉住回锚定重答三问。回头时
  明确回到哪一步、修什么。
- 只有内容本身是程序时才用流程形态；判断依据按需查阅，不设门禁。

## Gotchas

- **禁止语悖反**：禁止语让被禁行为更可及。规则正向陈述目标行为；无法正面
  表达的硬护栏才保留禁止，且配对「该做什么」。
- **为推测的需求设计**：没有真实做法支撑的需求不构成设计输入；锚定时先问
  「这套做法是否已被走通」。
- **成品格式化石**：一次交付的产出形态冒充方法论。先问形状背后有没有可迁
  移的结构；有则按 template-writing 拆骨架、试填验证，没有就留在个案里。
- **委托边界泄漏**：验证用的预期与对比信息只留在验证者手里，不进技能文档、
  不进子代理 context。
