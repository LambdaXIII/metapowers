# Research Workflow

📍 `web-deep-research` · 问题驱动的研究方法论 · [← 回 SKILL.md](../SKILL.md)

> 本技能的**驱动结构是问题集（Q-set）**，不是线索清单。
> Phase 0 把目标拆成原子问题（Q1、Q2…）；之后的循环由**开放问题**驱动——追踪能支撑该问题的线索、交叉验证后**消解**它；Phase 4 交付报告，仍未消解的问题诚实进「信息空白」。
>
> 阶段速览：Phase 0 明确话题并拆出初始问题集 → Phase 1 建立线索起点并映射到问题 → Phase 2 问题驱动地追踪线索链（纯收集，不做判断）→ Phase 3 交叉比对，作为问题的消解闸门 → 发现新问题回到 Phase 2 → Phase 4 整理报告，资料不被结论覆盖。

---

## 问题集（Q-set）：阅读前先懂这套术语

研究全程维护一份**问题集**——当前还"没答完什么"的清单。它是活的：随研究推进不断演化。

- **问题（Q）**：一个**原子问题**——需要证据消解的研究子问询，编号 `[Q1]`、`[Q2]`…。与「目标」（Phase 0 固定的研究维度）、「线索 S」（待追踪来源）、「发现 F」（评估产出）并列，**不可混用**。
- **消解**：Q 的答案通过交叉验证 → 变成发现 F 或线索 S，该 Q 从问题集移除。
- **转化**：某个 Q 的答案让另一个旧 Q 过时 → 旧 Q 移除，换成更精确的新 Q。
- **新增**：新线索或新矛盾引出以前没问过的问题 → 加入问题集。
- **不可得**：某 Q 经实际调查确认**无可达来源** → 产出"可得性"发现 F，该 Q 关闭（逐 Q 判定）。
- **收束**：问题集不再演化（不再新增、不再消解，边际价值下降）→ 整个研究循环的全局停点（区别于不可得的逐 Q 判定）。
- **排除**：某 Q 被判断不值得追 / 超出范围 → 关闭（价值判断，区别于不可得的可得性事实）。

**关键纪律**：Q 只存"还剩什么没答"的开放感，**不存答案**。答案一旦成立就转成 F 离开 Q，不持久化"问题+答案"。Phase 2 步骤 7 的**候选答案**是独立工作产物（记录答案内容与依据的 [S 编号]），不属于 Q 条目——Q 条目本身保持开放，不存答案内容。

## Phase 0: 明确话题（不联网）

**目标**：在搜索之前，确保你知道用户到底在问什么。不联网——仅基于对话上下文和你的判断。

**产出**：以下四项以固定格式记录（供跨会话续研时直接恢复上下文）：
- **实体名称**：确认后的名称（Phase 1 验证指称，之后锁定不再偏移）
- **目标清单**：逐条列出（Phase 1 映射线索覆盖；Phase 2 定期锚定；Phase 4 组织结论）
- **初始问题集**：每个目标拆解出的原子问题（Q1、Q2…），驱动后续循环的起点
- **范围边界**（Phase 2 定期回看是否偏离；Phase 4 结论范围锚定）

范围可在研究中途调整，但调整需要显式标注。

### 指称确认

用户用的名称是正确的吗？

- 已知实体 → 直接确认
- 听说的名字 / 内部代号 / 不完整名称 → 评估：你能自信推断正确名称吗？
  - 能 → 记录推断结果，Phase 1 搜索中验证
  - 不能 → **直接向用户确认**
- 无具体实体名称（类别查询：如"有什么好看的 X""最近 X 领域的新动态"）→ 确认类别边界：时间范围、质量标准、类型边界。这些边界的澄清本身也是研究的一部分——不联网时先做初步界定并标注不确定性，Phase 1 搜索中用真实数据修正

### 消歧

一个名字指向多个实体时，判断用户指的是哪一个。

- 上下文足以区分 → 自行判断
- 上下文不足，歧义无法调和 → **直接向用户确认**

### 意图拆解

用户一句话中可能包含多个需要独立研究的维度：

- **显式目标**：用户明确要求回答的问题
- **隐式目标**：用户语句中隐含的研究需求（如"帮我们设计 Agent"隐含了"Agent 设计方法论有哪些"）

每个目标作为一个独立维度纳入 Phase 1 的线索映射。

### 主题制定

研究的对象是**主题**，不是用户的问题本身。主会话基于对话上下文判断是否需要研究——技能被加载时研究意图已定，你的职责是把意图制定成可调查的主题。

- **主题 ≠ 用户的问题**：用户问"该不该换 Rust"，主题是"Rust 与现有技术栈在 X 领域的技术差异、易用性、性能、维护成本对比"——主题是可调查对象；用户的问题（要不要换）是主会话的决策，研究不替它作答
- **主题无倾向性**：把"该不该 / 好不好 / 要不要"类意图转化为考察 / 对比型主题，不预设结论。调查本身不含倾向，其用途是支援主会话的话题——结论支撑决策，决策权在用户
- **维度定位**：去倾向 ≠ 去维度——消除的是结论预设，不是用户问题中的研究维度。区分**核心关切**与**支撑性论据**：核心关切（用户真正想知道的，如"他到底配不配这个地位"）必须原样保留进主题；支撑性论据（用户用来质疑的理由，如"相比更年长导演没突出之处"）可纳入相关维度，不必升格为独立目标。若核心关切本身是具体对比（如"诺兰与库布里克影史地位谁高"），对比基准必须保留。判断问题：用户是想**校准评价**（配不配/值不值）还是想要**具体对比**（谁高/差异在哪）？
- **主题可研究**：有明确的调查对象、维度、范围，能拆出原子问题

目标清单与问题拆解都基于主题展开，而非基于用户的原话。

完成指称确认和意图拆解后，检查：当前话题是否匹配 Content Index 中的任何领域文档？回顾 SKILL.md 的 Content Index 表格，确认所有匹配的领域文档都已加载，若未加载则现在加载。

### 问题拆解

把每个目标拆成**原子问题**——每个 Q 是一个能用一条发现（或一组证据）独立回答的最小问题。

拆解标准：
- **一个 Q 一个问题**——"X 公司成立时间 + 创始人背景"是两个 Q，不是 [Q1] 一个
- **Q 是可回答的**——不是"X 到底怎么回事"这种需要整段报告的大问，而是能导向具体证据的子问
- **覆盖完整**——所有目标拆完，问题集应覆盖目标的所有关键面，不留"感觉还有个维度没拆出来"

示例：目标"X 公司的市场定位和竞争状况" → [Q1] X 成立于何时、规模多大？[Q2] X 的定价与产品定位是什么？[Q3] X 的主要竞品是谁、差异在哪？[Q4] X 的市场地位是否有可靠数据支撑？

问题集在后续循环中不断演化（消解 / 转化 / 新增）——Phase 0 的只是起点，不是冻结清单。

### 确定范围

本次研究包含什么、不包含什么。边界可以在研究过程中调整，但调整需要显式标注。

### 完成检查

- 指称是否已确认或修正？
- 主题是否已制定——中立、可研究、与用户的问题分离？
- 目标是否已拆解（显式 + 隐式）？
- 初始问题集是否已生成并覆盖所有目标？
- 范围是否已界定？

## Phase 1: 建立线索起点（联网）

**目标**：开始搜索，用真实数据验证 Phase 0 的判断，建立第一批线索，并把线索映射到问题集。

### 操作

1. **验证指称**——用 Phase 0 确认的名称首次搜索。发现偏差（如"有戏AI 已更名为 XX"）→ 立即更新名称，之后锁定，不再偏移
2. **初始搜索**——用最终确认的名称搜索话题，浏览 5-10 个结果
3. **识别线索**——从搜索结果中提取：
   - 术语：不熟悉的概念、专业名词、缩写
   - 人物：被反复提及的名字、机构、作品
   - 事件：时间节点、转折点、争议
   - 来源：被引用的原始报告、访谈、论文——记录它们，这是 Phase 2 的种子
4. **问题映射**——把每条线索映射到它可能支撑的问题 [Q 编号]。逐 Q 检查：哪些问题已有线索、哪些问题**线索稀疏甚至空白**（空白问题是 Phase 2 的优先追踪目标）
5. **语言选择**——根据话题选择搜索语言：
   - 创意/媒体话题：英文搜索通常线索更丰富（中文搜索可能被无关内容淹没）
   - 本土产业/政策话题：以本地语言为主
   - 技术话题：中英文并用
   - 如果选了单一语言但发现线索稀疏，换一种语言试试

### 完成检查

- 指称是否已验证或修正？
- 每个问题是否都有线索覆盖或明确的"待找"状态？线索空白的问题——为什么没有？（语言问题？搜索词问题？还是这个问题本身信息稀缺？）

## Phase 2: 问题驱动地追踪线索链

**目标**：追踪能支撑开放问题的线索，阅读，总结，发现新线索和新问题。**此阶段不做真假判断、不做置信度评估**——只收集和连接。判断留给 Phase 3（不对内容真伪做判断；按来源权威性排序选择追踪顺序属于收集策略，不是内容判断）。

问题集是此阶段的驱动：**取一个开放 Q → 顺能支撑它的线索追踪 → 得到候选答案**。线索是 Q 的载体，不是目的本身。

### 操作

1. **选一个问题**——优先选：线索空白/稀疏的问题（最可能因缺证据而无法消解）；涉及核心目标的问题
2. **取出能支撑它的下一条线索**——优先追踪来自高权威来源的线索
3. **阅读原始内容**——不只看摘要。不只看转载。直接阅读这个来源本身的完整内容
4. **总结**——用你自己的话概括这个来源说了什么。总结不是判断——不要说"这是对的"或"这不可信"，只复述它的说法。概括时保留具体信息（数字、日期、原文引述），不要压缩成笼统描述
5. **追踪连接**——这个来源：
   - 引用了什么？（追溯被引用方）
   - 被谁引用？（查找引用它的后续来源——这是发现新视角的路径）
   - 提到了哪些新术语、新人名、新事件？**这些新线索可能引出新的 Q**（新增到问题集）
6. **记录来源**——每条信息标注出处，**必须包含 URL 地址**（或文档路径、出版物编号等可追溯标识）。同时分配一个唯一的来源编号 `[S1]`, `[S2]` ...——按收集顺序递增即可。预判资料类型（事实 / 数据 / 知识 / 意见 / 经验）——可粗略，Phase 3 复核修正。这个编号贯穿后续所有阶段，在 Phase 3 的发现和 Phase 4 的报告中直接引用。来源丢失 = 这条信息在 Phase 3 无法被评估
7. **记录候选答案**——当某个 Q 的线索足以给出一个候选答案时，把它标记为该 Q 的**候选答案**（含依据的 [S 编号]）。**这不构成消解**——消解是 Phase 3 交叉验证通过之后的事。Q 保持开放
8. **追加到线索清单**——新发现的线索加入待追踪清单，标注它支撑哪个 [Q 编号]
9. **定期锚定**——回看 Phase 0 的判断：当前追踪是否仍在回答原始问题？是否偏离了范围？问题集是否还覆盖全部目标？

### 组织节奏

不同话题的线索追踪节奏不同，选择适合的即可（都服务于"把开放问题喂饱"）：

- **链式**：线索 A → A 引用的来源 B → B 引用的来源 C。深度优先，适合有清晰引用链的话题
- **广度优先**：先收集话题下所有主要来源，再逐个深读。适合框架、方法论、知识体系类话题
- **矩阵填充**：有多个问题和多个维度时，可以按问题横扫或按维度竖填。适合竞品分析、多方案对比

### 停止条件（收束）

研究自然结束时，**问题集会停止演化**（不再新增、不再消解、边际价值下降）。收束意味着：

- 不再产生新 Q（新线索只是重述已知，不再打开新的子问题）
- 不再有 Q 消解（对现有 Q 的候选答案都已完成交叉验证，见 Phase 3）
- 剩余开放 Q 要么已判定不可得，要么边际价值很低

收束是**全局停点**，与「不可得」（逐 Q 判定）区分：收束时仍开放的 Q，不是"不可得"，而是"还开放"——如实带进报告信息空白。

不需要逐条打勾。但如果"感觉做完了"，回看一下——有没有哪个 Q 线索特别稀疏但你下意识跳过了？

## Phase 3: 交叉比对（消解闸门）

**目标**：对 Phase 2 收集到的全部资料进行系统比对，**决定哪些问题的候选答案可以消解**。根据资料的**性质**采用不同的评估方式——事实用置信度，知识用合理性/系统性，意见找争议。

**消解闸门**：一个 Q 的候选答案，只有经过交叉验证、满足该信息类型的达标标准，才**消解**为发现 F。**单来源 / 未验证的答案不构成完整消解**——重要 Q 保持开放补证，或标注低置信度消解。
**验证强度 · 来源独立性**：交叉验证的效力取决于来源之间的独立性。

- **差异增强**：来源差异越大，一致越可信——不同领域（技术博客 / 学术论文 / 行业报告）、不同语言、不同地区、不同利益立场（厂商 / 用户 / 监管）的独立来源得出同一结论，构成强验证
- **关联削弱**：来源存在潜在关联时，一致不构成独立确认——同机构、同作者、同引用源头、共同利益、同一种测量方法——共同偏差可能同时污染这些来源，验证力相应下调

**领域特化规则优先**：领域文档（如 policy-law 的条文采信硬约束）定义的采信规则**优先于**本节通用规则；冲突时按领域规则执行。

### 第一步：分类

在比对之前，先判断你手头的每条关键信息属于什么类型：

- **事实**：关于现实世界中发生过/存在着的状态的声明。"X 公司成立于 2023 年""产品定价 ¥29/月"。**有真假值**——它要么符合现实，要么不符合
- **数据**：看起来像事实，但本质是"某人按某方法在某时间点测出的数字"。"市场规模 30 亿美元""用户增长 150%"。可靠与否取决于**测量方法**，而非数字本身是否能被直接验证
- **知识 / 框架**：系统化的认识结构。"三幕结构""Egri 的角色骨骼理论""精益创业方法论"。**没有真假值**——它要么内部自洽、有解释力、适用于你的场景，要么没有。不存在"三幕结构是对的还是错的"这个问题
- **意见 / 立场**：带有评价的声明，混了事实基底和主观判断。"A 是市场领导者""这个方向没有前途"。需要拆开：事实基底部分按事实处理，评价部分标注为立场
- **经验**：情境化的实践知识。"我们团队发现 X 做法在 Y 场景下导致 Z 问题"。有用性取决于**情境描述是否足够具体**、是否可迁移到你的场景

### 第二步：按类型分别处理

以下各类比对中，每产生一条发现即分配一个唯一编号 `F1`, `F2` ...，并标注它依据的 [S 编号] 与它消解的 [Q 编号]。这些编号在 Phase 4 中直接带入报告，不需要重新编号。

#### 事实 → 置信度评估

**目标**：区分可靠事实和错误信息。

- 多条高权威来源独立指向同一事实 → 高置信度，该 Q 消解
- 来源权威性分层：一手（原始报告、访谈原文、官方数据）> 权威二手（专业媒体、学术论文、行业报告）> 一般来源（个人博客、论坛）。一条学术论文 + 两条个人博客一致，不等于"三方确认"
- 只有一条来源覆盖 → 标注"单来源，未经交叉验证"，不赋置信度；该 Q **不消解**（保持开放补证，或标注低置信度消解）
- **官方一手自证**（机构对自身的定价、发布、规模声明）→ 官方对自身信息是天然最终权威，第二来源通常只是转引——标注"单来源 + 官方自证"后可低置信度消解；规模类数据（用户数、市占率）仍属数据，需第三方验证
- 高权威来源之间说法矛盾 → 这是有价值的发现，如下处理：
  - 如果矛盾涉及核心问题 → 该 Q 无法消解；转化为新线索/新 Q，回到 Phase 2 追踪"为什么存在这个矛盾"
  - 如果矛盾不涉及核心 → 标注并记录各方说法，不强行裁定
- 低权威来源与高权威来源矛盾 → 标注，采信高权威

#### 数据 → 方法论追溯

**目标**：判断数字的来源是否可靠，而不是判断数字本身是否"正确"。

- 追溯：谁测的？用什么方法？样本是什么？统计口径是什么？（如"市场规模"是否含了某个子品类？"用户数"是注册用户还是月活？）
- 如果数据的测量方法和定义边界不可追溯 → 标注为"来源不明数据"，不应作为关键结论的支柱；该 Q 不消解
- **单来源但方法可追溯**（该来源明确给出测量方法与样本）→ 标注方法与口径，保持开放或低置信度消解——与"来源不明数据"区分，可信度不同
- 不同来源对同一指标给出了不同数据 → 分析差异原因（口径不同？方法论不同？时间点不同？），而非简单判断"哪个对"——差异本身可能就是消解后 F 的内容

#### 知识 / 框架 → 系统性组合

**目标**：理解框架之间的关系，组合成一个系统化的知识图景。

- 框架之间是**互补**关系？还是**替代**关系？还是**层级**关系（一个是大框架，另一个是其子组件）？
- 多个框架覆盖同一问题但来自不同流派 → 对比它们的核心假设和适用范围。这是分析产出，不是需要解决的矛盾
- 框架内部是否自洽？是否与已知的高置信度事实冲突？（框架本身不能是"错的"，但它可以与事实矛盾——此时需要标注"某框架的某推论与某事实不一致"）
- 是否适用于你的场景？——这是对框架的**适配性判断**，不是对框架本身的评估

#### 意见 / 立场 → 归纳与争议识别

**目标**：理解各方立场，识别实质性争议。

- 归纳：在这个话题上存在哪些不同的立场？每个立场的持有者是谁？他们的相关性和发言资格是什么？（不是权威——一个 CEO 对行业的看法和一个学者的看法都有相关性，但维度不同）
- 识别实质性争议：不是"有人说好有人说坏"这种浅层分散——而是**基于不同前提或不同价值观得出的系统化分歧**
- 如果发现了实质性争议 → 标注争议的本质（前提冲突？价值冲突？信息不对称？），可能转化为新线索/新 Q 回到 Phase 2 探索

#### 经验 → 可迁移性评估

**目标**：判断他人的经验能否作为你的参考。

- 情境描述是否具体到你能判断它和你场景的相似度？
- 经验中提到的因果链是否清晰？（"我们做了 X，观察到了 Y，分析后认为原因是 Z"）还是只有结论没有过程？
- 如果可迁移 → 标注适用条件和限制
- 如果不可评估（太笼统）→ 标注，不作为行动依据

### 第三步：问题集的演化

交叉比对之后，对问题集做一次演化。每个 Q 落在以下之一：

- **消解**：交叉验证通过 → 答案转成 F，Q 移除
- **转化**：某个发现让某旧 Q 过时 → 旧 Q 移除，换成更精确的新 Q
- **新增**：比对中出现的矛盾/空白/新争议 → 加入新 Q
- **不可得**：经实际调查确认该 Q 无可达来源 → 产出"可得性"F，Q 关闭（区别于收束——这是对单个 Q 的判定）
- **排除**：该 Q 不值得追/超出范围 → 关闭（价值判断）
- **保持开放**：答案不足/未验证 → Q 保留，回到 Phase 2 补证

以下情况必然产生新 Q 或未消解 Q：

- 事实矛盾无法裁定 → 需要更多信息来打破僵局
- 某个问题的所有线索都来自低权威来源 → 需要寻找高权威补充
- 某个 Phase 0 目标完全缺乏覆盖 → 需要针对性搜索
- 意见争议的根源值得深入理解 → 需要进一步研究争议各方的论据

这些新问题 → 回到 Phase 2，作为新的追踪目标（S 编号和 F 编号从当前最大值继续递增）。

## Phase 4: 整理交付

**目标**：将 Phase 2 收集的资料和 Phase 3 的比对结果整理为研究报告。

**核心原则**：报告中的每一条结论都可以被读者逆向追踪——结论 ← 发现 ← 依据（资料摘要）← 来源（URL）。这条链中没有断点。

使用 `../templates/report-template.md` 作为报告结构。以下是关键要求：

### 输出形态

按问题类型与用户预期选择交付形态，不强制完整报告：

- **完整报告**：多目标、多来源的深度研究（默认）
- **决策简报**：研究用于支撑某个决策时——结论（直接回答被委托时支撑的决策问题）+ 关键证据 + 信息空白，保留结论 ← 发现 ← 来源的追溯链
- **精选列表**：类别查询 / 推荐类话题——推荐列表 + 入选理由摘要，不必套用完整报告结构

形态选择不影响内部流程：Phase 0-3 照常执行，差异只在 Phase 4 的呈现。

### 三层编号体系

### 三层编号体系

编号在 Phase 2 和 Phase 3 中随工作推进自然产生——收集来源时分配 [S 编号]，产生发现时分配 F 编号。Phase 4 将它们带入报告，不需要重新编号。章节以名称定位，不使用编号。

- **结论段** →「研究结论」章节，按 Phase 0 目标逐段组织，每段以 `← F编号` 标注依据的发现
- **来源编号** `[S1]` `[S2]` ... →「资料来源」和「参考资料」章节，附带完整 URL 和摘要
- **发现编号** `F1` `F2` ... →「交叉比对」章节，每个 F 标注依据的 S 编号

### 资料摘要的独立性

每一条来源的摘要必须**具体、完整**——保留数字、日期、引述、原文的关键论点。摘要不能是笼统描述（"讨论了某话题"）。足够详细，使读者不读原文也能理解来源说了什么。摘要是「交叉比对」章节中每条发现的依据基础——如果摘要太模糊，发现就成了无根之木。

### URL 完整性

「资料来源」和「参考资料」章节中的每条来源必须包含完整的 URL 地址。来源不可追溯 = 链条在最后一步断裂。如果某条信息确实无法回溯到 URL（如线下访谈、内部文档），标注获取方式和局限性。

### 空白诚实

Phase 3 中仍开放的问题、标记为"单来源"的事实、"来源不明"的数据、"不可评估"的经验——全部保留在报告中。不要为了报告的整洁而删掉"这还没确认"的信息。

- **仍开放的问题** → 写入「信息空白与遗留问题」，标注"还开放"（不是"不可得"）——收束到点但没答完，是诚实的边界
- **不可得的问题** → 写入「信息空白与遗留问题」，标注"不可得"（经调查确认无可达来源）
- **被排除的问题** → 写入「信息空白与遗留问题」，标注"排除"（价值判断：不值得追/超出范围）

### 未采用来源

Phase 2 中收集过但 Phase 3 判定不纳入结论的来源（冗余、低可靠性、不相关等），在报告中以简短列表记录——编号、标题/URL、一行排除原因。不写完整摘要。这既是诚实（展示未挑拣来源），也避免将来重复评估。

### 后续建议

基于 Phase 3 遗留的开放问题，建议下一步可以追踪的方向（如果有）。

### 交付前完整性验证

在报告完成前，逐条检查：

- 「研究结论」章节的每一条结论 → 是否能追溯到至少一条「交叉比对」章节的发现？
- 「交叉比对」章节的每一条发现 → 是否标注了依据的 [S 编号]？（消解型发现还应标注它消解的 [Q 编号]）
- 被引用的 [S 编号] → 在「资料来源」章节中是否有完整的摘要？
- 「资料来源」章节中的每条来源 → 在「参考资料」章节中是否有 URL？
- 「信息空白与遗留问题」章节 → 是否如实列出了收束时仍开放的问题（标注"还开放"）、不可得的问题（标注"不可得"）、被排除的问题（标注"排除"）？
- 是否存在"来源丢失但信息仍被作为结论支撑"的情况？（如果有，要么标注为不可靠，要么回到 Phase 2 补全）

## Quality Checklist

研究完成前逐条自检：

- [ ] **指称确认**：最终研究使用的名称是否正确？Phase 1 修正记录是否保留？
- [ ] **问题覆盖**：Phase 0 拆解出的每个目标、每个问题都有信息覆盖？仍开放的问题是否诚实标注？
- [ ] **来源追溯**：每条关键信息都标注了出处和 URL？来源丢失的信息是否诚实标注？
- [ ] **追踪链完整**：每条结论 ← 发现 ← 依据（来源摘要）← URL 的链条是否有断点？是否存在引用不存在的 [S 编号]、[F 编号]？是否存在有结论无发现、有发现无来源的情况？
- [ ] **问题消解**：每条发现是否标注了它消解的 [Q 编号]？单来源/未验证的答案是否没有冒充完整消解？
- [ ] **事实置信度**：关键事实是否经过交叉比对？单来源事实是否标注？
- [ ] **数据溯源**：引用的数据是否可以追溯到测量方法和定义边界？来源不明的数据是否标注？
- [ ] **知识系统性**：收集到的框架/知识是否被系统化组合而非简单罗列？框架之间的关系是否被分析？
- [ ] **意见争议**：是否存在实质性意见分歧？是否分析了争议的本质（前提/价值/信息差异）？
- [ ] **矛盾深追**：高权威来源之间的事实矛盾是否作为新问题回到了 Phase 2 追踪？
- [ ] **具体性**：收集到的是具体信息（数字、日期、引述），而非笼统概括？
- [ ] **范围锚定**：最终结论是否仍在 Phase 0 确定的范围内？超出的部分是否显式标注？
- [ ] **时效覆盖**：素材的时间覆盖是否覆盖目标时间窗？缺口是否如实标注？
- [ ] **边界诚实**：仅依据摘要的信息、未经确认的推断——是否标注？收束时仍开放/不可得/被排除的问题是否如实写入「信息空白」？
- [ ] **资料独立于结论**：报告中每条来源的摘要是否足够完整（读者不看结论也能理解）？结论是否可追溯到具体资料编号？
- [ ] **URL 完整**：报告中每条可追溯的来源是否包含了 URL 地址？
