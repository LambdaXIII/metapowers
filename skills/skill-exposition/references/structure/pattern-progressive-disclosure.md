# 分层披露模式（progressive-disclosure）

> 按**阅读时间 / 篇幅**组织内容：概览 → 细节逐层展开，L1 约 30 秒可读完，至 L4 按需深入。可选用的组织方案之一，按需加载。

## 模式定位

组织轴是**披露深度**。内容按读者愿意投入的阅读时间分层：L1 概览（约 30 秒）、L2 摘要（约 2 分钟）、L3 详情（约 10 分钟）、L4 深度（按需）。原则是不一次性展示所有信息——读者停在适合自己的层级，深入与否由自己决定；后层内容不干扰前层的简洁性。

## 适用情况

- 读者群体**异质**：既有只想快速判断"是否适合我"的浏览者，也有要完整执行的使用者，还有深挖设计的维护者
- 内容**量大且深度分级自然**——概览能独立成立，不依赖细节就能读懂
- 学习者可能只有几十秒的注意力，需要先用 L1 帮读者做"要不要继续读"的决定

## 结构示意

单篇说明文内的层级排布（篇幅过大拆为章节文件时，L1-L2 置于入口，L3-L4 分文件并在导航中指明）：

1. **L1 概览**（30 秒）：一句话定义 + 适用场景 + 快速开始。只读这一层就能判断"这个技能是否适合我"
2. **L2 摘要**（2 分钟）：核心概念 + 主要流程。建立认知后能判断"我是否需要深入了解"
3. **L3 详情**（10 分钟）：完整流程 + 决策规则 + 边界条件。有完整信息支持实际使用
4. **L4 深度**（按需）：设计思想 + 版本历史 + 深入细节。需要时查阅，不需要时不读

要点：

- 层与层之间是**递进而非并列**：L2 建立在 L1 之上，L3 建立在 L2 之上
- L1 不是"正文的摘要"，而是独立成立的最小完整介绍——只读 L1 的读者不应感到缺了必需信息
- L3 必须完整到支持执行，不能为迁就层级而省略规则或例外
- L4 不干扰前层：深层内容放在文档后部或独立文件中，前层读者无须经过它

## 权衡与注意

- **何时不选**：内容短小、读者群单一（如都需要完整学习）时，分层是多余的结构负担——直接用学习路径模式（learning-path）更简洁
- **与学习路径（learning-path）的差异**：learning-path 是顺序轴（读者按序读完全部内容）；本模式是深度轴（读者停在适合自己的层）。两者可组合：每一层内部仍按学习路径的顺序排
- **与按知识类型分组（knowledge-types）的关系**：类别分组解决"按什么切"，分层披露解决"披露多深"——可外层分层、内层按类别，反之亦可
- **风险提示**：分层最易做成机械复述——每一层重复上一层的话再加长。层间应递进补充新信息，而不是重复旧信息；L1 若写得像目录而非可独立理解的介绍，读者无法据其做决定

## 示例说明

假想技能「日志分析」（log-analyzer）：**L1**（30 秒：一句话定义 + 适用场景 + 一条命令快速开始）→ **L2**（2 分钟：核心概念"日志流 / 模式 / 告警"与主流程概览）→ **L3**（10 分钟：完整规则、正则模式库、阈值配置、异常处理）→ **L4**（按需：设计思想——为何采用流式处理 `[推断: 基于约束反推]`、版本变更历史）。
