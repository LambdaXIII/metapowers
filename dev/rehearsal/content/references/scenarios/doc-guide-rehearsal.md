# 文档/指南质量验证推演
> 场景文档 — 配合推演通用论述参考使用。


将 rehearsal（推演）方法应用于文档/指南写作的质量验证。适用于：
- 写作者完成单篇文档后的自我验证（单文档推演）
- 全部文档完成后的全流程跨文档推演（全流程推演）

---

## 单文档推演

写完文档后，用推演代替静态 checklist 进行验证。

### 客体定位

目标读者（预期的接收方）。已知工作上下文，但**从未读过刚写的这份文档**。目标是"读完后知道怎么执行对应工作"。

初始状态：
- 知道有相关参考文档但没读过
- 知道有上下游模块但没看过它们的文档
- 目标是"执行本文描述的工作"

### 四步流程

> 推演前先完成通用论述中的「作者视角」和「清空」步骤。

**1. 清空**

参照通用论述的「作者视角」和「清空」步骤：

1. **回看作者视角**：确认你在推演前已写下「这份材料的目标读者是谁、期望达到什么效果」。
2. **设定阅读身份**：你是目标读者（预期的接收方）。已知工作上下文，但**从未读过刚写的这份文档**。目标是「读完后知道怎么执行对应工作」。
3. **显式清空**：扔掉作者记忆——不知道你写文档时的设计意图、不知道哪句话是重点、不知道哪些是后来追加的。只带客体的初始状态和这份文档本身进入。

**2. 逐帧跟**
按阅读顺序逐段走，记录心理反应：

| 反应 | 含义 |
|------|------|
| "这里停住了" | 信息密度过高 / 措辞模糊 / 跳过了必要前置 |
| "这里不知道做什么" | 缺少明确可执行的下一步 |
| "这里跳过去了" | 结构没抓住注意力，重要的东西被埋没 |
| "这里误解了" | 措辞有歧义，可能被理解为错误的意思 |
| "这里需要回头看" | 引用了还没定义的概念或术语 |

**3. 边界刨**
至少三类异常路径：

| 场景 | 操作 |
|------|------|
| 信息缺失 | 客体没读引用的参考文档，这篇文档还站得住吗？ |
| 错误输入 | 客体误解了一条关键指令，会走到什么死路？ |
| 跨模块跳转 | 客体从上个模块跳过来，期望的输入和本文档的起点匹配吗？ |

### 4. 评估整理

参照通用论述的 4a-4e 流程。本载体特定要求：

**严重程度格式：** 阻塞/缺陷/建议。三级定义：
- **阻塞**：读者无法完成目标（如关键步骤缺失）
- **缺陷**：读者能走完但质量受影响（如引导不足）
- **建议**：可读性或措辞改进

**评估维度：**

| 评估维度 | 含义 |
|------|------|
| 入口明确性 | 读完标题/首段，知道该不该继续读 / 从哪里开始 |
| 步骤可跟踪性 | 每一步都有明确可执行的行动，不是抽象原则 |
| 术语一致性 | 术语与其他文档一致 |
| 缺失场景覆盖 | 边界情况、异常路径有覆盖 |
| 独立性 | 虽然引用但不依赖，能独立指导执行 |

**意图对照注意：** 回到步骤 0 写下的「目标读者是谁/期望达到什么效果」。

**修复优先级：** 按严重程度排序。检查五个维度是否均有记录。

**4e 错误模式搜索候选：**
- **路径末端无收束** — 提供信息后忘记给出「下一步做什么」的引导
- **隐含前置知识假设** — 文档假设读者已知某些概念但未定义
- **术语跨文档不一致** — 同一概念在不同文档中用了不同名字

### 通过标准

- 推演中无"这里不知道做什么"或"这里误解了"记录
- 无 阻塞 级发现
- 不通过则修改后重新推演，循环直到通过

## 全流程跨文档推演

所有文档完成后，对整个知识库做一次完整的端到端推演。

### 客体定位

从零开始接手一个完整项目的执行者。已知各模块的定义，但从未实际操作过。

### 载体

全部相关文档（通用指南 + 各模块特定文档）。

### 链路

按工作流程的天然顺序：起点的模块 → 下一站 → 直到终点。

### 流程

**1. 逐模块跟**
模拟客体逐个模块的工作流。在每个模块转换点推演：

```
模块 A → 模块 B：
 - 模块 A 的输出是否在模块 B 的文档中被引用为输入？
 - 关键术语在两个模块中是否一致？
 - 完成模块 A 后客体自然能知道下一步去模块 B 的哪个文件吗？
```

**2. 跨模块边界刨**

| 异常场景 | 检查目标 |
|---------|---------|
| 跳过某模块直接进入下一站 | 文档是否提供必要的上下文或警告？ |
| 只读了通用指南没读模块指南 | 通用指南是否足够支撑执行？ |
| 两个模块对同一概念的不同表述 | 有没有矛盾？需不需要统一？ |
| 项目规模/参数超出标准范围 | 各文档是否覆盖了变体情况？ |

### 3. 评估整理

参照通用论述的 4a-4e 流程。本载体特定要求：

**严重程度格式：** 阻塞/缺陷/建议。三级定义见单文档。

**评估维度：**

| 评估维度 | 含义 |
|------|------|
| 全流程可执行性 | 从起点到终点，按文档走能完整走通吗？ |
| 模块流转清晰度 | 每个模块的输出/输入契约清晰吗？ |
| 术语全局统一 | 关键术语在所有文档中一致吗？ |
| 覆盖完整性 | 全部工作内容被覆盖了？ |
| 异常容错 | 跳步、逆行、跨读时能 recover 吗？ |
| 引用完整性 | 所有相对链接指向真实文件 |
| 独立可读性 | 每个文档自身站得住 |

**意图对照注意：** 回到步骤 0 写下的全流程期望。

**修复优先级：** 按严重程度排序。检查七个维度是否均有记录。

**4e 错误模式搜索候选：**
- **模块流转契约缺失** — 模块 A 的输出未在模块 B 的输入中被引用
- **术语全局不统一** — 关键术语在多个文档中表述不一致
- **跳步无恢复指引** — 跳过某模块后文档未提供必要的上下文

### 通过标准

- 全流程推演无卡死点（客体到了某步完全不知道下一步）
- 无 阻塞 级发现
- 低分项记录为改进清单

## 常见问题

**Q: 推演和审阅有什么区别？**
审阅是"我再看一遍有没有问题"。推演是"我假装不是作者，第一次读，走一遍全过程"。推演暴露的是结构性和体验性问题，审阅发现的是文字性和事实性问题。两者互补。

**Q: 单文档推演是在写完后做，还是在写作过程中做？**
写完初稿后做。推演发现的卡点修改，修改完如果涉及结构变动则重新推演。不建议边写边推演——推演需要完整载体才能产生有效信号。

**Q: 全流程推演发现很多低分项怎么办？**
按影响范围排序修复：先修导致卡死点的（全流程可执行性 阻塞），再修一致性/覆盖性问题，最后修引用和可读性问题。
