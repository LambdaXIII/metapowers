# 修改一个技能

对象已存在、改动能在既有结构内完成时，是修改。对象不存在，或既有结构本身要动（定位、命名、范围边界变了），属于[设计](skill-design.md)——继续按修改修补，只会得到一次没有锚定的重写。归属判断先于一切动作。

## 范围纪律

- **只改要求的部分**。技能的知识分散在多个互相衔接的文件里，一次改动的实际影响面积总比视线里大；顺手「优化」相邻内容会让变更失去边界，执行后的检验也随之失去地图——你不再知道该核对哪些位置。
- 动手前写下一句可检查的目标效果（改完是什么样）。这句话有两个用处：收敛修改方向，以及挡住范围外的诱惑。范围外的念头记下来留给下一次，不混进这次改动。
- 改动范围按**功能角色**划，不按主题词划。同一主题词下的内容常常服务不同的失败场景，按词圈范围会把几处各自独立的保护机制一起扫掉，故障在之后很久才暴露，且不再能隔离根因。判据：只改最精确的那个目标、其他不动，我是否仍认为指令完成？是，那其他就不该动。
- 环境特定的值（绝对路径、主机名、账号、项目专有路径）参数化后再写进技能，不写死。写死的值换台机器即失效，且污染的是「这是技能的方法」与「这是作者的环境」的区分。

## 理解现状

- 起点不是改，是**呈现路径追踪**：全文检索目标概念的所有出现点（覆盖正文、示例、`description` 与元信息字段）→ 排序定出首次出现（定义锚点）与其余引用点 → 核对定义是否准确、各引用与定义是否一致。
- 检索先于判断：没有完整出现清单就动手，改到一半才会在别处发现引用，而那时的改动语境已经变了——先前改过的句子要按新发现重判一次，等于白改。
- 命中只证明文字在那里，不证明它现行有效。检索结果要按归属分类后才算理解完成。
- 不靠记忆改：对话上下文与记忆不是权威，文件才是。检索结果里没有，才算没有。
- 从问题清单进来时（[审查](skill-review.md)、[快速测试](skill-quick-test.md)或[后评估](skill-post-assessment.md)的产出），清单本身就是现状：每条已带位置与判据，且按严重度排好序，按序消费即可，不必重查一遍。清单之外另发现的不一致，另算一次，不顺手并入这次的范围。

## 修改执行

- **涟漪式节奏**：找到一处出现点 → 判断归属 → 改 → 下一处。先扫完再统一改，是用修改前的语境判断修改后的问题。
- 每个命中是候选，不是目标。归属四类，处置方式完全不同：

| 归属 | 特征 | 处置 |
|---|---|---|
| 定义区 | 决定这个概念的含义，改动影响最大 | 最后改，改完逐点回归引用 |
| 引用区 | 依赖定义，多数只需跟随 | 多数跟随定义；少数要改写句式 |
| 历史残留 | 描述已经不存在的旧行为 | 删，不是替换 |
| 无关命中 | 同名异指，与目标概念无关 | 不动 |

- **抵制批量替换**。同一字符串在不同出现点语义角色不同，文本级替换会把「描述旧行为」的句子也改写成新说法，制造一条看起来一致、实际错误的陈述。逐处修改慢，但不同位置本就需要不同处理——改、删、或明确判定不动。
- 改定义点之前先列引用清单：所有引用点的位置与当前表述。定义一改，清单上每一项都要重新确认仍然成立；没有清单，回归检查只能靠再搜一遍，等于把理解现状再做一次。

## 耦合链回溯

- 改动影响沿三层传播，越往外越难发现：
  - **核心定义** —— 概念在此成立。
  - **直接引用者** —— 检索能命中，靠出现清单覆盖。
  - **条件依赖者** —— 字面不出现目标词，却依赖这个定义成立：标准门槛、示例、常见问题、完成判据里的隐含取值。检索找不到，要主动追问「哪些内容依赖这个概念成立」。
- 条件依赖者是最容易漏的一层，而漏它的后果是技能表面一致、实际自相矛盾：定义变了，示例还在演示旧语义。
- **远端残留**：有些环境惯例要求技能带开发侧文档（设计锚定文档、变更记录一类）。这类文档不参与执行，却是一致性锚点——审查判断「缺陷还是设计如此」时拿它当基准。改动触及定位、命名、范围边界时，回头核对并同步它；目标环境没有这类文档，就没有这一步。
- 计划里的每条「已删除 / 已合并 / 已融入」声明，都要能指出对应的实际内容与位置。说不出位置的声明不可验证，本质上是把未完成说成已完成。

## 内容手术

- 新增内容与既有结构对齐，不造第二套并列惯例。判据是它与同层其他小节是否同一种形态（同为要点、同为表格、同为步骤）——形态不一致的新内容会让读者用错误的模式解读它。
- 新增一条判据之前，先查其他文件有没有写过同一条。同一条判据在两处各写一遍，两处会各自漂移（转发类缺陷的判法见[找出一个技能的问题](skill-review.md)）；权威位置只有一处，其余位置是指针。
- 大幅度重写先备份原文件，写完后逐段对照补漏，确认无丢失再清理备份。这里的失败模式不是写不好，是写到一半忘记原始信息、而原内容已被覆盖。
- 搬动内容按三步走，**顺序不可省**：写入新位置 → 更新所有引用 → 删除旧位置。中间任何时刻技能都保持完整可读，且不存在「两边都没有」的窗口。
- 修剪先诊断再动手，两种病的处理相反，顺序不能反：
  - **沉积** —— 过时、冗余、被取代的内容，每行都没在干活 → 删。
  - **臃肿** —— 每行都活着且唯一，只是整体太长 → 不删，做披露分层（后置到支撑文件）或按分支/序列切开。
- 修剪整句删，不裁半句——半句残留比整句更误导，读者会拿它当完整判断。判别哪些内容属于沉积（化石），见[找出一个技能的问题](skill-review.md)的化石类。

## 升级判断

- 基准区分：修改以**既有设计意图**为基准（锚定三问的答案、术语权威、范围边界）。基准之内的改动是修改；基准本身要动，就是设计问题。
- 两条判据，任一成立就停下转设计：改动面覆盖文件大半、几乎逐句在变；或一次变更牵动了「这个技能提供什么、不管什么」。
- 判据的意义在于：在修改的注意模式里继续打补丁，产出的是一个既不符合旧意图、也没有新意图的中间态。此时正确的动作是重新锚定，而不是再多改几处。

## 执行后检验

- 旧术语全文零残留：再检索旧词（覆盖正文、示例、元信息、配套文档；检索词同时覆盖正文用词与引用格式两种写法），与改前清单逐项对齐——每个出现点都有去处：改了、删了、或判定过不动。**判定过不动的也要能对出理由。**
- 逐文件核对同层结构一致：入口的路由覆盖新小节（路由即索引，不另设一份清单），各文件同级标题形态齐整，没有文件还在用旧的分节方式。
- 耦合项回归：拿改前列的引用清单，定义改完后逐点确认引用仍然成立；条件依赖者单独过一遍。
- 三项都过才算改完。跳过执行后检验是修改工作最常见的失败——改动本身是对的，留下的一半旧状态让技能自相矛盾。

## Gotchas

- **凭记忆替代检索** → 先建出现清单，理解现状先于修改。
- **把命中当目标** → 逐处归属判断，再决定改、删、不动。
- **整体批量替换** → 涟漪节奏逐处改，允许不同出现点不同处理。
- **改定义忘引用** → 改前列引用清单，改后逐项回归。
- **漏掉条件依赖者** → 检索之外追问「谁依赖这个概念成立」。
- **顺手扩大范围** → 目标效果一句话挡住；范围外的念头记下来留给下一次。
- **重写丢内容** → 整文件重写先备份，写完对照补漏再清理。
- **该升级不升级** → 牵动设计意图就停下转设计，不在正文里打补丁。
