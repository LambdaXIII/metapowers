# 评估一个刚用完的技能

对象是刚用过的技能，证据是刚刚完成任务的过程。这个动作叫**后评估**：把这次使用中关于这个技能的洞察记下来——哪些方面真的有效，哪些不足，哪些错了。证据就在你手里：委派出去，对方拿到的是文件不是经历，回顾就退化成了通读（那是[预评估](skill-pre-assessment.md)的活）。过程细节在上下文与记忆里衰减很快，任务一收尾就记。与[审查](skill-review.md)的分工：审查判文本说的和做的是不是一回事，这里记实际用起来怎么样。

## 翻检过程

答案从这段经历里找，技能文本用来定位与核对；下面是入手的角度，不是逐项作答的工序：

- **指引被照上了吗**——被跳过或改造的步骤是信号：绕开它任务照样走，要么那步多余，要么与实际不符。它当初想防什么？
- **哪里停顿、回读、犹豫过**——沿那一步引用的判据倒推，第一处说不清的位置多半就是根因。
- **技能给的判据帮上判断了吗**——还是每个判断最后都靠你自己拿主意。
- **不用它会怎样**——这类任务原来怎么做，对出这次哪些地方确实被省了或稳了，哪些反而添了环节。
- **它是被正常调用的吗**——自动触发的技能，该来的时候来了吗，不该来的时候来了吗。

每条先归因：这次的不顺手是技能的账，还是任务或环境的账——在卡住的位置换不带技能的做法，会不会同样卡？会，是任务或环境的；不会，才是指引的。同一位置反复卡，就不是巧合。任务成败与技能好坏是两回事：成功的任务也可能全程在绕开指引。

## 洞察的成色

- 每条洞察带本次实证：过程中的哪件事、哪个位置。「感觉不太好用」定位不了也改不动，不记。
- 实际执行形态照实记，包括偏离技能指引的地方——偏离是这次最有价值的信号之一，不是过错。
- 结论限定在这次、这类任务上。改进建议给到「这里缺什么」为止；怎么改是[修改](skill-modify.md)的事。
- 记下来的洞察怎么用——改、留、弃——是记录之外的决定。
