# 笔记标签模式（Note Tags）

> 为笔记打标签：标签帮助快速理解笔记内容，对笔记的检索、编写、分类、整理等多种操作起到提示性作用。有效降低各类笔记条目相关工作的思考负担。

## 核心方法

在笔记头部元数据（YAML 段）中设置 `tags` 字段，依照格式编写这些标签。

## 标签的设置

- 标签不宜使用过长的短语，应是简短的词汇，最好是单个单词
- 需要时，标签可以按领域嵌套，如：`todo`、`todo/blocked`、`todo/pending`
- 标签不要求同维度，也不一定反映文档的内容主题，如：`coding`、`knowledge`、`imported`、`English`、`workflow`、`log`、`deprecated`
- 不建议为元数据设置多个用于存放标签的字段

## 扩展方法与建议

- 笔记库的规则中建议设计一套标签提炼的规范——比如标签可从内容、用途、话题、置信度等维度进行提炼
- 笔记或标签过于庞杂时，建议在规则中设置标签注册表：所有笔记必须从注册表中选用标签；注册表中无合适的标签时，先注册此标签再使用

## 一种可能的做法

这是一种做法参考，可按笔记库自身情况调整。

规则文档中的标签板块：

```
## 标签

条目标签写入 frontmatter 的 tags 字段，从内容、用途、话题等维度提炼，
使用简短词汇，需要时按领域嵌套：

- coding — 编程相关
- imported — 外部导入
- todo/pending — 待办中受阻
```

庞杂时启用注册表：

```
## 标签

一个 tag 不在此表中 = 不存在。写条目时从这里选 tag，需要新 tag 时先
注册到这里。

- 每条至少选一个 Domain tag 和一个 Activity 或 Meta tag
- 至多选 5 个 tag——超过意味着条目应该拆分
- 注册新 tag 前检查是否已有同义 tag

### Domain（项目/领域）

| Tag | 含义 |
|-----|------|
| `project-a` | 项目 A |
| `skill-dev` | 技能开发 |

### Activity（工作类型）

| Tag | 含义 |
|-----|------|
| `research` | 调研、信息搜集 |
| `debugging` | 调试、问题排查 |
```
