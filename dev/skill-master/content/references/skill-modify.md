# 修改一个技能

## 定位与范围纪律

- 修改服务已存在的成品。归属判断先于一切动作：对象已存在、改动在既有结构
  内完成，是修改；对象不存在或既有结构本身要动，属于设计。
- 只改要求的部分：技能是多文件互指的呈现，一次改动的实际影响面积总比视线
  里大；顺手「优化」相邻内容会让变更失去边界，执行后检验失去地图。
- 动手前写下一句可检查的目标效果（改完是什么样），收敛修改方向，挡住范围
  外的诱惑。

## 理解现状

- 起点不是改，是呈现路径追踪：全文检索目标概念的所有出现点（覆盖正文、
  示例、description 与元信息字段）→ 排序定出首次出现（定义锚点）与其余
  引用点 → 核对定义是否准确、各引用与定义是否一致。
- 检索先于判断：没有完整出现清单就动手，改到一半才会在别处发现引用，而
  那时的改动语境已经变了。命中只证明文字在那里，不证明它现行有效。
- 不靠记忆改：对话上下文与记忆不是权威，文件才是——检索结果里没有，才算
  没有。

## 修改执行

- 涟漪式节奏：找到一处出现点 → 判断归属 → 改 → 下一处。先扫完再统一改，
  是用修改前的语境判断修改后的问题。
- 归属四类：定义区（决定概念含义，改动影响最大）、引用区（依赖定义，多数
  只需跟随）、历史残留（描述旧行为，往往该删而非替换）、无关命中（同名
  异指，不该动）。每个命中是候选，不是目标。
- 抵制批量替换：同一字符串在不同出现点语义角色不同，文本级替换把「描述旧
  行为」的句子也改写。逐处修改慢，但不同位置本就需要不同处理——改、删、
  或明确不动。

## 耦合链回溯

- 改动影响沿三层传播：核心定义 → 直接引用者（检索能命中）→ 条件依赖者
  （字面不出现目标词却依赖定义成立：标准门槛、示例、常见问题——检索找
  不到，要主动追问「哪些内容依赖这个概念成立」）。
- 远端残留：配套设计文档不参与执行，却是一致性锚点（审查判「缺陷还是设计
  如此」的坐标系）。改动触及定位、命名、范围边界时，回头核对并同步设计
  文档。

## 内容手术

- 新增内容与既有结构对齐，不造第二套并列惯例；判据是它与同层其他小节是否
  同一种形态。
- 大幅度重写先备份原文件，写完后逐段对照补漏，确认无丢失再清理备份；搬动
  内容先立新位、更新引用，再删旧位——中间任何时刻技能保持完整可读。
- 修剪先诊断再动手：沉积（过时、冗余、被取代——删）与臃肿（每行都活着但
  整体太长——不删，披露分层）顺序不能反。修剪整句删，不裁半句——半句
  残留比整句更误导。化石内容的删的动作在此执行，判别归审查工作的化石
  维度。

## 升级判断

- 坐标系区分：修改的坐标系是既有设计意图（锚定三问的答案、术语权威、范围
  边界）；坐标系内改动是修改，坐标系本身要动就是设计问题。
- 两条判据：改动面覆盖文件大半、几乎逐句在变；或一次变更牵动「这个技能
  提供什么、不管什么」。此时停下转设计工作——继续修补只会得到一次没有
  锚定的重写。

## 执行后检验

- 旧术语全文零残留：再检索旧词（覆盖正文、示例、元信息、配套文档；检索词
  覆盖正文用词与引用格式两种写法），与改前清单逐项对齐——每个出现点都有
  去处：改了、删了、或判定过不动。
- 逐文件核对同层结构一致：路由与索引覆盖新小节，各册同级标题形态齐整。
- 耦合项回归：改前列引用清单，定义改完后逐点确认引用仍然成立。

## Gotchas

- **凭记忆替代检索** → 先建出现清单，理解现状先于修改。
- **把命中当目标** → 逐处归属判断，再决定改、删、不动。
- **整体批量替换** → 涟漪节奏逐处改，允许不同出现点不同处理。
- **改定义忘引用** → 改前列引用清单，改后逐项回归。
- **顺手扩大范围** → 目标效果一句话挡住；范围外的念头记下来留给下一次。
- **重写丢内容** → 整文件重写先备份，写完对照补漏再清理。
- **该升级不升级** → 牵动设计意图就停下转设计，不在正文里打补丁。
