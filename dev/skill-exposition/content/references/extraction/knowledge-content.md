# 知识库型内容的提取提醒

> 梳理时遇到概念/术语/关系类内容时按需加载。本文只讲「怎么提取不失真」；怎么写进说明文由你自行发挥（行文见 general/readability.md）。

## 这是什么

**定义**：技能中承载「是什么」的内容——概念、术语、定义，以及概念之间的关系与分类。

**识别线索**（读到以下任一即属此类内容）：

- 定义句（「X 是指…」「X 是…的机制」）
- 术语表、词汇说明
- 概念对比、分类、层级表述（「包括」「由…组成」「区别于」「不同于」）
- 首次出现的专有名词及其解释

概念内容是学习者理解技能的认知地基。定义类内容的失真通常是「软化」式的——限定条件被悄悄去掉，概念被写得更宽泛，学习者建立的概念与源概念从此偏离。

## 提取注意点

1. **定义精确性——不模糊化**。
   注意：定义中的限定条件原样保留：「X 指包含 A、B、C 三部分的机制」不要写成「X 是一种机制」。
   为什么：定义是学习者建立概念的锚点，模糊化就是劣化源内容，直接违反忠实性。

2. **概念间关系原样提取**。
   注意：依赖（A 依赖 B）、包含（A 包含 B、C）、并列（A 与 D 并列）按源的表述记录，关系词不替换。
   为什么：关系是概念体系的结构，关系丢失 = 概念孤立，学习者无法把概念迁移到新场景。

3. **术语体系收集完整**。
   注意：同一概念在不同文件/位置的不同叫法全部收集并建立对应（如 frontmatter 里叫「输入范围」，正文里叫「范围定义」）。
   为什么：术语不对应会导致学习者读 A 处的定义、B 处的用法时对不上号。

4. **定义与使用位置跨文件归并**。
   注意：概念的定义可能在一个文件、使用约束在另一个文件，提取时都要归到该概念名下。
   为什么：方面可能跨文件分布（见 exposition-guide.md 2.2），定位不全 = 提取必然遗漏。

5. **边界概念区分保留**。
   注意：源中明确区分的一对概念（如「触发条件」与「适用场景」）保留区分本身，不合并成一个。
   为什么：技能作者区分它们必有原因，通常对应不同行为；合并 = 歪曲。

6. **分类与层级不动**。
   注意：源的分类标准、父概念-子概念层级原样保留，不擅自调整。
   为什么：分类是作者组织知识的方式，调整分类 = 暗示不同的知识结构。

7. **术语首次出现附源语言原文**。
   注意：学习者语言的术语首次出现时附源语言原文（如「技能阐述（exposition）」）。
   为什么：这是忠实性在语言转写层面的要求——防止翻译失真，也便于学习者回查源材料。

8. **区分定义与规则**。
   注意：概念的定义（是什么）与关于该概念的规则（什么时候怎样）分开记录，分别对应本文与 rule-content.md 的注意点。
   为什么：定义与规则混记会让说明文的「是什么」章节混入「怎么做」内容，两类内容的保真要点不同。

## 常见失误

- **反例 1**：源定义「盲测指评估者不知道被测对象身份的实验」，说明文写成「盲测是一种评估方法」——限定条件（不知道身份）丢失。
- **反例 2**：源区分「触发条件（何时应该触发）」与「适用场景（何时用户会需要）」，说明文合并成「使用时机」。
- **反例 3**：概念 X 在正文定义、在 references/ 里叫「X 机制」，说明文只用了其中一个叫法，另一处的描述挂不上。
- **反例 4**：源里「A 包含 B」，说明文写成「A 与 B 并列」——包含关系被降级为并列关系。

## 自查提示

- 每个核心概念的限定条件（定义里的「在…情况下」「包含…」）都保留了吗？
- 概念之间的关系词（依赖/包含/并列/区别于）与源一致吗？
- 同一概念的所有叫法都收集齐并建立了对应吗？
- 有没有把两个被源区分开的概念合并成一个？
- 概念的定义与关于它的规则分开放置了吗？
